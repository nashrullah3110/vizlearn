Overview

GROUP BY divides filtered rows into groups with the same value for each grouping expression. An aggregate such as COUNT or SUM then summarizes each group. If you group orders by customer_id, the result has one row per customer who has at least one qualifying order.

What a group represents

query.sqlSQLite
SELECT customer_id, COUNT(*) AS order_count, SUM(total) AS spend
FROM orders
WHERE status = 'paid'
GROUP BY customer_id;
Result

The query first removes unpaid rows, then groups the remaining rows and calculates values. WHERE filters input rows; HAVING filters completed groups. See HAVING for a threshold example and aggregate functions for NULL behavior.

Select only values that describe the group

In standard SQL, every selected expression that is not aggregated must be part of the grouping key (or otherwise be functionally determined where the engine supports that rule). Selecting an arbitrary name next to a grouped customer_id can be invalid or ambiguous. SQLite permits some bare columns and may choose a value from an input row; do not rely on that behavior for portable results.

If a customer's name is needed, group by both columns, join the grouped result back to customers, or use a window function if rows should remain separate. Decide based on the output grain you want.

NULL and empty groups

Rows with NULL in a grouping key are collected into one NULL group in common SQL engines. A group appears only when at least one input row belongs to it. A query with GROUP BY over no qualifying rows therefore returns no groups, while an aggregate without GROUP BY still returns one summary row.

Example: count distinct customers by month

If the output should be one row per month, group by the month expression and count customer IDs. Decide whether a customer with multiple orders in one month counts once; if so, COUNT(DISTINCT customer_id) expresses that rule. Be careful when grouping on formatted date text: sorting and time-zone conversion can change which month an event belongs to. Store or convert timestamps consistently, then group using an expression appropriate for the database. State the grain in a comment when the report is reused.
