Overview

Read a logarithm

A logarithm answers: which exponent turns a positive number into the value I want? It reverses exponentiation, so the output of a logarithm is an exponent.

by = x   ⇔   logb(x) = y

For example, log₂(8) = 3 because 2³ = 8. A real logarithm needs a positive argument x and a positive base b other than 1. The graph and controls below let you change the base and argument and watch that inverse relationship.

Logarithms

Logs invert powers, turn products into sums, and make ratios easier to compare.

Turn a product into a sum

For positive p and q, the product rule is

logb(pq) = logb(p) + logb(q)

With base 2, the demo's starting values p = 8 and q = 4 give log₂(32) = 5 and log₂(8) + log₂(4) = 3 + 2 = 5. Both sides match. The rule does not say that log(p + q) equals log(p) + log(q); it applies to multiplication, with the same base and positive inputs.

Compare bases and scales

Changing the base rescales the output. You can calculate any base using natural logs:

logb(x) = ln(x) / ln(b)

For instance, log₂(8) = ln(8) / ln(2) = 3. Base 2 is common for bits and powers of two; ln means base e; base 10 is useful for decimal orders of magnitude. Follow the curve as you switch among the visualiser's base presets. For the displayed bases, which are all greater than 1, the logarithm increases with x.

The input must stay positive. As x approaches zero from above, logb(x) falls without bound; at zero or below, it is undefined over the real numbers. A logarithmic x-axis changes how horizontal distances are drawn: equal ratios such as 1→10 and 10→100 receive equal spacing. It does not change the function's values.

Why probability calculations use logs

Independent probabilities multiply. Taking a logarithm turns that product into a sum, which avoids trying to store a very small product directly. Here is a short example: multiplying 0.1 by itself 400 times underflows to zero in ordinary floating-point arithmetic, but adding the 400 log-values remains representable.

logarithms.pyPython
import math

probability = 0.1
count = 400
product = probability ** count
log_product = count * math.log(probability)

print("direct product:", product)
print("sum of log probabilities:", log_product)
print("log base 2 of 8:", math.log(8, 2))
Output
For a known outcome with predicted probability p, the negative log-likelihood is −ln(p): assigning a smaller probability gives a larger penalty. At exactly p = 0, this expression is infinite, so practical loss implementations use numerically stable calculations rather than taking the logarithm of a zero probability directly.

Answer without scrolling back up.
  1. What does log₂(8) = 3 mean?
    A logarithm gives the exponent: 2³ = 8, so log₂(8) = 3.
  2. Which expression equals log_b(pq), for positive p and q?
    The product rule turns multiplication inside one logarithm into addition of two logarithms with the same base.
  3. Which x-values are allowed in a real-valued log_b(x)?
    A real logarithm requires a positive input. At x = 0 and for negative x it is undefined.
  4. What does changing the logarithm's base do to its value?
    The change-of-base formula is log_b(x) = ln(x) / ln(b), so changing the base rescales the output.
