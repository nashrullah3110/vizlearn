title: Product of array except self
intro: For each element, return the product of every other element - without using division.

## The problem, and the two forbidden shortcuts

For each position, return the product of every <em>other</em> element.

<p class="mono-font">[1, 2, 3, 4]&nbsp;&rarr;&nbsp;[24, 12, 8, 6]</p>

Two constraints are always stated, and they are what make it a real problem:

<strong>Do not use division.</strong> The obvious solution &mdash; total product divided by each element &mdash; is banned. And it also fails on zeros.

<strong>O(n) time.</strong> The nested loop multiplying all of it else is O(n²) and excluded.

Worth noting why division fails even when permitted: a single zero makes the total product zero. So every division gives zero or an error. Handling zeros correctly requires case analysis on how many there are. This is more code than the intended solution. The constraint against division is what pushes you toward the real insight.

The idea is prefix and suffix products. A left-to-right pass builds the running product of all of it before each position; a right-to-left pass does the same for all of it after. Multiplying the two gives the answer in two O(n) passes. This page shows both passes with their intermediate arrays. Then the single-array variant that folds the second pass into the output, and finally feeds the division approach arrays with zeros so you can watch it break.


## Run it

The two-pass version with both intermediate states printed, checked against the division shortcut &mdash;. This is given arrays containing one zero and two zeros so you can watch it fail.

```python-run
values = [1, 2, 3, 4]

def product_except_self(values):
    n = len(values)
    result = [1] * n

    running = 1                       # everything to the LEFT
    for i in range(n):
        result[i] = running
        running *= values[i]
    print("  after the left pass :", result)

    running = 1                       # everything to the RIGHT
    for i in range(n - 1, -1, -1):
        result[i] *= running
        running *= values[i]
    print("  after the right pass:", result)
    return result

print("prefix/suffix:", product_except_self([1,2,3,4]))
```

```python-run
values = [1, 2, 3, 4]

def by_division(values):
    """The forbidden shortcut, and why it is forbidden."""
    total = 1
    for v in values:
        total *= v
    return [total // v for v in values]

print("by division :", by_division([1,2,3,4]))
try:
    by_division([1,0,3,4])
except ZeroDivisionError as e:
    print("with a zero :", type(e).__name__ + ":", e, "- why division is not the answer")
```
## Prefix and suffix products

Every element's answer is <strong>all of it before it, times all of it after it</strong>. Compute those two directions in separate passes.

```python-run
def product_except_self(nums):
    n = len(nums)
    out = [1] * n

    prefix = 1
    for i in range(n):
        out[i] = prefix                # product of everything BEFORE i
        prefix *= nums[i]

    suffix = 1
    for i in range(n - 1, -1, -1):
        out[i] *= suffix               # multiply in everything AFTER i
        suffix *= nums[i]

    return out

print(product_except_self([1,2,3,4]))
```
O(n) time, and O(1) extra space if the output array is not counted &mdash; which is the usual convention, and worth stating.

The ordering inside each loop is what makes it work: `out[i]` is assigned <em>before</em> `prefix` is updated with `nums[i]`. So it never includes the element itself. Reversing those two lines is the standard bug.

## Tracing it

`[1, 2, 3, 4]`:

<strong>Forward pass</strong> &mdash; prefix products:

|i|prefix before|out[i]|prefix after|
|---|---|---|---|
|0|1|1|1|
|1|1|1|2|
|2|2|2|6|
|3|6|6|24|

`out = [1, 1, 2, 6]` &mdash; each entry is the product of all of it to its left.

<strong>Backward pass</strong> &mdash; multiplying in suffix products:

|i|suffix before|out[i] before|out[i] after|suffix after|
|---|---|---|---|---|
|3|1|6|6|4|
|2|4|2|8|12|
|1|12|1|12|24|
|0|24|1|24|24|

`out = [24, 12, 8, 6]`. Correct.

The two-table trace is worth doing on paper in an interview. The algorithm is short and the index handling is exactly where errors occur.

## Why not just divide

Multiply all of it, then divide by each element. It is O(n), it is the first thing everyone says. And the question by name forbids it &mdash; because it breaks on zero. One zero makes every other answer a division by zero; two zeros make every answer zero.

You can special-case the zero count, and it works. Say that, then give the prefix/suffix answer, because the point of the question is the decomposition rather than the arithmetic.

## The decomposition

The product of all of it except element <em>i</em> is (all of it left of i) &times; (all of it right of i). Both of those are cumulative products, and each can be built in one pass.

The trick that gets you to O(1) extra space is to store the left products right in the output array. Then walk backwards carrying the right product in a single variable and multiplying it in. No second array is ever allocated.

## The pattern to spot

"Something about all of it except me" is almost always prefix and suffix aggregates. The same shape solves trapping rain water (max to the left and right of each bar), candy distribution. And the maximum-product subarray.

Note the convention: the leftmost prefix and the rightmost suffix are both 1, the identity for product. For a sum-based variant they would be 0. Getting the identity wrong is the usual bug.

## Zeros, which are the interesting case

The prefix-suffix solution handles zeros with no special casing at all. This is one of its attractions. It is worth verifying rather than asserting:

<strong>One zero,</strong> `[1, 0, 3]`: the answer is `[0, 3, 0]`. The zero position gets the product of its neighbours; every other position includes the zero and is so zero. The algorithm gives this naturally.

<strong>Two zeros,</strong> `[0, 2, 0]`: every position sees at least one zero. So the answer is `[0, 0, 0]`.

Compare with the division approach, which needs explicit counting. No zeros means divide normally; one zero means only that position is non-zero; two or more means all of it is zero. Three branches, and each is a chance to get it wrong.

That contrast is worth stating: <strong>the prefix-suffix method is not merely allowed under the constraint, it is truly simpler.</strong>

## Edge cases

|Case|Result|
|---|---|
|`[1, 2]`|`[2, 1]`|
|`[5]`|`[1]` &mdash; the empty product|
|`[]`|`[]`|
|Contains one zero|Only that position is non-zero|
|Contains several zeros|All zeros|
|Negative numbers|Handled &mdash; signs multiply normally|
|Large values|Python integers are unbounded; other languages overflow|

The single-element case returning `[1]` is the empty-product convention. And it is worth confirming with the interviewer rather than assuming.

The overflow row matters in languages with fixed-width integers: the product of many values overflows silently. Python has no such limit, and mentioning that the problem is harder in C or Java shows awareness.

## The variants

<strong>Two-pass with explicit arrays.</strong> Build `prefix[]` and `suffix[]` apart, then multiply. O(n) space, easier to explain, and a fair first version before optimising to O(1).

<strong>Sum of array except self.</strong> Trivially the total minus each element. Subtraction has no zero problem. This is exactly why the product version is the interview question.

<strong>Product of array except self, division allowed.</strong> Count zeros and branch, as above. Worth writing out if asked, to show the case analysis is understood.

<strong>Maximum product subarray.</strong> A different problem, and a common companion question. Track both the running maximum and minimum, because multiplying by a negative swaps them.

<strong>Product of every window of size k.</strong> Prefix products plus division. Or a sliding-window approach handling zeros by tracking the last zero's position.

## What it is testing

<strong>Do you find the prefix-suffix decomposition?</strong> "All of it before, times all of it after" is the insight. And it is a truly non-obvious reframing.

<strong>Do you achieve O(1) extra space?</strong> Reusing the output array for the prefix pass and multiplying the suffix in during the second is the expected refinement.

<strong>Do you get the index ordering right?</strong> Assigning before updating the accumulator is the one place the code breaks.

<strong>Do you handle zeros without special cases?</strong> And can you explain why no special case is needed?

<strong>Do you notice the division approach's zero problem</strong> even though division is banned anyway?

The transferable technique is <strong>precomputed prefix aggregates</strong>. Prefix sums answer range-sum queries in O(1). Prefix products, prefix maxima and prefix counts all follow the same shape. Spotting when a problem wants "all of it before this point" is worth more than this specific solution.

## Questions people ask

<strong>Why not divide the total product by each element?</strong> Division fails when the array contains a zero, and many versions of the problem forbid it. The prefix and suffix approach needs no special case for zeros.

<strong>What are the time and space complexities?</strong> O(n) time with two passes. Extra space is O(1) if the output array is not counted, because the suffix product is kept in one running variable.

<strong>Why assign `out[i]` before updating the running product?</strong> The answer for index i must exclude `nums[i]`. Folding the element in first would multiply it into its own result.

<strong>How does the result change with one zero in the input?</strong> Every position except the zero's own becomes 0, and the zero's position gets the product of all the others. The two-pass method produces this without any branching.

<strong>What happens with two or more zeros?</strong> Every output is 0, since each product includes at least one zero. The prefix and suffix passes reach this naturally.

<strong>Is the output array counted as extra space?</strong> Most interviewers say no, which is how you claim O(1). State your assumption out loud so there is no confusion.

## Recap in one screen

- Each answer is the product of all of it to the left times all of it to the right.
- Two passes: fill the output with prefix products. Then multiply suffix products in going backwards.
- O(n) time and O(1) extra space beyond the output array.
- Assign `out[i]` before folding `nums[i]` into the accumulator, or the element includes itself.
- Zeros need no special handling, which is why this beats the division approach even when division is allowed.
