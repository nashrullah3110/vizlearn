title: 3Sum
intro: Find all unique triples in an array that sum to zero.

## The problem

Find all unique triplets in an array that sum to zero.

<p class="mono-font">[&minus;1, 0, 1, 2, &minus;1, &minus;4]&nbsp;&rarr;&nbsp;[[&minus;1, &minus;1, 2], [&minus;1, 0, 1]]</p>

Two words carry the difficulty. <strong>All</strong> means the answer is a list, not a single result. <strong>Unique</strong> means duplicate triplets must be suppressed &mdash; and with a duplicated `-1` in the input, that is where most implementations fail.

The brute force is three nested loops: O(n³). The expected solution is O(n²).


## Run it

The two-pointer version against brute force with both operation counts, and the deduplication removed so you can see the duplicate triples it produces.

```python-run
import random

data = [-1, 0, 1, 2, -1, -4]
dupes = [-2, 0, 0, 2, 2, -2, 0]

def three_sum(values):
    values = sorted(values)
    out, ops = [], 0
    for i in range(len(values) - 2):
        if values[i] > 0:
            break                              # smallest triple already positive
        if i and values[i] == values[i - 1]:
            continue                           # skip a repeated fixed value
        lo, hi = i + 1, len(values) - 1
        while lo < hi:
            ops += 1
            total = values[i] + values[lo] + values[hi]
            if total < 0:
                lo += 1
            elif total > 0:
                hi -= 1
            else:
                out.append((values[i], values[lo], values[hi]))
                lo, hi = lo + 1, hi - 1
                while lo < hi and values[lo] == values[lo - 1]:
                    lo += 1                    # and skip repeated pointer values
                while lo < hi and values[hi] == values[hi + 1]:
                    hi -= 1
    return out, ops

print("two pointers:", three_sum([-1,0,1,2,-1,-4])[0])
```

```python-run
import random

data = [-1, 0, 1, 2, -1, -4]
dupes = [-2, 0, 0, 2, 2, -2, 0]

def brute_force(values):
    out, ops = set(), 0
    n = len(values)
    for i in range(n):
        for j in range(i + 1, n):
            for k in range(j + 1, n):
                ops += 1
                if values[i] + values[j] + values[k] == 0:
                    out.add(tuple(sorted((values[i], values[j], values[k]))))
    return sorted(out), ops

print("brute force :", brute_force([-1,0,1,2,-1,-4])[0])
```
## Sort, then fix one and two-pointer the rest

```python-run
def three_sum(nums):
    nums.sort()
    out = []
    for i in range(len(nums) - 2):
        if nums[i] > 0:
            break                                  # sorted: no triplet can sum to 0
        if i and nums[i] == nums[i-1]:
            continue                               # skip duplicate first elements
        lo, hi = i + 1, len(nums) - 1
        while lo < hi:
            total = nums[i] + nums[lo] + nums[hi]
            if total < 0:
                lo += 1
            elif total > 0:
                hi -= 1
            else:
                out.append([nums[i], nums[lo], nums[hi]])
                lo += 1
                while lo < hi and nums[lo] == nums[lo-1]:
                    lo += 1                        # skip duplicate second elements
                hi -= 1
    return out

print(three_sum([-1,0,1,2,-1,-4]))
```
O(n²) time &mdash; an outer loop with an inner linear scan &mdash; and O(1) extra space beyond the output, or O(n) if the sort is counted.

The structure is worth naming: <strong>reduce three-sum to n instances of two-sum on a sorted array.</strong> Fixing `nums[i]` turns "find three summing to zero" into "find two summing to `-nums[i]`", which two pointers solve in O(n).

## The duplicate handling, which is the whole difficulty

Three separate skips are needed, and each addresses a different source of repeats.

<strong>Duplicate first elements.</strong> `if i and nums[i] == nums[i-1]: continue`. Without it, `[-1, -1, 0, 1]` produces `[-1, 0, 1]` twice &mdash; once for each `-1`.

<strong>Duplicate second elements.</strong> After recording a triplet, advance `lo` past any repeats. Without it, `[-2, 0, 0, 2, 2]` produces `[-2, 0, 2]` several times.

<strong>The third element</strong> needs no separate skip: with the first two fixed, the third is determined, so no additional duplicate can arise.

The alternative &mdash; collecting into a set of sorted tuples &mdash; also works and costs O(n) extra space and hides the reasoning. Interviewers generally want the skip version, because it demonstrates understanding of where the duplicates come from.

The `if nums[i] > 0: break` line is a genuine optimisation rather than a correctness fix: once the smallest of the three is positive, no triplet can reach zero, so the rest of the loop is wasted.

## Reducing the third loop

The brute force is three nested loops, O(n&sup3;). Fix the first element and the problem becomes "find two numbers summing to <code>-values[i]</code>" &mdash; which is Two Sum, and on sorted input Two Sum is two pointers in O(n).

n iterations of an O(n) inner scan is O(n&sup2;), and the sort is O(n&nbsp;log&nbsp;n) so it disappears into that. Using a hash map for the inner search is also O(n&sup2;), and then deduplication is much harder &mdash; which is the argument for sorting.

## Deduplication is the real difficulty

Two places need it. Skip a fixed element equal to the previous one, or every triple starting with that value is emitted twice. And after recording a triple, advance past any repeats of both pointer values, or the same triple is found again inside the same scan.

Sorting is what makes both a simple adjacency check. Without it you would collect triples into a set of sorted tuples &mdash; correct, and it allocates for every candidate.

## The early exits worth mentioning

Once <code>values[i] &gt; 0</code> the smallest possible triple is already positive, so the scan can stop entirely. That is not a complexity improvement and it is a large constant on real input.

The generalisation is kSum: fix an element and recurse down to the two-pointer base case, giving O(n^(k&minus;1)). Naming that shows you see the pattern rather than the single problem.

## Tracing the duplicates

`[-1, 0, 1, 2, -1, -4]` sorted becomes `[-4, -1, -1, 0, 1, 2]`.

|i|nums[i]|Window|Result|
|---|---|---|---|
|0|&minus;4|lo=1, hi=5|No triplet sums to 0|
|1|&minus;1|lo=2, hi=5|`-1 + -1 + 2 = 0` &rarr; record; then `-1 + 0 + 1 = 0` &rarr; record|
|2|&minus;1|&mdash;|<strong>Skipped</strong> &mdash; same as nums[1]|
|3|0|lo=4, hi=5|`0 + 1 + 2 = 3` &gt; 0, `hi` falls to 4, loop ends|

Two triplets, no repeats. The skip at i = 2 is what prevents `[-1, 0, 1]` appearing twice.

Walking that table aloud is a good way to demonstrate the solution in an interview, because it exercises exactly the case the duplicate handling exists for.

## Edge cases

|Case|Result|
|---|---|
|Fewer than 3 elements|`[]`|
|All zeros, `[0,0,0]`|`[[0,0,0]]` &mdash; one triplet|
|All zeros, `[0,0,0,0]`|`[[0,0,0]]` &mdash; still one, thanks to the skips|
|All positive|`[]` &mdash; caught by the early break|
|All negative|`[]`|
|No triplet sums to zero|`[]`|
|Many duplicates|Each distinct triplet once|

The `[0,0,0,0]` case is the cleanest test of the duplicate logic, and worth mentioning unprompted.

## The generalisation to k-sum

The structure extends: fix k&minus;2 elements with nested loops, and two-pointer the last two.

|Problem|Approach|Complexity|
|---|---|---|
|Two-sum, sorted|Two pointers|O(n)|
|Two-sum, unsorted|Hash map|O(n)|
|Three-sum|One loop + two pointers|O(n&sup2;)|
|Four-sum|Two loops + two pointers|O(n&sup3;)|
|k-sum|k&minus;2 loops + two pointers|O(n^(k&minus;1))|

Four-sum has a better alternative worth knowing: hash all pairwise sums, then look for two pairs summing to the target &mdash; O(n²) time and O(n²) space, better than O(n³) when memory allows. That trade appears again in the "meet in the middle" technique for subset problems.

## The variants

<strong>Three-sum closest.</strong> Find the triplet whose sum is nearest a target. Same structure, and instead of comparing against zero, track the smallest absolute difference. No duplicate handling needed, because only one answer is returned.

<strong>Three-sum smaller.</strong> Count triplets with sum below a target. When `nums[i] + nums[lo] + nums[hi] < target`, every position between `lo` and `hi` also works &mdash; so add `hi - lo` and advance `lo`. That counting shortcut is the insight, and it keeps the whole thing O(n²).

<strong>Three-sum with multiplicity.</strong> Count the number of index triplets rather than distinct value triplets &mdash; a counting problem over value frequencies, with careful case analysis for repeated values.

<strong>Two-sum with a target other than zero.</strong> Trivially the same code with the comparison adjusted.

## What it is testing

<strong>Do you sort first?</strong> Sorting enables the two-pointer reduction, and it is the move that turns O(n³) into O(n²).

<strong>Do you handle duplicates correctly?</strong> This is the actual assessment. Producing correct triplets with repeats is a fail.

<strong>Do you see the reduction to two-sum?</strong> Saying "fix one element and this becomes two-sum on the rest" is the answer the interviewer is listening for.

<strong>Do you state complexity precisely?</strong> O(n²), with the sort's O(n log n) absorbed.

<strong>Do you find the early exit?</strong> Breaking when the smallest element is positive is a small demonstration of attention.

The transferable lesson is reduction: recognising that a harder problem is a loop around an easier one you already know. That habit applies far beyond this question.

## Recap in one screen

- Sort, fix one element, and two-pointer the remainder &mdash; three-sum is n instances of two-sum.
- O(n&sup2;) time, O(1) extra space beyond the output.
- Skip duplicate first elements at the outer loop, and duplicate second elements after recording a triplet.
- The third element needs no skip, because the first two determine it.
- The pattern generalises: k&minus;2 loops plus two pointers, at O(n^(k&minus;1)).
