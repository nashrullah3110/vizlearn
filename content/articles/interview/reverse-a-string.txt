title: Reverse a string
intro: Reverse a string. Now do it in place, with O(1) extra memory.

## The problem, and the Python answer

Reverse a string. In Python the answer is one slice:

```python
s[::-1]
```

That is idiomatic, C-speed, and correct. Stating it immediately is the right opening &mdash; and the interviewer is almost certainly asking something else underneath, so the useful part is what comes next.

The alternatives, and when each is relevant:

```python
"".join(reversed(s))        # explicit, works on any iterable
"".join(s[i] for i in range(len(s)-1, -1, -1))     # manual, no slicing
```

<strong>The reason slicing wins:</strong> it allocates the result once and copies backwards in C. Building a string with `+=` in a loop is O(n²), because strings are immutable and each concatenation copies everything so far.


## Run it

Three reversals of the same text &mdash; the slice, the two-pointer swap, and the word-level variant &mdash; with the extra memory each one uses printed beside it.

```python-run
# Reversing a string: the idiom, and the version an interviewer wants.

def reverse_slice(s):
    return s[::-1]                       # O(n) time, O(n) extra memory


def reverse_in_place(chars):
    """Two pointers, swapping inwards. O(1) extra memory."""
    lo, hi = 0, len(chars) - 1
    swaps = 0
    while lo < hi:                       # strictly <: the middle needs no swap
        chars[lo], chars[hi] = chars[hi], chars[lo]
        swaps += 1
        lo, hi = lo + 1, hi - 1
    return swaps


s = "stressed"
print("original      :", s)
print("s[::-1]       :", reverse_slice(s))

chars = list(s)                          # strings cannot be modified in place
swaps = reverse_in_place(chars)
print("two pointers  :", "".join(chars), f"({swaps} swaps for {len(s)} chars)")

# Odd length: the middle character stays put, which is correct.
odd = list("abcde")
reverse_in_place(odd)
print("odd length    :", "".join(odd))

# --- the follow-ups ----------------------------------------------------
sentence = "the quick brown fox"
print()
print("words reversed:", " ".join(sentence.split()[::-1]))

vowels = "aeiouAEIOU"
def reverse_vowels(s):
    chars = list(s)
    lo, hi = 0, len(chars) - 1
    while lo < hi:
        while lo < hi and chars[lo] not in vowels:
            lo += 1
        while lo < hi and chars[hi] not in vowels:
            hi -= 1
        chars[lo], chars[hi] = chars[hi], chars[lo]
        lo, hi = lo + 1, hi - 1
    return "".join(chars)

print("vowels only   :", reverse_vowels("programming"))
print("(consonants stay where they are - only a, i, o moved)")
```
## Reversing in place, and why Python cannot

The classic version of this question is "reverse a string in place with O(1) extra space", using two pointers:

```python
def reverse_in_place(chars):          # a LIST of characters, not a string
    lo, hi = 0, len(chars) - 1
    while lo < hi:
        chars[lo], chars[hi] = chars[hi], chars[lo]
        lo += 1
        hi -= 1
    return chars
```

<strong>This cannot be done on a Python string</strong>, because strings are immutable. There is no way to modify one, so O(1) space is impossible &mdash; the reversed string is a new object.

That is worth saying explicitly rather than pretending otherwise. The in-place version applies to a list of characters, or to a mutable string type in another language.

The two-pointer loop is the answer being looked for in the general form: swap the ends, move inwards, stop when they meet. O(n) time, O(1) extra space, n/2 swaps.

## The variations that are actually asked

Plain reversal is too simple to be the real question. Three variants are common:

<strong>Reverse the words, not the characters.</strong> `"the sky is blue"` &rarr; `"blue is sky the"`:

```python
" ".join(s.split()[::-1])
```

`split()` with no argument collapses runs of whitespace and discards empties, which handles `"  hello   world  "` correctly. `split(" ")` does not.

<strong>Reverse each word in place, keeping word order.</strong> `"the sky"` &rarr; `"eht yks"`:

```python
" ".join(w[::-1] for w in s.split())
```

<strong>Reverse only the vowels, or only the letters,</strong> leaving other characters in position &mdash; a two-pointer scan that skips characters not to be moved.

Asking "reverse the characters or the words?" before starting is the right move; the question is frequently stated ambiguously on purpose.

## The Python answer, and why it is not the whole answer

<p><code>s[::-1]</code> is correct, fast and what you should write in real code. It also allocates a second string of the same length, because Python strings are immutable and there is no in-place option. An interviewer asking for O(1) space is asking you to leave strings behind and work on a character array.</p>

## The two-pointer version

Put one pointer at each end. Swap the characters they name, move both inwards, stop when they meet. That is n/2 swaps and two integers of extra memory, regardless of length.

The loop condition is <code>while lo &lt; hi</code>, strictly less than. With <code>&lt;=</code> an odd-length string swaps its middle character with itself &mdash; harmless but pointless, and the condition is the part interviewers check.

## The variations that follow

"Reverse the words but not the characters" &mdash; <code>" ".join(s.split()[::-1])</code>, or reverse the whole thing and then reverse each word in place, which is the O(1)-space trick.

"Reverse only the vowels" &mdash; the same two pointers, each skipping forward until it lands on a vowel. "Reverse in groups of k" &mdash; the same swap loop applied to each block.

## The Unicode problem

`s[::-1]` reverses <strong>code points</strong>, and that is not always what a human means by reversing text.

<strong>Combining characters.</strong> "é" written as "e" plus a combining acute accent reverses into the accent followed by the "e", which renders as a different (and broken) sequence.

<strong>Emoji with modifiers.</strong> A skin-tone emoji is a base character plus a modifier, and reversing separates them.

<strong>Emoji sequences joined with zero-width joiners</strong> &mdash; family and profession emoji &mdash; break apart entirely.

The correct unit is the <strong>grapheme cluster</strong>: what a reader perceives as one character. Python's standard library has no grapheme segmentation, and the `regex` module does:

```python
import regex
def reverse_graphemes(s):
    return "".join(reversed(regex.findall(r"\X", s)))
```

For ASCII text `s[::-1]` is fine. Raising this distinction shows you know the difference between bytes, code points and characters &mdash; and that difference is what several other interview questions in this area are actually about.

## Complexity and edge cases

|Approach|Time|Space|
|---|---|---|
|`s[::-1]`|O(n)|O(n) &mdash; a new string|
|`"".join(reversed(s))`|O(n)|O(n)|
|Two pointers on a list|O(n)|O(1) extra|
|`+=` in a loop|<strong>O(n&sup2;)</strong>|O(n)|

|Edge case|Behaviour|
|---|---|
|Empty string|Returns empty|
|Single character|Returns itself|
|Palindrome|Returns an equal string|
|Whitespace|Preserved and reversed with everything else|
|`None`|Raises &mdash; guard if the contract allows it|

## The follow-ups

<strong>"Do it without slicing."</strong> `"".join(reversed(s))`, or an explicit loop appending to a list and joining.

<strong>"Reverse in place."</strong> Only possible on a mutable sequence; explain why a Python string cannot be, then give the two-pointer version for a list.

<strong>"Reverse a linked list."</strong> A different and more substantial problem &mdash; three pointers, redirecting each `next` backwards. Frequently the real destination of this line of questioning.

<strong>"Check whether a string is a palindrome."</strong> Comparing `s == s[::-1]` works and allocates; two pointers from both ends is O(1) space and short-circuits on the first mismatch.

<strong>"Reverse only part of the string."</strong> Two pointers bounded by the given range.

## What it is testing

Plain string reversal is a warm-up. What is being assessed:

<strong>Do you know the idiomatic one-liner,</strong> and can you also explain what it does?

<strong>Do you know that `+=` in a loop is quadratic?</strong> This is the single most common Python performance mistake, and it is what the question is often probing for.

<strong>Do you understand immutability</strong> and therefore why "in place" is not available?

<strong>Do you clarify the requirement</strong> &mdash; characters or words?

<strong>Do you know that characters are not code points?</strong> The Unicode point separates a careful answer from a superficial one.

## Recap in one screen

- `s[::-1]` is the idiomatic answer: O(n) time, O(n) space, implemented in C.
- Python strings are immutable, so in-place reversal is impossible &mdash; the two-pointer version needs a list.
- Never build a reversed string with `+=` in a loop; that is O(n&sup2;).
- Clarify whether characters or words are to be reversed; `split()` with no argument handles whitespace correctly.
- Slicing reverses code points, not grapheme clusters, so combining characters and emoji break.
