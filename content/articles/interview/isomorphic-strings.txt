title: Isomorphic strings
intro: Do two strings have the same character pattern? &#x27;egg&#x27; and &#x27;add&#x27; do; &#x27;foo&#x27; and &#x27;bar&#x27; do not.

## The problem

Two strings are isomorphic if the characters of one can be replaced by the characters of the other always, preserving order.

|s|t|Isomorphic?|Why|
|---|---|---|---|
|`"egg"`|`"add"`|Yes|e&rarr;a, g&rarr;d|
|`"foo"`|`"bar"`|No|o would map to both a and r|
|`"paper"`|`"title"`|Yes|p&rarr;t, a&rarr;i, e&rarr;l, r&rarr;e|
|`"badc"`|`"baba"`|<strong>No</strong>|d and c would both map to a|
|`"ab"`|`"aa"`|No|Same reason|

The critical requirement is that the mapping must be a <strong>bijection</strong>. One-to-one in both ways. The `"badc"` / `"baba"` case is the one that catches solutions checking only one way. A correct O(n) solution maintains two dictionaries: one mapping characters of `s` to characters of `t`. And one mapping the reverse. At each spot, if either character is now mapped to a thing different, the answer is no. A shortcut that checks only `s → t` will accept `"ab"` / `"aa"` because no character in `s` maps to two different characters. But it misses that two characters in `s` map to the same character in `t` &mdash; which violates injectivity. An other approach encodes each string's pattern as a tuple of first-instance indices: `"egg"` turns `(0, 1, 1)` and `"add"` also turns `(0, 1, 1)`. So comparing the tuples decides isomorphism without building explicit maps. This page runs both approaches on the same test cases, highlights the one-way failure, and covers the pattern-encoding other.


## Run it

The two-map version and the single-map version run side by side, on the input that separates them, plus the canonical-form other reaching the same verdicts.

```python-run
tests = [("egg", "add"), ("foo", "bar"), ("paper", "title"),
         ("badc", "baba"), ("ab", "aa"), ("", "")]

def isomorphic(a, b):
    if len(a) != len(b):
        return False
    forward, backward = {}, {}
    for x, y in zip(a, b):
        if forward.setdefault(x, y) != y:      # x already maps elsewhere
            return False
        if backward.setdefault(y, x) != x:     # y is already claimed
            return False
    return True

for a,b in [("egg","add"),("foo","bar")]: print(a,b,"->",isomorphic(a,b))
```

```python-run
tests = [("egg", "add"), ("foo", "bar"), ("paper", "title"),
         ("badc", "baba"), ("ab", "aa"), ("", "")]

def isomorphic_one_map(a, b):
    """The version with the bug, kept to show what it accepts."""
    if len(a) != len(b):
        return False
    forward = {}
    for x, y in zip(a, b):
        if forward.setdefault(x, y) != y:
            return False
    return True

for a,b in [("egg","add"),("foo","bar")]: print(a,b,"->",isomorphic_one_map(a,b))
```

```python-run
tests = [("egg", "add"), ("foo", "bar"), ("paper", "title"),
         ("badc", "baba"), ("ab", "aa"), ("", "")]

def pattern(s):
    """Canonical form: the order in which distinct characters first appear."""
    seen = {}
    return tuple(seen.setdefault(ch, len(seen)) for ch in s)

print("patterns:", pattern("egg"), pattern("add"), pattern("foo"))
```
## Two maps, not one

```python-run
def is_isomorphic(s, t):
    if len(s) != len(t):
        return False
    forward, backward = {}, {}
    for a, b in zip(s, t):
        if a in forward and forward[a] != b:
            return False
        if b in backward and backward[b] != a:
            return False
        forward[a] = b
        backward[b] = a
    return True

for a,b in [("egg","add"),("foo","bar"),("paper","title")]:
    print(a, b, is_isomorphic(a,b))
```
O(n) time, O(k) space where k is the alphabet size.

Checking only `forward` accepts `"badc"` / `"baba"`: `b&rarr;b`, `a&rarr;a`, `d&rarr;b`... which conflicts, so that given pair is caught. But `"ab"` / `"aa"` is not &mdash; `a&rarr;a` and `b&rarr;a` are both steady forwards. And they map two characters to one.

The second map is what enforces injectivity, and stating why it is needed. With a counterexample. Is the substance of a good answer.

## The pattern-normalisation other

An elegant one-liner: two strings are isomorphic just when their <strong>instance patterns</strong> match.

```python-run
def is_isomorphic_pattern(s, t):
    def pattern(x):
        return [x.index(ch) for ch in x]      # first-occurrence index per char
    return pattern(s) == pattern(t)

for a,b in [("egg","add"),("foo","bar")]:
    print(a, b, is_isomorphic_pattern(a,b))
```
`"egg"` gives `[0, 1, 1]` and `"add"` gives `[0, 1, 1]`. Equal, so isomorphic. `"foo"` gives `[0, 1, 1]` and `"bar"` gives `[0, 1, 2]` &mdash; different.

This by itself handles both ways, because the pattern is a canonical form. The catch is that `x.index(ch)` is O(n). This makes the whole thing O(n²). Fixing it with a dictionary restores O(n):

```python-run
def pattern(x):
    first = {}
    out = []
    for i, ch in enumerate(x):
        first.setdefault(ch, i)
        out.append(first[ch])
    return out

print(pattern("egg"), pattern("add"), pattern("foo"))
```
Worth offering as the canonical-form view after the two-map version, because it is the same idea that solves the "group anagrams" family. Normalise, then compare.

## What isomorphic means here

There must be a one-to-one correspondence between the characters. Replacing each character of the first string according to a fixed rule gives the second. And no two characters map to the same target. "Same shape, different letters".

A length check is a free first rejection, and the empty string is isomorphic to itself. The canonical-form view makes the whole thing one check: encode each
string as the first-instance index of each character, so `"paper"` turns
`[0, 1, 0, 2, 3]` and `"title"` turns `[0, 1, 0, 2, 3]`. The same, so
isomorphic &mdash; while `"foo"` gives `[0, 1, 1]` and `"bar"` gives `[0, 1, 2]`,
which differ at the third spot. Because the pattern is canonical it checks
both ways at once, which is just what the two-map version needs a second
map to do.

## Why one map is not enough

Track only a&nbsp;&rarr;&nbsp;b and <code>"badc"</code> against <code>"baba"</code> passes: <code>b&rarr;b</code>, <code>a&rarr;a</code>, <code>d&rarr;b</code>, <code>c&rarr;a</code>. Each forward rule is steady, and two distinct characters have collapsed onto one target.

The reverse map catches it: <code>b</code> is now claimed by <code>b</code>. So <code>d&rarr;b</code> is rejected. Both ways are needed because a bijection is a constraint in both ways.

## The canonical-form other

Normalise each string to the pattern of first appearances. <code>"paper"</code> and <code>"title"</code> both turn <code>[0,1,2,0,3]</code>. And compare the patterns. One pass each, no paired bookkeeping, and it extends naturally to comparing many strings at once by using the pattern as a dictionary key.

That is the same "canonicalise, then compare" idea as grouping anagrams. This is worth pointing out.

## Edge cases

|Case|Result|
|---|---|
|Different lengths|False &mdash; check first, it is O(1)|
|Both empty|True|
|Single characters|True, whatever they are|
|Same string|True &mdash; the identity mapping|
|`"aa"` / `"ab"`|False &mdash; a cannot map to two characters|
|`"ab"` / `"aa"`|False &mdash; needs the backward map|
|All distinct in both|True, if lengths match|
|Unicode|Works &mdash; dictionaries handle any hashable character|

The two `"ab"`/`"aa"` rows are the pair to test: one way catches the first. And only the second map catches the second. Mentioning both shows that the bijection requirement is understood rather than copied.

## The tied problems

<strong>Word pattern.</strong> The same problem with words instead of characters. Does `"dog cat cat dog"` match the pattern `"abba"`? The same structure over `s.split()`.

<strong>Group isomorphic strings.</strong> Use the normalised pattern as a dictionary key, just as sorted characters group anagrams. The canonical-form technique again.

<strong>Isomorphic graphs.</strong> Superficially tied and vastly harder &mdash; graph isomorphism has no known polynomial algorithm. Worth knowing the distinction if it comes up, because the name invites confusion.

<strong>Find and replace with a steady mapping.</strong> The real version: applying a cipher or a tokenisation always.

|Problem|Canonical form|
|---|---|
|Isomorphic strings|First-occurrence index pattern|
|Anagrams|Sorted characters, or a count tuple|
|Rotations|Smallest rotation, or `b in a + a`|
|Case-insensitive equality|Casefolded string|

That table is the transferable lesson: <strong>when a problem asks whether two things are the same under some transformation, compute a canonical form and compare.</strong> It turns an equivalence test into a hash lookup. This is what makes grouping doable.

## What it is testing

<strong>Do you need a bijection?</strong> The one-map solution is the trap. And the interviewer will have `"ab"` / `"aa"` ready.

<strong>Do you check lengths first?</strong> One line, O(1), and it avoids the whole loop.

<strong>Do you know it is order-sensitive?</strong> Isomorphism preserves spot, unlike anagrams. Conflating the two is a conceptual error.

<strong>Do you see the canonical-form view?</strong> Offering the pattern-normalisation solution shows you can reframe rather than only implement.

<strong>Is your `index`-based version O(n) or O(n&sup2;)?</strong> The elegant one-liner is quadratic, and noticing that is the gap between neat and correct.

## Questions people ask

<strong>What does isomorphic mean for two strings?</strong> Each character in the first string maps to exactly one character in the second, and no two characters map to the same one. The mapping must be one-to-one in both directions.

<strong>Why is one dictionary not enough?</strong> A single map checks that each source character has one target but allows two sources to share a target. For example, 'ab' and 'aa' would pass; a second map or a set of used targets blocks this.

<strong>What is the time and space complexity?</strong> O(n) time for one pass, and O(k) space for the alphabet size k, which is O(1) for ASCII.

<strong>What is the canonical-form alternative?</strong> Replace each string with the index of each character's first occurrence, such as 'egg' becoming [0, 1, 1], and compare the two patterns. Isomorphic strings produce the same pattern.

<strong>What if the lengths differ?</strong> They cannot be isomorphic, so return False immediately. Check this first, since the pass assumes equal lengths.

<strong>How is this related to word pattern?</strong> Word pattern is the same bijection check with words in place of the second string's characters. The two-map solution carries over directly.

## Recap in one screen

- Isomorphic means a steady one-to-one character mapping preserving order.
- Two dictionaries are needed &mdash; forward and backward &mdash; or `"ab"` / `"aa"` passes incorrectly.
- O(n) time, O(k) space; check lengths first.
- Normalising each string to its first-instance index pattern gives a canonical form that handles both ways.
- Use `str.index` inside a comprehension and the elegant version turns O(n&sup2;). A dictionary restores O(n).
