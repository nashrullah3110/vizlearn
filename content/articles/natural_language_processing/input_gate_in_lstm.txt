title: The Input Gate: Deciding What to Write
intro: Having decided what to erase, the LSTM must decide what to store. The Input Gate is the valve on that write &mdash; and it works as one half of a two-part team.

## What the Gate Actually Is

Like the Forget Gate, the Input Gate is a sigmoid layer emitting one value per memory slot:

$$i_t = \sigma(W_i \cdot [H_{t-1}, X_t] + b_i)$$

But notice what it is multiplied against. It never touches the old memory. It scales the <strong>candidate vector</strong> $\tilde{C}_t$ &mdash; the freshly proposed content &mdash; before that content is added to the cell state:

$$C_t = \underbrace{f_t \odot C_{t-1}}_{\text{what survives}} + \underbrace{i_t \odot \tilde{C}_t}_{\text{what gets written}}$$

## Two Layers, Two Different Jobs

Beginners often merge these two ideas, so it is worth stating plainly:

- <strong style="color: #ef4444">The candidate $\tilde{C}_t$ ($\tanh$)</strong> answers <em>"what is the new information?"</em> It can be positive or negative, because it is real content.
- <strong style="color: var(--gate-color)">The input gate $i_t$ ($\sigma$)</strong> answers <em>"how much of it do we actually want?"</em> It is strictly between 0 and 1, because it is a volume knob, not content.

Splitting the decision this way is what lets the cell be selective per dimension. The candidate can propose a strong update to eight memory slots while the gate admits it into only two of them.

## Why Addition, Not Replacement

The written term is <em>added</em> to what the Forget Gate let through. This matters enormously. Replacement would destroy old memory every time something new arrived; addition lets the cell <strong>accumulate</strong> &mdash; keeping the subject of a sentence while layering on new adjectives.

It also protects the gradient. Addition passes gradients backwards unchanged, which is precisely why the cell state acts as a highway through time rather than a lossy relay.

## Forget and Input Are Not Opposites

A natural assumption is that $i_t = 1 - f_t$ &mdash; that whatever you forget, you replace. In a standard LSTM this is <strong>false</strong>: the two gates are independent layers with their own weights, and all four combinations are meaningful.

The cell can keep old memory <em>and</em> write new content ($f\!\approx\!1, i\!\approx\!1$), keep memory and write nothing ($f\!\approx\!1, i\!\approx\!0$), wipe and overwrite ($f\!\approx\!0, i\!\approx\!1$), or wipe and store nothing at all ($f\!\approx\!0, i\!\approx\!0$). The GRU is the variant that <em>does</em> tie them together with a single update gate &mdash; which is exactly how it saves a set of weights.

## Deciding what to store

The forget gate decides what leaves memory. The input gate decides what enters it &mdash; and it works in a pair with the candidate memory.

<p class="mono-font">i&#7511; = &sigma;(W&#7522; &middot; [h&#7511;&#8331;&#8321;, x&#7511;] + b&#7522;)&nbsp;&nbsp;&nbsp;&nbsp;the gate</p>
<p class="mono-font">g&#7511; = tanh(W&#7509; &middot; [h&#7511;&#8331;&#8321;, x&#7511;] + b&#7509;)&nbsp;&nbsp;the candidate</p>
<p class="mono-font">c&#7511; = f&#7511; &#8857; c&#7511;&#8331;&#8321; + i&#7511; &#8857; g&#7511;</p>

Two separate computations from the same inputs, with different activations and different jobs:

- The <strong>candidate</strong> `g` uses tanh, so its values run from &minus;1 to 1. It is <em>what could be written</em> &mdash; content, which may be positive or negative.
- The <strong>gate</strong> `i` uses sigmoid, so its values run from 0 to 1. It is <em>how much of that content to actually write</em>.

Their elementwise product is what gets added to the cell state. A dimension with a strong candidate and a closed gate contributes nothing; a dimension with a weak candidate and an open gate contributes a little.

## Why the split is necessary

The obvious question: why not have one computation produce both the content and its strength?

Because they are different decisions and depend on different things. Whether a piece of information is <em>relevant now</em> is a question about context; what that information <em>is</em> is a question about the current input. Separating them lets the cell learn "this input carries a strong signal, but it is not relevant at this point in the sequence" &mdash; which a single computation cannot express.

The practical demonstration is selectivity. Reading "The cat, which was orange, sat", the cell wants to store the subject (cat) and update its state as the clause proceeds without letting "orange" overwrite the subject. Separate gate and candidate make that possible: the candidate can carry "orange" while the gate keeps it out of the dimensions holding the subject.

|&nbsp;|Gate `i`|Candidate `g`|
|---|---|---|
|Activation|Sigmoid|Tanh|
|Range|0 to 1|&minus;1 to 1|
|Meaning|How much to write|What to write|
|Analogy|The valve|The fluid|

## Working with the forget gate

The cell update has two terms, and the two gates control one each. That independence is what distinguishes an LSTM from a GRU.

|Forget|Input|Result for that dimension|
|---|---|---|
|1|0|Keep old memory unchanged|
|0|1|Replace entirely with new|
|1|1|Add new on top of old &mdash; accumulate|
|0|0|Clear the dimension|
|0.9|0.3|Decay slowly while adding a little|

The third row is what a GRU cannot do. Its update gate uses `z` and `1 − z`, so keeping the old state at full strength forces the new contribution to zero. An LSTM can do both, and that is the expressiveness it buys with its extra gate.

The `1 → 1` case matters in practice: it is how a cell accumulates evidence over several steps, such as building up a sentiment reading across a sentence rather than replacing it word by word.

## The gate that decides what is worth storing

The input gate is what lets a cell see something and choose to ignore it. Without it every token would be written to memory, which is the defect it exists to fix.

```python-run
import numpy as np

def sigmoid(z):
    return 1 / (1 + np.exp(-np.clip(z, -30, 30)))

print("    i = sigmoid(Wi @ [x, h] + bi)")
print("    c = f * c_old + i * g")
print()
print("the input gate multiplies the CANDIDATE, not the input. so the cell")
print("computes what it would store first, and then decides whether to:")
print("%12s %12s %16s %s" % ("candidate g", "gate i", "reaches memory", ""))
for g, i in ((0.9, 0.95), (0.9, 0.50), (0.9, 0.02), (-0.8, 0.90), (0.1, 0.99)):
    print("%12.2f %12.2f %16.4f %s"
          % (g, i, g * i, "<- computed, then discarded" if i < 0.1 else ""))
print()

print("WHY IT MATTERS. compare a cell with a working input gate against one")
print("whose gate is stuck open, on a sequence where most tokens are noise:")
rng = np.random.default_rng(0)
T = 40
signal_steps = {5, 22}
c_gated, c_open = 0.0, 0.0
print("%6s %10s %12s %14s %14s"
      % ("step", "token", "candidate", "gated cell", "always-on cell"))
for t in range(T):
    important = t in signal_steps
    g = 1.0 if important else rng.normal(0, 0.4)       # noise between signals
    i_gated = 0.95 if important else 0.03              # what a trained gate does
    c_gated = 0.98 * c_gated + i_gated * g
    c_open = 0.98 * c_open + 1.0 * g                   # gate stuck at 1
    if t in (0, 5, 12, 22, 30, 39):
        print("%6d %10s %12.4f %14.4f %14.4f"
              % (t, "SIGNAL" if important else "noise", g, c_gated, c_open))
print()
print("both cells saw exactly the same tokens. the gated one holds a clean")
print("trace of the two signals; the always-on one has integrated 38 pieces")
print("of noise on top of them.")
print("   final gated cell     : %.4f" % c_gated)
print("   final always-on cell : %.4f" % c_open)
print()
print("that is the whole function: a cell that cannot decline an input is a")
print("cell whose memory is the sum of everything it has ever seen.")
print()

print("THE PARTNERSHIP WITH THE FORGET GATE. the two together give four")
print("behaviours, and a trained unit uses all of them:")
print("%10s %10s %28s" % ("forget", "input", "what the step does"))
for f, i, what in ((0.99, 0.01, "hold -- ignore this token"),
                   (0.99, 0.95, "accumulate -- add to memory"),
                   (0.05, 0.95, "replace -- overwrite memory"),
                   (0.05, 0.01, "clear -- flush and store nothing")):
    print("%10.2f %10.2f %28s" % (f, i, what))
print()
c = 1.0
print("   running those four in sequence from c = 1.0:")
for f, i, label in ((0.99, 0.01, "hold"), (0.99, 0.95, "accumulate"),
                    (0.05, 0.95, "replace"), (0.05, 0.01, "clear")):
    c = f * c + i * 0.8
    print("      %-12s -> c = %.4f" % (label, c))
print()
print("   an LSTM is those four operations, chosen per unit and per step by")
print("   two sigmoids. nothing more exotic than that.")
print()

print("A GRU TIES THEM TOGETHER. it uses one gate z and sets")
print("    c = (1 - z) * c_old + z * g")
print("so whatever it forgets, it replaces by exactly that much:")
print("%10s %14s %14s %s" % ("z", "keeps", "writes", "possible in an LSTM?"))
for z in (0.1, 0.5, 0.9):
    print("%10.1f %14.2f %14.2f %s" % (z, 1 - z, z, "yes"))
print("%10s %14s %14s %s" % ("--", "0.99", "0.95", "yes -- accumulate"))
print("%10s %14s %14s %s" % ("--", "0.05", "0.01", "yes -- clear"))
print("   the GRU cannot do those last two: it cannot accumulate without")
print("   also forgetting, or clear without also writing. that is one fewer")
print("   parameter set to train and one fewer thing it can express, and in")
print("   practice the two architectures score very close to each other.")
print()

print("the bias here is initialised at 0, not 1 like the forget gate:")
print("   bi = 0 -> gate starts at %.4f, so the cell begins half-open to"
      % sigmoid(0.0))
print("   new information and learns from there. starting it near 1 would")
print("   flood the memory before the model has learned what matters.")
```

## Things to try

1. <strong>Run the simulation.</strong> The highlighted route shows $i_t$ leaving the glowing gate, meeting the candidate at the $\times$ operator, and only then rising to the $+$ on the conveyor belt.
2. <strong>Set the gate to 0 but leave the candidate at 0.80.</strong> The written amount drops to zero. The network did all the work of computing a rich candidate and then threw it away &mdash; the cell state simply passes through untouched.
3. <strong>Open the gate to 1.00 and sweep the candidate.</strong> Now the written amount tracks the candidate exactly, including negative values that pull the memory slot down.
4. <strong>Try gate 1.00 with candidate 0.00.</strong> Nothing is written even though the gate is wide open &mdash; proof that the gate controls volume, not content.

## In one line

The Input Gate is the LSTM's write-enable line. It converts a proposal into an actual memory change, one dimension at a time, and it does so by <em>adding</em> rather than overwriting. To see where that proposal comes from, study the <strong>Candidate Memory</strong> layer next.

## What goes wrong

<strong>The gate stays closed.</strong> If `i` is consistently near 0, nothing new ever enters memory and the cell state is frozen. The model behaves as if it had no memory at all beyond the current input. Usually a symptom of a learning rate or initialisation problem, or a task where the model has found no use for memory.

<strong>The gate stays open.</strong> If `i` is consistently near 1 while the forget gate is also near 1, the cell state grows without bound as contributions accumulate. Values in the hundreds appear, tanh in the output path saturates, and gradients vanish through the output gate. Layer normalisation inside the cell is one remedy.

<strong>Saturated sigmoids.</strong> A gate pinned at 0 or 1 has a derivative near zero, so it stops learning when to open and close. Keeping pre-activations in a reasonable range &mdash; scaled inputs, sensible initialisation &mdash; prevents it.

Diagnosing these means logging the mean and spread of gate activations:

```python
# with a manual cell that returns its gates
print(f"input gate: mean {i.mean():.3f}  std {i.std():.3f}")
```

Healthy gates have a mean somewhere in the middle of the range and genuine variation across dimensions and time steps. A mean of 0.99 with a standard deviation of 0.001 means the gate has stopped being a gate.

## Parameter cost

Each gate needs its own weight matrix over the concatenated previous hidden state and current input:

<p class="mono-font">per gate: (input + hidden) &times; hidden + hidden</p>

With 300-dimensional input and 256 hidden units that is 143,616 parameters per gate. An LSTM has four such matrices &mdash; forget, input, candidate and output &mdash; so about 574,000 per layer.

That is why LSTMs are heavier than they appear, and why a GRU with three matrices instead of four is roughly 25% smaller. In practice the four are computed as one fused matrix multiplication and then split, which is what `nn.LSTM` does internally and why it is much faster than a hand-written loop.

## Questions people ask

<strong>Why does the candidate use tanh and the gate use sigmoid?</strong> Content should be able to be negative, so tanh. A gate is a fraction, so sigmoid.

<strong>Is the input gate the same as the update gate in a GRU?</strong> Related but not the same. A GRU's update gate does the work of forget and input together, with coupled coefficients.

<strong>Can the input gate be negative?</strong> No &mdash; sigmoid output is strictly between 0 and 1. Negative <em>content</em> comes from the candidate.

<strong>What if the input gate is always 0?</strong> The cell never stores anything new, and memory is useless. Check initialisation and learning rate.

<strong>Should its bias be initialised specially?</strong> Zero is standard. It is the <em>forget</em> gate that benefits from a bias of 1.

<strong>Are the four matrices computed separately?</strong> No &mdash; implementations concatenate them into one multiplication and split the result, which is considerably faster.

## Recap in one screen

- The input gate decides how much new information to write; the candidate decides what that information is.
- Sigmoid for the gate (a fraction), tanh for the candidate (content that may be negative).
- Their elementwise product is added to the retained old state.
- Separate forget and input gates let a cell keep old memory and add new at full strength &mdash; a GRU cannot.
- Watch for gates saturated at 0 or 1: a gate that never varies has stopped functioning as one.
