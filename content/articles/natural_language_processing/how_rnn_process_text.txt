## The Power of Memory in Language

<p>Standard neural networks have a major limitation: they have no memory of the past. They process each input independently. This is a problem for language, where the order of words is crucial. For example, "dog bites man" and "man bites dog" use the same words but have completely different meanings.</p><strong>Recurrent Neural Networks (RNNs)</strong> solve this by introducing a <strong>memory loop</strong>. As an RNN reads a sentence word by word, it passes a summary of what it has seen so far to the next step. This summary is called the <strong>hidden state</strong>.

## The Unrolled RNN: Step-by-Step Processing

The visualization above "unrolls" the RNN loop, showing it as a sequence of identical cells, one for each word (or "time step"). Here’s how the information flows:

1. <strong>Time Step 1 (First Word):</strong> The network takes the first word's embedding (a numerical vector, $X_1$) and an initial hidden state ($H_0$, usually all zeros). It processes them to produce an output ($Y_1$) and, most importantly, a new hidden state ($H_1$).
2. <strong>Time Step 2 (Second Word):</strong> The network takes the second word's embedding ($X_2$) and the <em>previous</em> hidden state ($H_1$). This is the memory! $H_1$ contains information about the first word, giving the network context. It then produces a new output ($Y_2$) and an updated hidden state ($H_2$).
3. <strong>And so on...:</strong> This process repeats for every word in the sequence. Each step receives the current word and the memory of all preceding words.

## Shared Weights: The Key to Learning

A crucial concept in RNNs is <strong>shared weights</strong>. The same set of calculations (the same "brain") is used at every single time step. This is incredibly efficient. Instead of learning a new set of rules for the first word, second word, etc., the RNN learns a single set of rules for how to update its memory based on a new word and its previous memory. The "Parameters" calculation in the visualization shows the size of these shared weights.

## One word at a time, carrying a state

A recurrent network processes a sequence step by step. At each step it combines the current input with what it remembers from before:

<p class="mono-font">h&#7511; = tanh(W&#8341;&#8341; h&#7511;&#8331;&#8321; + W&#8339;&#8341; x&#7511; + b)</p>

`hₜ` is the hidden state &mdash; a fixed-size vector summarising everything seen so far. `xₜ` is the current word's embedding. The same weight matrices are used at every step, which is parameter sharing along the time axis.

Walking through "the cat sat":

|Step|Input|State contains|
|---|---|---|
|1|"the"|A determiner has appeared|
|2|"cat"|A noun phrase, subject-like|
|3|"sat"|A subject and its verb|

Each state is a function of the current word and the previous state, so information propagates forward by being repeatedly transformed.

That single design choice &mdash; one weight matrix reused at every step &mdash; is what lets an RNN handle sequences of any length with a fixed number of parameters.

## The architectures it supports

|Shape|Input &rarr; output|Example|
|---|---|---|
|Many-to-one|Sequence &rarr; one label|Sentiment classification|
|Many-to-many, aligned|Sequence &rarr; sequence of the same length|Part-of-speech tagging|
|Many-to-many, unaligned|Sequence &rarr; different-length sequence|Translation (encoder-decoder)|
|One-to-many|One input &rarr; sequence|Image captioning|

For classification, use the final hidden state &mdash; or better, pool over all states, since the final one is biased towards the end of the sequence.

For an encoder-decoder, the encoder's final state is the "thought vector" passed to the decoder. That design is exactly where attention was invented: compressing a whole sentence into one fixed vector is a bottleneck, and letting the decoder look back at every encoder state instead removed it.

## Two structural limitations

<strong>Vanishing gradients.</strong> Backpropagation through 50 steps multiplies 50 Jacobian factors. If they average below 1, the gradient reaching step 1 is effectively zero, so the network cannot learn that step 1 mattered. Tanh's derivative is at most 1 and usually well below it, so decay is the default.

<strong>No parallelism.</strong> Step t needs `hₜ₋₁`, so the steps must run in order. A GPU's thousands of cores sit mostly idle, and training time scales with sequence length. This is a hardware-utilisation problem, and it is the reason transformers displaced RNNs at scale rather than any single quality issue.

The first was addressed by gating (LSTM, GRU). The second was not addressable within the recurrent framework at all &mdash; which is why the field moved to attention.

## The loop, and the four shapes it can take

An RNN reads one token at a time and updates one state. Where you take the output from decides whether you have a classifier, a tagger, a generator or a translator -- four architectures from the same loop.

```python-run
import numpy as np

rng = np.random.default_rng(0)
vocab = ["<pad>", "the", "film", "was", "not", "very", "good", "bad", "."]
idx = {w: i for i, w in enumerate(vocab)}
V, D, H = len(vocab), 6, 5

E = rng.normal(0, 0.5, (V, D))
Wx = rng.normal(0, 0.5, (D, H))
Wh = rng.normal(0, 0.5, (H, H))
b = np.zeros(H)
Wy = rng.normal(0, 0.5, (H, 2))          # 2 outputs, for illustration

def step(x, h):
    return np.tanh(x @ Wx + h @ Wh + b)

sent = "the film was not very good .".split()
ids = [idx[w] for w in sent]
print("the pipeline, end to end:")
print("   text   : %r" % " ".join(sent))
print("   tokens : %s" % sent)
print("   ids    : %s" % ids)
print("   vectors: %d x %d (one row per token)" % (len(ids), D))
print()

h = np.zeros(H)
states = []
print("then the loop. one token in, one state out, %d times:" % len(ids))
print("%10s %8s %30s" % ("token", "id", "hidden state"))
for w, i in zip(sent, ids):
    h = step(E[i], h)
    states.append(h.copy())
    print("%10s %8d %30s" % (w, i, np.round(h, 4)))
print()
print("the state after the last token has seen the whole sentence. the state")
print("after 'not' has seen only the first four words -- and that asymmetry")
print("is what makes the four shapes below different.")
print()

print("SHAPE 1 -- MANY TO ONE. take only the final state:")
logits = states[-1] @ Wy
print("   final state -> %s -> class %d"
      % (np.round(logits, 4), int(logits.argmax())))
print("   used for: sentiment, topic classification, spam detection.")
print("   the whole sentence is compressed into %d numbers before any" % H)
print("   decision is made.")
print()

print("SHAPE 2 -- MANY TO MANY, aligned. take EVERY state:")
print("%10s %26s %10s" % ("token", "state", "tag"))
for w, s in zip(sent, states):
    print("%10s %26s %10d" % (w, np.round(s[:3], 3), int((s @ Wy).argmax())))
print("   used for: part-of-speech tagging, named entity recognition.")
print("   one output per input, and each one only sees the tokens BEFORE")
print("   it -- which is why taggers are usually bidirectional.")
print()

print("SHAPE 3 -- ONE TO MANY. one input, then feed each output back in:")
h = step(E[idx["the"]], np.zeros(H))
generated = ["the"]
for _ in range(4):
    probs = np.exp(h @ Wy - (h @ Wy).max())
    nxt = vocab[1 + int(np.argmax(np.abs(h)) % (V - 1))]   # a stand-in decoder
    generated.append(nxt)
    h = step(E[idx[nxt]], h)
print("   %s" % " ".join(generated))
print("   (these weights are random and the decoder is a stand-in, so the")
print("   output is gibberish. the SHAPE is the point -- output becomes")
print("   input, and the loop keeps going as long as you let it.)")
print("   used for: text generation, image captioning.")
print("   note the model's own output becomes its next input, so an early")
print("   mistake propagates -- that is exposure bias, and it is why")
print("   generation quality degrades with length.")
print()

print("SHAPE 4 -- MANY TO MANY, unaligned (encoder-decoder). read the whole")
print("input, then start writing:")
print("   encoder: %s -> final state %s" % (" ".join(sent), np.round(states[-1][:3], 3)))
print("   decoder: starts from that state and produces its own sequence")
print("   used for: translation, summarisation.")
print("   the input and output lengths need not match, which none of the")
print("   first three shapes allow.")
print()

print("AND THE PROBLEM THE FIRST AND FOURTH SHARE. everything the model")
print("knows is in %d numbers, whatever the input length:" % H)
for L in (4, 10, 30):
    a = [idx[vocab[1 + (i % (V - 1))]] for i in range(L)]
    hh = np.zeros(H)
    for i in a:
        hh = step(E[i], hh)
    aa = list(a); aa[0] = idx["bad"] if aa[0] != idx["bad"] else idx["good"]
    hh2 = np.zeros(H)
    for i in aa:
        hh2 = step(E[i], hh2)
    print("   length %2d: changing the FIRST token moves the final state by %.6f"
          % (L, np.linalg.norm(hh - hh2)))
print("   by 30 tokens the first word is gone. for classification that may")
print("   be survivable; for translation it is not, and that is exactly the")
print("   bottleneck attention was invented to remove.")
```

## Where that leaves you

RNNs are designed for sequential data like text. Their core feature is the <strong>hidden state</strong>, a memory that is passed through time, allowing the network to remember previous inputs and understand context. By using shared weights, they can efficiently process sequences of any length, making them a cornerstone of modern Natural Language Processing.

## Backpropagation through time

Training an RNN means unrolling it. A 50-word sentence becomes a 50-layer feed-forward network that happens to share weights, and ordinary backpropagation is applied to that unrolled graph.

The gradient for a shared weight is the <strong>sum</strong> of its gradients from every time step, since it was used at all of them.

Two practical consequences:

<strong>Memory grows with sequence length,</strong> because every step's activations must be stored for the backward pass. Long sequences exhaust memory quickly.

<strong>Truncated BPTT</strong> is the standard remedy: backpropagate only k steps back (typically 20&ndash;50) rather than to the beginning. It bounds memory and compute, at the cost of not learning dependencies longer than k.

Gradient clipping is essentially mandatory here. The same multiplication that vanishes gradients can explode them, and a single large gradient destroys the weights in one step.

## Practical notes

```python
import torch.nn as nn

rnn = nn.LSTM(300, 256, batch_first=True)      # prefer LSTM/GRU over nn.RNN
out, (h, c) = rnn(packed_input)
```

`nn.RNN` &mdash; the plain version &mdash; is almost never the right choice; use an LSTM or GRU, which cost little more and train far better.

Three details that matter with real text:

<strong>Pack variable-length sequences.</strong> `pack_padded_sequence` tells the RNN to stop at each sequence's real end. Without it, the final hidden state summarises the padding rather than the sentence.

<strong>Sort or bucket by length</strong> when batching, so batches contain similar lengths and less padding is wasted.

<strong>Consider bidirectionality</strong> for classification and tagging &mdash; running one RNN forward and another backward and concatenating gives each position both left and right context. Not available for generation or streaming.

## Questions people ask

<strong>Are RNNs still used?</strong> Yes, in streaming inference with bounded memory, on-device models, small datasets and classical time-series work. Not for large-scale language modelling.

<strong>Why does the same weight matrix apply at every step?</strong> Parameter sharing along time &mdash; the same reason a convolution shares filters across space. It lets one model handle any length.

<strong>How long a sequence can an LSTM handle?</strong> Hundreds of steps in practice; thousands is unreliable. Transformers handle far longer, at quadratic cost.

<strong>What is the hidden state size?</strong> A hyperparameter, typically 128&ndash;512. Larger means more memory capacity and more parameters.

<strong>Can I stack RNN layers?</strong> Yes, and two is usually the practical limit &mdash; deeper stacks are hard to train.

<strong>Why did transformers replace them?</strong> Parallelism across the sequence and constant path length between positions. Both are structural advantages that gating cannot provide.

## Recap in one screen

- An RNN carries a fixed-size hidden state, updated at each step from the input and the previous state.
- The same weights are reused at every step, so one model handles any sequence length.
- Training unrolls the sequence and sums each weight's gradient across all steps.
- Vanishing gradients limit range (fixed by gating); the sequential dependency prevents parallelism (not fixable).
- Pack variable-length batches, clip gradients, and prefer LSTM or GRU over the plain cell.
