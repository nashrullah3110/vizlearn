title: RNN Architecture: A Practical Guide
intro: Unrolling a recurrent cell across time gives a network as deep as the sequence is long - sharing one set of weights the whole way. That is what makes RNNs efficient, and what makes them hard to train.

## Unrolling

An RNN is usually drawn as a cell with an arrow looping back to itself. That is compact and slightly misleading. To understand training, unroll it: draw one copy of the cell per timestep, with the hidden state flowing left to right between copies.

Unrolled, an RNN over a 50-token sentence is a <strong>50-layer deep network</strong>. Every layer is the same layer &mdash; identical weights &mdash; but the computational graph really is that deep, and the gradient really does have to travel all the way back through it.

## Counting the parameters

A recurrent cell with input size d and hidden size h has:

W<sub>x</sub>: d &times; h&nbsp;&nbsp;&nbsp;&nbsp;W<sub>h</sub>: h &times; h&nbsp;&nbsp;&nbsp;&nbsp;b: h

total = dh + h&sup2; + h

With d = 100 and h = 128 that is 12,800 + 16,384 + 128 = <strong>29,312</strong> parameters &mdash; and that number does not change whether the sequence is 5 tokens or 5,000. The <span class="mono-font">h&sup2;</span> term usually dominates, which is why hidden size is the expensive dimension and doubling it roughly quadruples the recurrent weights.

## Backpropagation through time

<p>Training unrolls the network, runs a normal forward pass, then backpropagates from the loss all the way back to timestep 1. Because the same weights appear at every step, the gradient for <span class="mono-font">W<sub>h</sub></span> is the <em>sum</em> of its gradient contributions from all timesteps.</p><p>This is called backpropagation through time, and it has two practical consequences. Memory grows linearly with sequence length, since every intermediate hidden state must be kept for the backward pass. And the gradient reaching early timesteps is a long product, so it vanishes or explodes exactly as depth causes it to in a feedforward network.</p><strong>Truncated BPTT</strong> is the standard mitigation: backpropagate only k steps back, typically 20 to 50, and treat anything earlier as constant. It bounds memory and gradient depth at the cost of never learning dependencies longer than k.

## The shapes a recurrent network can take

The cell is the same in every case. What changes is where inputs enter and where outputs are taken, and that determines what the network can do.

|Shape|Input &rarr; output|Example|
|---|---|---|
|One-to-many|One vector &rarr; sequence|Image captioning|
|Many-to-one|Sequence &rarr; one value|Sentiment classification|
|Many-to-many, aligned|Sequence &rarr; same-length sequence|Part-of-speech tagging|
|Many-to-many, unaligned|Sequence &rarr; different-length sequence|Translation|

<strong>Many-to-one</strong> takes an output only at the end. Use pooled hidden states rather than only the final one, since the final state over-weights the end of the input.

<strong>Many-to-many aligned</strong> takes an output at every step, and a bidirectional layer usually helps because right context disambiguates.

<strong>Many-to-many unaligned</strong> needs two networks: an encoder that reads the input and a decoder that produces the output. This is where attention was invented.

## The encoder-decoder, and the bottleneck that motivated attention

For translation, an encoder reads the source sentence and its final hidden state is passed to a decoder, which generates the target one token at a time.

That final state is a fixed-size vector &mdash; 512 numbers, say &mdash; and it must contain everything about the source sentence. For five words that is comfortable. For fifty it is a severe compression, and translation quality was observed to fall sharply with sentence length.

<strong>Attention</strong> removed the bottleneck: instead of passing only the final state, keep <em>all</em> the encoder's hidden states, and let the decoder compute a weighted combination at each output step, choosing what to look at.

That change &mdash; introduced for exactly this problem &mdash; improved translation immediately, and within a few years the attention mechanism had displaced the recurrence it was invented to assist. "Attention is all you need" is a literal description of what happened next.

## Depth, and how to add it

Stacking recurrent layers means feeding one layer's output sequence into the next:

```python
lstm = nn.LSTM(300, 256, num_layers=2, batch_first=True, dropout=0.2)
```

The `dropout` argument applies <em>between</em> layers, not within the recurrence &mdash; applying dropout to the recurrent connection with a different mask each step damages the memory, which is why variational dropout (the same mask at every step) exists.

Two layers is the practical limit for most tasks. Deep recurrent stacks are hard to train: the gradient must travel back through both depth and time, and the two decays compound. Residual connections between layers help and are less standard here than in transformers.

Two other structural choices:

<strong>Bidirectional</strong> layers run a second pass backwards and concatenate, doubling the output width. Excellent for tagging and classification, unusable for generation or streaming.

<strong>Where the output head goes.</strong> On the final layer, always &mdash; but note that in a stacked bidirectional model, extracting the right final states requires care, since each direction's final state corresponds to a different end of the sequence.

## One weight matrix, applied over and over

An RNN is a loop with shared weights. Unrolling it shows why that sharing is the whole idea and also the whole problem.

```python-run
import numpy as np

rng = np.random.default_rng(0)
H, X, T = 4, 3, 6
Wx = rng.normal(0, 0.5, (X, H))
Wh = rng.normal(0, 0.5, (H, H))
b = np.zeros(H)
seq = rng.normal(0, 1.0, (T, X))

print("the entire architecture is one line, run in a loop:")
print("    h = tanh(x @ Wx + h @ Wh + b)")
print()
print("parameters: Wx %s + Wh %s + b %s = %d numbers, and they do NOT"
      % ((X, H), (H, H), (H,), Wx.size + Wh.size + b.size))
print("grow with sequence length. a 5-token sequence and a 5000-token one")
print("use exactly the same weights.")
print()

h = np.zeros(H)
print("%6s %28s %28s" % ("step", "input x", "hidden h"))
for t, x in enumerate(seq):
    h = np.tanh(x @ Wx + h @ Wh + b)
    print("%6d %28s %28s" % (t, np.round(x, 3), np.round(h, 4)))
print()
print("h is the only thing carried forward. everything the network knows")
print("about the first %d tokens has to fit in those %d numbers." % (T - 1, H))
print()

print("THE SHARING IS THE POINT. compare against a feed-forward network")
print("that takes the whole sequence at once:")
for t in (10, 100, 1000):
    rnn = X * H + H * H + H
    ff = (t * X) * H + H
    print("   %5d tokens: RNN %6d parameters, feed-forward %8d"
          % (t, rnn, ff))
print("   and the feed-forward version can only ever accept exactly the")
print("   length it was built for. the RNN accepts any length, and what it")
print("   learned about position 3 applies at position 300.")
print()

print("UNROLLED, it is a very deep network with tied weights:")
print("   x0 -> [tanh] -> h0")
print("   x1 -> [tanh] -> h1     each box is the SAME Wh")
print("   x2 -> [tanh] -> h2")
print("   ...")
print("   a %d-token sequence is a %d-layer network. that is where the" % (T, T))
print("   trouble starts.")
print()

print("THE PROBLEM. the gradient from a late step back to step 0 passes")
print("through Wh once per step, so it is governed by that matrix's")
print("eigenvalues:")
print("   %-14s %18s %22s" % ("weight sd", "spectral radius", "after 50 steps"))
for scale in (0.15, 0.3, 0.5, 0.8):
    W = rng.normal(0, scale, (H, H))
    rho = np.abs(np.linalg.eigvals(W)).max()
    val = rho ** 50
    print("   %-14.2f %18.4f %22s"
          % (scale, rho, "%.3e" % val if val < 1e100 else "overflow"))
print("   below 1 it vanishes, above 1 it explodes, and only exactly 1")
print("   survives. tanh's derivative is at most 1 and usually less, which")
print("   pushes the product further down.")
print()
LONG = 40
long_seq = rng.normal(0, 1.0, (LONG, X))
h = np.zeros(H)
J = np.eye(H)
grads = []
for t, x in enumerate(long_seq):
    h = np.tanh(x @ Wx + h @ Wh + b)
    J = J @ (Wh * (1 - h ** 2))          # accumulate the Jacobian
    grads.append(np.abs(J).max())
print("   measured on a %d-step sequence with these actual weights --" % LONG)
print("   how much gradient still reaches step 0 from step t:")
for t in (0, 2, 5, 10, 20, 30, 39):
    g = grads[t]
    print("      from step %2d: %.3e  %s"
          % (t, g, "#" * max(0, int(30 * min(g, 1.0)))))
print("   by step %d it is %.1e of what it started as. no amount of"
      % (LONG - 1, grads[-1] / grads[0]))
print("   training fixes that -- it is a property of repeated multiplication.")
print()

print("WHAT AN RNN IS STILL GOOD FOR. it processes one token at a time in")
print("O(1) memory per step, where attention needs the whole sequence:")
for t in (128, 1024, 8192):
    print("   %5d tokens: RNN state %4d numbers, attention matrix %12s"
          % (t, H, "{:,}".format(t * t)))
print("   that is why RNN-shaped models keep being revisited for very long")
print("   sequences and for streaming, where you cannot hold the whole")
print("   input at once. state-space models are the current form of that")
print("   argument.")
print()
print("but for anything that fits in a context window, attention won on two")
print("counts: it has a direct path between any two positions rather than a")
print("chain of %d multiplications, and it is parallel across the sequence"
      % T)
print("where this loop is inherently sequential.")
```

## Things to try

1. <strong>See where the parameters live.</strong> Press <strong>Parameters</strong> and read the breakdown. The recurrent matrix is the largest block, because it is h &times; h while the input matrix is only d &times; h.
2. <strong>Grow the hidden state.</strong> Raise <strong>Hidden State</strong> from 10 to 40 and check the parameter count again. It grows roughly with the square, not linearly &mdash; the h&sup2; term taking over.
3. <strong>Grow the input instead.</strong> Raise <strong>Input Vector</strong> by the same amount. The parameter count rises far less, because that dimension only appears in the d &times; h term.
4. <strong>Watch one step execute.</strong> Press <strong>Simulate Cell Operation</strong> and follow the two matrix multiplications combining and passing through tanh. That single operation is what gets repeated once per token, with the same weights every time.

## The sequence shapes an RNN can be wired into

- <strong>Many-to-one</strong> &mdash; read the whole sequence, use only the final hidden state. Sentiment classification.
- <strong>Many-to-many, aligned</strong> &mdash; one output per input. Part-of-speech tagging and named entity recognition.
- <strong>Many-to-many, unaligned</strong> &mdash; an encoder reads the input into a state and a decoder generates a different-length output. Translation, and the architecture attention was invented to improve.
- <strong>One-to-many</strong> &mdash; a single input generates a sequence. Image captioning.

## Where this goes wrong

- <strong>Not clipping gradients.</strong> The repeated multiplication makes explosion common. Clipping the global norm at around 1.0 is close to mandatory for recurrent models.
- <strong>Padding without masking.</strong> Batching requires equal lengths, so short sequences are padded &mdash; and unless those positions are masked, the model learns from the padding and the loss is computed over meaningless tokens.
- <strong>Running out of memory on long sequences.</strong> Every hidden state is retained for the backward pass. Truncate the BPTT window rather than reducing the batch to one.
- <strong>Expecting parallelism.</strong> Timestep t needs the state from t&minus;1, so an RNN is inherently sequential and cannot use a GPU the way a transformer can. That, more than accuracy, is why transformers displaced them.

## In one line

An RNN is one cell unrolled across time, sharing weights at every step, so its parameter count is fixed at dh + h&sup2; + h regardless of sequence length. Training backpropagates through the whole unrolled graph, which makes the effective depth equal to the sequence length &mdash; hence vanishing gradients, mandatory gradient clipping, and truncated BPTT. The sequential dependency is also what stops it parallelising, which is what eventually made attention the better architecture.

## Building one end to end

```python
class TextClassifier(nn.Module):
    def __init__(self, vocab, emb=300, hidden=256, classes=2):
        super().__init__()
        self.embed = nn.Embedding(vocab, emb, padding_idx=0)
        self.lstm = nn.LSTM(emb, hidden, num_layers=2, batch_first=True,
                            bidirectional=True, dropout=0.3)
        self.drop = nn.Dropout(0.3)
        self.head = nn.Linear(hidden * 2, classes)     # *2 for bidirectional

    def forward(self, ids, lengths):
        x = self.embed(ids)
        packed = pack_padded_sequence(x, lengths, batch_first=True,
                                      enforce_sorted=False)
        out, _ = self.lstm(packed)
        out, _ = pad_packed_sequence(out, batch_first=True)

        mask = (ids != 0).unsqueeze(-1)
        pooled = (out * mask).sum(1) / mask.sum(1).clamp(min=1)
        return self.head(self.drop(pooled))
```

Four details in that code are the ones that matter in practice: `padding_idx=0` keeps the pad embedding at zero, packing stops the LSTM processing padding, `hidden * 2` accounts for bidirectionality, and the masked mean pooling ignores padding when summarising.

Getting any of the four wrong produces a model that trains and underperforms without an error message.

## Training notes

<strong>Clip gradients.</strong> `clip_grad_norm_(params, 5.0)`. Recurrent models are the classic case, and omitting it eventually produces `NaN`.

<strong>Sort or bucket by length</strong> when batching, so batches contain similar lengths and less computation is wasted on padding.

<strong>Watch memory against sequence length.</strong> Activation memory grows linearly with the number of steps, so a model that fits at 200 tokens may fail at 500.

<strong>Use pretrained embeddings</strong> where available, and consider freezing them with small datasets &mdash; there is far less to overfit.

<strong>Truncate backpropagation</strong> for very long sequences, detaching the state every k steps.

## Questions people ask

<strong>How many layers should I use?</strong> One or two. Deeper recurrent stacks rarely repay the training difficulty.

<strong>Should I use the last hidden state or pool?</strong> Pool, for classification.

<strong>Where does dropout go?</strong> Between layers via the `dropout` argument, and after pooling before the head. Not on the recurrent connection with a per-step mask.

<strong>Bidirectional or not?</strong> Bidirectional for classification and tagging; unidirectional for generation and streaming.

<strong>Is an encoder-decoder RNN still used?</strong> Rarely for translation. The structure survives in transformers, with attention doing the work the recurrence used to.

<strong>Why did attention replace this?</strong> It removed the fixed-size bottleneck between encoder and decoder, and then proved sufficient without the recurrence at all.

## Recap in one screen

- One cell, four arrangements: one-to-many, many-to-one, aligned and unaligned many-to-many.
- Unaligned tasks need an encoder and a decoder, and the fixed-size state between them was the bottleneck attention was invented to remove.
- Stack at most two layers; put dropout between them, not inside the recurrence.
- Bidirectional doubles the output width and requires the complete input.
- Pack padded batches, clip gradients, and pool over states rather than taking the last one.
