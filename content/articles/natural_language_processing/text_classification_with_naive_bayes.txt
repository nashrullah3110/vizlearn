intro: Multiply word probabilities under each class label and pick the winner. The maths is one line, the assumption is wrong, and the classifier works anyway.

## What Naive Bayes assumes

You have a document and a set of possible class labels. Naive Bayes treats the document as a bag of words and assumes every word is conditionally independent of every other word given the class. That assumption is plainly false. The word "not" changes the meaning of every word that follows it, and "New" before "York" is not the same as "New" before "idea". The model ignores all of that.

The payoff is that the joint probability of all the words factorises into a product of individual word probabilities, which you can estimate from counts alone. No optimiser, no matrix algebra, no GPU. One pass through the training data builds the whole model.

## The maths

For a document d made of words w<sub>1</sub>, w<sub>2</sub>, &hellip;, w<sub>n</sub>, Bayes' theorem gives:

P(class | d) &prop; P(class) &times; &prod; P(w<sub>i</sub> | class)

P(class) is the prior: the fraction of training documents that belong to that class. P(w<sub>i</sub> | class) is the likelihood: how often the word w<sub>i</sub> appears in documents of that class. You compute both from counts, multiply them together, and pick the class with the highest score.

That is the entire algorithm. The visualisation above lets you type a sentence and watch each word contribute evidence for or against each class.

## Why log-probabilities

Multiplying many small probabilities together produces numbers so small that floating-point arithmetic rounds them to zero. A document with 200 words can push the product below 10<sup>&minus;300</sup>, which underflows in 64-bit floating point.

The fix is to work in log space. Since log is monotonic, the class that maximises the product also maximises the sum of logs:

log P(class | d) = log P(class) + &sum; log P(w<sub>i</sub> | class)

Addition is cheaper than multiplication and never underflows. This is what every practical implementation does, and what the visualisation above shows.

## Laplace smoothing

A word that never appeared in positive training documents gets P(word | positive) = 0. One zero anywhere makes the entire product zero, so the model ignores all the other evidence. A single unseen word vetoes the entire classification.

<strong>Laplace smoothing</strong> (add-1 smoothing) fixes this by adding a pseudocount of 1 to every word count:

P(w | class) = (count(w, class) + 1) / (total words in class + V)

V is the vocabulary size. The denominator grows by V to keep the probabilities summing to 1. The effect is that no word ever has zero probability. The cost is that rare words get a slight boost relative to their true frequency, but this is almost always worth it.

You can generalise to add-&alpha; smoothing by using a fractional pseudocount. &alpha; = 1 is the most common choice.

## Where it works and where it fails

Naive Bayes works well for:

- **Spam filtering.** The bag-of-words model is a natural fit because spam is mostly about which words appear, not their exact arrangement.
- **Sentiment analysis.** Words like "excellent", "terrible" and "disappointing" carry strong class signal on their own.
- **Topic classification.** Documents about sport contain sport words; documents about politics contain politics words.
- **Medical text triage.** Routing clinical notes by specialty based on keyword frequency.

It struggles when:

- **Word order matters.** "The movie was not good" and "The movie was good, not bad" have overlapping word sets but opposite meanings. Naive Bayes cannot distinguish them.
- **Words interact.** "Hot dog" means something different from "hot" and "dog" separately.
- **Classes are defined by absence.** Some categories are defined less by which words appear and more by which words do not. A bag-of-words model has no natural way to represent that.

For tasks where order matters, [n-grams](n_gram.html) partially help by treating bigrams as features. For richer representations, [embeddings](what_are_embeddings.html) capture meaning that word counts miss, and [text encoding](why_text_encoding_is_needed_in_nlp.html) explains why the conversion from text to numbers is needed at all.

## A Naive Bayes classifier from scratch

```python
import math
from collections import Counter, defaultdict

# ---- tiny training set ----
train = [
    ("I love this movie", "positive"),
    ("great film and wonderful acting", "positive"),
    ("terrible waste of time", "negative"),
    ("awful movie I hated it", "negative"),
]

# ---- build counts ----
class_counts = Counter()
word_counts  = defaultdict(Counter)
vocab = set()

for text, label in train:
    words = text.lower().split()
    class_counts[label] += 1
    for w in words:
        word_counts[label][w] += 1
        vocab.add(w)

V = len(vocab)
total = sum(class_counts.values())

# ---- classify a new document ----
def classify(text):
    words = text.lower().split()
    scores = {}
    for label in class_counts:
        log_p = math.log(class_counts[label] / total)
        n = sum(word_counts[label].values())
        for w in words:
            log_p += math.log((word_counts[label][w] + 1) / (n + V))
        scores[label] = log_p
    return max(scores, key=scores.get), scores

pred, scores = classify("I love great acting")
print(f"Prediction: {pred}")
for label, s in scores.items():
    print(f"  {label}: {s:.4f}")
```

The code uses Laplace smoothing (the +1 in the numerator) and works entirely in log space. It trains in one pass and classifies in time proportional to the document length times the number of classes.

## Questions people ask

**Is Naive Bayes actually "naive"?**
Yes. The conditional independence assumption is almost never true for real language. But the classifier needs correct rankings, not correct probabilities, and the independence assumption rarely changes which class scores highest.

**When should I use Naive Bayes over logistic regression?**
When you have very little training data, many features, or need a fast baseline. Naive Bayes has fewer parameters to estimate, so it handles sparse high-dimensional data well. With enough data, logistic regression usually wins on accuracy.

**Does Naive Bayes work with TF-IDF features?**
The multinomial variant uses raw counts. If you want TF-IDF, the complement Naive Bayes variant or a simple logistic regression is a better match. Scikit-learn provides both.

**What is the difference between multinomial and Bernoulli Naive Bayes?**
Multinomial uses word counts. Bernoulli uses binary presence or absence. For short texts like tweets, Bernoulli sometimes works better because repeated words add little information.

**Can Naive Bayes handle more than two classes?**
Yes. The formula generalises to any number of classes. You compute P(class) and the word likelihoods for each class independently, then pick the class with the highest score.

**Why does Naive Bayes still appear in production systems?**
Because it trains in milliseconds, classifies in microseconds, and gives a strong baseline. Many production spam filters and content classifiers still use it, sometimes as the first stage of a pipeline that escalates uncertain cases to a heavier model.
