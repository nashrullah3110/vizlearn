title: Candidate Memory: Proposing the New Content
intro: Three of the LSTM's four internal layers are sigmoid gates that control flow. This one is different: it is the only layer that manufactures the information itself.

## A Proposal, Not a Decision

The candidate layer &mdash; written $\tilde{C}_t$ and read "C-tilde" &mdash; takes the same merged vector as every other layer and produces a fresh piece of content:

$$\tilde{C}_t = \tanh(W_C \cdot [H_{t-1}, X_t] + b_C)$$

It has no authority. It cannot write to memory on its own; the Input Gate decides how much of it survives. Think of it as an <strong>employee drafting a proposal</strong> and the input gate as the manager approving some, all, or none of it.

## Why $\tanh$ and Not a Sigmoid?

This is the question that separates people who have memorised the diagram from people who understand it. The answer is <strong>sign</strong>.

- A sigmoid outputs $[0, 1]$. Every update it proposed would <em>increase</em> the memory value. The cell state could only ever drift upward.
- $\tanh$ outputs $[-1, 1]$. The candidate can push a memory slot <strong>up or down</strong>, which is what real information requires &mdash; "this sentence is negative" needs to be representable, not just "more of something".

Being zero-centred also helps optimisation: the updates do not carry a systematic positive bias that the rest of the network has to cancel out.

## Bounded Output Keeps Memory Stable

Because the cell state is repeatedly <em>added</em> to, an unbounded proposal would let $C_t$ grow without limit over a long sequence and blow up the activations. Clamping every proposal to $[-1, 1]$ means each step can move a memory slot by at most 1. Combined with the Forget Gate's decay, the cell state stays in a numerically comfortable range no matter how long the sequence runs.

## The Cost of Bounding: Saturation

The same squashing that keeps things stable creates a trap. The derivative of $\tanh$ is $1 - \tanh^2(z)$: it peaks at <strong>1.0</strong> when $z = 0$ and collapses toward <strong>0</strong> as $|z|$ grows. Once a unit is driven to $z = \pm 4$, its output is stuck near $\pm 1$ and almost no gradient flows back &mdash; the unit has effectively stopped learning.

This is why weight initialisation and normalisation matter so much. They keep pre-activations near the middle of the curve, where the layer is still responsive.

## The content, before the decision to store it

The candidate memory is what the cell <em>could</em> add to its state at this step. It is computed from the same inputs as the gates, with one important difference:

<p class="mono-font">g&#7511; = tanh(W&#7509; &middot; [h&#7511;&#8331;&#8321;, x&#7511;] + b&#7509;)</p>

Note the <strong>tanh</strong>, not sigmoid. That is the whole distinction between content and gate:

|&nbsp;|Candidate `g`|Gates `f`, `i`, `o`|
|---|---|---|
|Activation|tanh|Sigmoid|
|Range|&minus;1 to 1|0 to 1|
|Meaning|What to write|How much to write|
|Can be negative|Yes|No|

Content needs to be able to be negative, because a feature can be present, absent, or actively counter-indicated. A gate cannot be negative, because "write &minus;30% of this" is meaningless.

The candidate is then scaled by the input gate before being added:

<p class="mono-font">c&#7511; = f&#7511; &#8857; c&#7511;&#8331;&#8321; + i&#7511; &#8857; g&#7511;</p>

So the candidate proposes and the input gate decides. Sometimes described as the pair being a writer and a valve, which is a fair reading.

## Why the tanh bound matters

The cell state accumulates across time steps. If the candidate were unbounded &mdash; a linear or ReLU output &mdash; then repeated additions could grow the state without limit.

That growth has two consequences. The output path `tanh(cₜ)` saturates, so its gradient approaches zero and the output gate stops learning. And the numbers themselves can overflow into `inf` over a long sequence.

Bounding the candidate to &plusmn;1 means each step adds at most 1 to any dimension, and the forget gate can subtract. The state can still grow over many steps &mdash; which is why cell values in the tens are possible and worth monitoring &mdash; and it grows linearly rather than explosively.

This is also why <strong>ReLU is not used inside recurrent cells</strong>. It is the default in feed-forward networks and the wrong choice here: an unbounded activation applied repeatedly through a recurrence produces instability that gating cannot contain.

## The two roles, concretely

Take a cell tracking sentiment while reading "the film was not very good".

At "good", the candidate for the sentiment dimension is strongly positive &mdash; that is what the word contributes in isolation. At "not", earlier, a different dimension carried a negation signal, and the state now reflects it.

What the trained cell learns is to use the gates to combine these correctly rather than letting the last strong candidate win. The candidate at "good" may be +0.9 while the input gate for that dimension is low, because the context makes a naive positive reading wrong.

That division of labour &mdash; the candidate reading the current word, the gates reading the context &mdash; is what the four-way structure buys, and it is why a single computation producing both content and strength would be less expressive.

1. <strong>Run the simulation.</strong> Watch the highlighted red route: the candidate is computed alongside the gates, then immediately meets the Input Gate at a $\times$ before it is ever allowed near the conveyor belt.
2. <strong>Slide $z$ to 0.</strong> The proposal is zero, but the gradient bar is at its maximum. Nothing is being written, yet this is the state in which the layer learns fastest.
3. <strong>Push $z$ past $\pm 3$.</strong> The output bar pins to full while the gradient bar empties &mdash; watch both at once. That is saturation, visible in a single glance.
4. <strong>Go negative.</strong> The output bar turns red, showing a proposal that <em>subtracts</em> from memory. No sigmoid gate in this cell can do that; only the candidate carries a sign.

## In one line

The candidate layer is the LSTM's content generator: bounded, signed, and completely powerless on its own. Content and control are deliberately separated &mdash; $\tanh$ proposes, sigmoid disposes. The last piece of the cell decides what the outside world gets to see: the <strong>Output Gate</strong>.

## Where it sits in the computation

All four of an LSTM's transformations take the same input &mdash; the concatenation of the previous hidden state and the current input &mdash; and produce vectors of the same width. So implementations compute them as one matrix multiplication and split the result:

```python
gates = x @ W_ih.T + h @ W_hh.T + b        # one multiply, 4x hidden wide
i, f, g, o = gates.chunk(4, dim=-1)        # split into the four parts

i, f, o = i.sigmoid(), f.sigmoid(), o.sigmoid()
g = g.tanh()                                # only the candidate uses tanh

c = f * c + i * g
h = o * c.tanh()
```

That fusion is why `nn.LSTM` is dramatically faster than a hand-written Python loop: one large matrix multiplication per step rather than four small ones, with cuDNN kernels underneath.

The candidate's weight matrix is the same size as each gate's: `(input + hidden) × hidden`. With 300-dimensional input and 256 hidden units, about 143,000 parameters &mdash; a quarter of the cell's total.

## Failure modes

<strong>Candidate saturated at &plusmn;1.</strong> If the pre-activation is consistently large, tanh is flat and its derivative is near zero, so the candidate's weights stop learning. Scaled inputs and sensible initialisation prevent it; layer normalisation inside the cell fixes it directly.

<strong>Candidate near zero everywhere.</strong> Nothing is ever proposed for storage, so memory never updates usefully. Usually a dead-weights or learning-rate problem.

<strong>Cell state growing without bound.</strong> Forget gate near 1 and input gate near 1 for many steps means candidates accumulate. Check `|c|`: values above about 5 mean the output tanh is saturated.

Monitoring is straightforward with a manual cell:

```python
print(f"candidate: mean {g.mean():.3f} |max| {g.abs().max():.3f}")
print(f"cell state: |max| {c.abs().max():.3f}")
```

A candidate whose absolute maximum is pinned at 1.0 across all dimensions is saturated. Healthy values are spread across the range.

## Questions people ask

<strong>Why tanh rather than sigmoid for the candidate?</strong> Content must be able to be negative. Sigmoid's 0-to-1 range could only ever add.

<strong>Why not ReLU?</strong> It is unbounded, and an unbounded activation added repeatedly through a recurrence destabilises the cell state.

<strong>Is the candidate the same as the new cell state?</strong> No &mdash; it is the <em>proposal</em>. The new cell state is the retained old state plus the gated candidate.

<strong>Can the candidate be ignored entirely?</strong> Yes, when the input gate is near 0 for that dimension. That is the mechanism for "this word is not relevant here".

<strong>Does it have its own weights?</strong> Yes &mdash; one matrix, the same size as each gate's, computed in the same fused multiplication.

<strong>What is `g` called in the literature?</strong> Variously the candidate, the candidate cell state, `c̃ₜ`, or the "new memory content". They all mean this.

## Recap in one screen

- The candidate is what the cell could write to memory: content, not a decision.
- It uses tanh, so it ranges from &minus;1 to 1 and can be negative &mdash; unlike the sigmoid gates.
- The input gate scales it before it is added to the retained cell state.
- The bound keeps the accumulating cell state growing linearly rather than explosively, which is why ReLU is not used here.
- All four transformations are computed as one fused matrix multiplication and split.
