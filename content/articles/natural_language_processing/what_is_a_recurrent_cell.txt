title: What is a Recurrent Cell?: A Practical Guide
intro: A recurrent cell is a small network that runs once per token and passes a summary of everything it has seen to its future self. That loop is what lets a fixed-size model read a sequence of any length.

## The problem with feeding a sentence to a normal network

A feedforward network has a fixed number of inputs. A sentence does not have a fixed number of words. You can pad everything to a maximum length, but then the model has no notion that word 3 comes before word 4 &mdash; each position gets its own independent weights, so “dog bites man” and “man bites dog” are unrelated inputs as far as it is concerned.

A recurrent cell solves both problems with one idea: process <em>one</em> token at a time, and carry a running summary forward.

## The recurrence, written out

At each timestep t the cell takes the current input <span class="mono-font">x<sub>t</sub></span> and the previous hidden state <span class="mono-font">h<sub>t&minus;1</sub></span>, and produces a new hidden state:

h<sub>t</sub> = tanh(W<sub>x</sub>x<sub>t</sub> + W<sub>h</sub>h<sub>t&minus;1</sub> + b)

Three things are worth noticing. The hidden state is the <strong>memory</strong> &mdash; a fixed-size vector holding everything the cell has decided is worth keeping from the sequence so far. The weights <span class="mono-font">W<sub>x</sub></span>, <span class="mono-font">W<sub>h</sub></span> and <span class="mono-font">b</span> are the <strong>same at every timestep</strong>; the cell is one small network applied repeatedly, not a chain of different networks. And because the weights do not depend on position, the same cell handles a sequence of 5 tokens or 500.

That weight sharing is what makes the parameter count independent of sequence length &mdash; and it is exactly the same trick a convolution uses across space.

## The unit that carries state

A recurrent cell is the piece of a recurrent network that runs once per time step. It takes two things &mdash; the current input and its own state from the previous step &mdash; and produces a new state.

<p class="mono-font">h&#7511; = cell(x&#7511;, h&#7511;&#8331;&#8321;)</p>

For the simplest cell:

<p class="mono-font">h&#7511; = tanh(W&#8341;&#8341; h&#7511;&#8331;&#8321; + W&#8339;&#8341; x&#7511; + b)</p>

The state `hₜ` is a fixed-size vector that summarises everything seen so far. Its size is a hyperparameter &mdash; 128, 256, 512 &mdash; and it does not grow with the sequence, which is both the cell's defining strength and its defining limit.

The <strong>same weights are used at every step</strong>. That is parameter sharing along time, and it is what lets one cell handle a sequence of any length with a fixed parameter count. A network with distinct weights per position would need a separate set for every possible length.

## Three cells, in order of sophistication

|Cell|State|Gates|Parameters per layer|
|---|---|---|---|
|Simple RNN|h|None|1 matrix|
|GRU|h|2 (update, reset)|3 matrices|
|LSTM|h and c|3 (forget, input, output)|4 matrices|

<strong>The simple cell</strong> overwrites its state at every step. Whatever it knew is repeatedly transformed, and after fifty steps almost nothing survives. Gradients decay along the same path, so it cannot learn long-range dependencies. It is a teaching device rather than a practical choice.

<strong>The GRU</strong> adds an update gate that interpolates between keeping the old state and replacing it, plus a reset gate controlling how much history the candidate sees. One state, two gates.

<strong>The LSTM</strong> adds a separate cell state updated additively, with three gates deciding what to drop, what to store and what to expose. Two states, three gates.

The pattern across the three is the same insight applied more thoroughly: <strong>give the state an additive path so information and gradients can survive many steps.</strong>

## Why gating changes everything

For the simple cell, the gradient across one step involves the derivative of tanh times the recurrent weight matrix &mdash; a quantity nothing keeps near 1, and usually below it. Over 50 steps the product collapses.

For an LSTM, `∂cₜ/∂cₜ₋₁` is exactly the forget gate. When the network has learned to preserve something, that value is near 1 and the gradient passes back essentially undamped.

That single derivative is the difference between failing at 20 steps and succeeding at 200. And it is structurally the same trick as a residual connection in a deep feed-forward network: an additive path with a derivative of 1.

The practical guidance follows directly: <strong>use an LSTM or GRU, never `nn.RNN`.</strong> The extra cost is small and the difference in what can be learned is large.

## One interface, three implementations

A recurrent cell is any function that takes a state and an input and returns a new state. Writing the RNN, LSTM and GRU cells against that one signature shows what they share and exactly where they differ.

```python-run
import numpy as np

rng = np.random.default_rng(0)
X, H = 3, 4

def sigmoid(z):
    return 1 / (1 + np.exp(-np.clip(z, -30, 30)))

print("the interface, and it is the whole abstraction:")
print("    new_state = cell(input, old_state)")
print()
print("everything else -- how many gates, whether there is a separate")
print("memory -- is an implementation detail behind that signature. which")
print("is why frameworks let you swap RNN for LSTM by changing one word.")
print()

# --- the three cells, same signature
Wx = rng.normal(0, 0.5, (X, H)); Wh = rng.normal(0, 0.5, (H, H))

def rnn_cell(x, state):
    h = state
    return np.tanh(x @ Wx + h @ Wh)

Wg = {k: rng.normal(0, 0.5, (X + H, H)) for k in "fiog"}
bg = {k: (np.ones(H) if k == "f" else np.zeros(H)) for k in "fiog"}

def lstm_cell(x, state):
    h, c = state
    z = np.concatenate([x, h])
    f = sigmoid(z @ Wg["f"] + bg["f"])
    i = sigmoid(z @ Wg["i"] + bg["i"])
    g = np.tanh(z @ Wg["g"] + bg["g"])
    o = sigmoid(z @ Wg["o"] + bg["o"])
    c_new = f * c + i * g
    return o * np.tanh(c_new), c_new

Wz = rng.normal(0, 0.5, (X + H, H))
Wr = rng.normal(0, 0.5, (X + H, H))
Wc = rng.normal(0, 0.5, (X + H, H))

def gru_cell(x, state):
    h = state
    zz = np.concatenate([x, h])
    z = sigmoid(zz @ Wz)
    r = sigmoid(zz @ Wr)
    cand = np.tanh(np.concatenate([x, r * h]) @ Wc)
    return (1 - z) * h + z * cand

print("%14s %12s %10s %14s"
      % ("cell", "state", "gates", "parameters"))
print("%14s %12s %10d %14d" % ("RNN", "h", 0, Wx.size + Wh.size))
print("%14s %12s %10d %14d" % ("LSTM", "h and c", 4, 4 * (X + H) * H))
print("%14s %12s %10d %14d" % ("GRU", "h", 3, 3 * (X + H) * H))
print()

print("run all three over the same 5 inputs. only the LSTM's state is a")
print("pair; the loop that drives them is otherwise identical:")
seq = rng.normal(0, 1.0, (5, X))
print("%8s %30s %30s %30s" % ("step", "RNN h[0:2]", "LSTM h[0:2]", "GRU h[0:2]"))
h_r = np.zeros(H)
s_l = (np.zeros(H), np.zeros(H))
h_g = np.zeros(H)
for t, x in enumerate(seq):
    h_r = rnn_cell(x, h_r)
    s_l = lstm_cell(x, s_l)
    h_g = gru_cell(x, h_g)
    print("%8d %30s %30s %30s"
          % (t, np.round(h_r[:2], 4), np.round(s_l[0][:2], 4), np.round(h_g[:2], 4)))
print()

print("THE LOOP IS THE SAME CODE for all three:")
print("    state = initial_state")
print("    for x in sequence:")
print("        state = cell(x, state)")
print("that is what makes a cell a useful abstraction, and it is why")
print("'RNN' loosely means both the cell and the loop around it.")
print()

print("WHAT THE STATE HAS TO DO. it is a fixed-size summary of everything")
print("seen so far, and everything the model will ever know about the past")
print("has to fit in it:")
for h_size in (4, 128, 1024):
    print("   hidden size %5d -> %5d numbers carry the entire history"
          % (h_size, h_size))
print("   that bound does not grow with the sequence. a 10-token sequence")
print("   and a 10,000-token one are summarised into the same %d numbers."
      % H)
print()
print("   here is that limit biting. feed a long sequence and ask how much")
print("   of step 0 is still recoverable from the state:")
for L in (2, 5, 10, 25, 50):
    a = rng.normal(0, 1.0, (L, X))
    b = a.copy(); b[0] = rng.normal(0, 1.0, X)
    ha, hb = np.zeros(H), np.zeros(H)
    for xa, xb in zip(a, b):
        ha, hb = rnn_cell(xa, ha), rnn_cell(xb, hb)
    print("      length %3d: changing step 0 moves the final state by %.6f"
          % (L, np.linalg.norm(ha - hb)))
print("   the LSTM and GRU exist to make that number fall more slowly. they")
print("   do not remove the bound -- the state is still fixed size.")
print()

print("STACKING. a cell's output is a valid input to another cell, so you")
print("can layer them:")
Wx2 = rng.normal(0, 0.5, (H, H))
def rnn_cell2(x, h):
    return np.tanh(x @ Wx2 + h @ Wh)
h1, h2 = np.zeros(H), np.zeros(H)
print("%8s %26s %26s" % ("step", "layer 1 h[0:2]", "layer 2 h[0:2]"))
for t, x in enumerate(seq):
    h1 = rnn_cell(x, h1)
    h2 = rnn_cell2(h1, h2)
    print("%8d %26s %26s" % (t, np.round(h1[:2], 4), np.round(h2[:2], 4)))
print("   layer 2's input at step t is layer 1's output at step t. depth in")
print("   this direction is separate from depth through time, and both make")
print("   the gradient path longer.")
```

## Things to try

1. <strong>Feed one token at a time.</strong> Press <strong>Feed Next Token</strong> and watch the hidden state change. Each press mixes new input into the existing memory rather than replacing it.
2. <strong>Watch old information fade.</strong> Keep pressing and follow the contribution of the first token. It does not vanish at once; it is progressively diluted as later tokens are folded in. That gradual decay is exactly why plain recurrent cells struggle with long-range dependencies.
3. <strong>Reset and compare.</strong> Press <strong>Reset Memory</strong> and feed the same tokens in a different order. The final state differs &mdash; unlike a bag-of-words model, order genuinely changes the representation.
4. <strong>Run it continuously.</strong> Press <strong>Auto Run</strong> and note that no new parameters appear as the sequence lengthens. One cell, applied repeatedly.

## Why the simple cell is not enough

The hidden state is overwritten at every step. Information from token 1 survives to token 50 only by passing through 49 successive multiplications by <span class="mono-font">W<sub>h</sub></span> and 49 tanh nonlinearities.

That is the vanishing gradient problem in its original setting. The gradient reaching timestep 1 is a product of 49 terms, and since tanh’s derivative is at most 1 and typically well below it, the product decays geometrically. In practice a simple recurrent cell reliably remembers about 10 timesteps and loses anything much further back.

The fix is to give the cell an explicit, <em>additive</em> memory channel with learned gates controlling what enters and leaves it &mdash; which is precisely what LSTM and GRU do.

## Common mistakes

- <strong>Expecting long-range memory.</strong> A vanilla recurrent cell does not have it. If dependencies span more than a handful of tokens, use an LSTM, a GRU, or attention.
- <strong>Exploding gradients.</strong> If <span class="mono-font">W<sub>h</sub></span> has eigenvalues above 1 the repeated multiplication amplifies instead of decaying, and the loss becomes NaN. Gradient clipping is standard practice for recurrent models for exactly this reason.
- <strong>Confusing the hidden state with the output.</strong> They coincide in the simplest cell, but in an LSTM the cell state and hidden state are different objects, and mixing them up is a common implementation bug.
- <strong>Forgetting to reset state between sequences.</strong> Carrying the hidden state from one unrelated example into the next leaks information and quietly corrupts training.

## In one line

A recurrent cell applies one small network at every timestep, combining the current token with a hidden state that summarises everything before it, using the same weights throughout. That gives a fixed-size model the ability to read arbitrary-length sequences and to be sensitive to order. Its weakness is that memory is overwritten multiplicatively at each step, so information decays after roughly ten timesteps &mdash; the limitation that gated cells were invented to remove.

## The cell versus the layer

Frameworks distinguish two levels, and knowing which you want saves confusion.

<strong>The cell</strong> processes one time step. `nn.LSTMCell` takes `(x, (h, c))` and returns the new states. You write the loop.

<strong>The layer</strong> processes a whole sequence. `nn.LSTM` takes a `(batch, seq, features)` tensor and runs the loop internally, in optimised C or cuDNN.

```python
# the layer - what you almost always want
lstm = nn.LSTM(300, 256, batch_first=True)
out, (h, c) = lstm(x)                        # x: (batch, seq, 300)

# the cell - when you need per-step control
cell = nn.LSTMCell(300, 256)
h, c = torch.zeros(b, 256), torch.zeros(b, 256)
for t in range(seq_len):
    h, c = cell(x[:, t], (h, c))
```

The layer is dramatically faster &mdash; often ten times or more &mdash; because it fuses the four gate matrices into one multiplication and uses hardware-optimised kernels. Write the loop only when you need something the layer cannot express: inspecting gates, applying custom logic between steps, scheduled sampling during training.

## Two states, two purposes

For an LSTM specifically, the distinction between the states is worth restating because it is the design's whole point.

The <strong>cell state</strong> is private long-term memory. It is unbounded, updated additively, and passed only to the next time step.

The <strong>hidden state</strong> is the working output. It is bounded by tanh, filtered by the output gate, and passed to three places: the next layer, the prediction head, and the next step's gate computations.

That separation lets a cell hold information quietly without reporting it. A GRU, having only a hidden state, cannot make the distinction &mdash; whatever it remembers is what it outputs.

## Where recurrent cells still fit

Transformers displaced them for large-scale language work. The cases where a recurrent cell remains the better engineering choice are specific and real:

- <strong>Streaming with bounded memory.</strong> One fixed-size state regardless of how much has been processed, where a transformer's KV cache grows with every token.
- <strong>On-device inference.</strong> Small, fast, no attention kernels required.
- <strong>Small datasets.</strong> The inductive bias helps where a transformer trained from scratch overfits.
- <strong>Classical time series.</strong> Numeric sequences of moderate length, where windowing plus a GRU is a strong baseline.
- <strong>Inside larger systems</strong>, as state trackers or encoders.

State-space models such as Mamba are worth noting: they revisit recurrence with linear scaling in sequence length and are competitive with transformers on long sequences, which suggests the idea is not finished.

## Questions people ask

<strong>What is the difference between a cell and a layer?</strong> The cell handles one step; the layer runs the loop over a whole sequence and is much faster.

<strong>Should I ever use `nn.RNN`?</strong> Only to demonstrate the problem it has. Use LSTM or GRU.

<strong>How big should the hidden state be?</strong> 128&ndash;512 typically. Larger means more memory capacity and more parameters.

<strong>Can I stack cells?</strong> Yes &mdash; each layer's outputs are the next layer's inputs. Two layers is the practical limit.

<strong>Does the cell see the whole sequence?</strong> Not at once. It sees one element at a time, carrying a summary of the rest.

<strong>Why can it not be parallelised?</strong> Step t needs `hₜ₋₁`, so the steps are strictly ordered. This is the structural reason transformers won at scale.

## Recap in one screen

- A recurrent cell maps the current input and the previous state to a new state, using the same weights every step.
- The state is a fixed-size summary that does not grow with the sequence.
- A simple cell overwrites its state and cannot learn long range; gating adds an additive path that preserves both information and gradients.
- Use the layer (`nn.LSTM`) rather than the cell unless you need per-step control.
- Still the right tool for streaming, on-device and small-data sequence work.
