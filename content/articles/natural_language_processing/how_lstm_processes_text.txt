intro: Discover how Long Short-Term Memory networks use a dual-state architecture to overcome the limitations of standard RNNs.

## The Vanishing Gradient Problem

Standard Recurrent Neural Networks (RNNs) pass a single "hidden state" forward through time. While great in theory, standard RNNs suffer from the <strong>vanishing gradient problem</strong>. During training, as the network looks back across many time steps (long sentences), the signals necessary to update the weights become microscopically small.

The result? A standard RNN essentially develops "amnesia." By the time it reads the 20th word in a sentence, it has mostly forgotten the 1st word. This makes it terrible at understanding long-range dependencies in text.

## The Dual State Solution: Cell and Hidden States

LSTMs solve this amnesia by introducing a more complex internal structure that passes <strong>two</strong> distinct states forward at every time step (as seen in the visualization):

1. <strong style="color: var(--cell-state)">The Cell State ($C_t$):</strong> Often compared to a conveyor belt. It runs straight down the entire chain, with only minor linear interactions. It's very easy for information to flow along it unchanged. This is the LSTM's <em>long-term memory</em>.
2. <strong style="color: var(--accent-primary)">The Hidden State ($H_t$):</strong> This is the LSTM's <em>short-term memory</em> or its "focus" for the current time step. It is derived from the Cell State and is what gets passed up as the output ($Y_t$) for that specific step.

## The Four Gates (Why so many parameters?)

To control what gets added to or removed from the Cell State conveyor belt, the LSTM uses neural network layers called <strong>gates</strong>. Inside every single LSTM cell block shown in the visual, there are actually four separate fully-connected layers operating simultaneously:

- <strong>Forget Gate ($f_t$):</strong> Decides what information to throw away from the past cell state.
- <strong>Input Gate ($i_t$):</strong> Decides which new values to update in the cell state.
- <strong>Cell Candidate ($\tilde{C}_t$):</strong> Creates a vector of new candidate values that could be added to the state.
- <strong>Output Gate ($o_t$):</strong> Decides what parts of the cell state to output as the new Hidden State ($H_t$).

Because there are 4 independent layers doing calculations on the inputs ($X_t$) and previous hidden state ($H_{t-1}$), <strong>an LSTM has roughly 4 times as many parameters as a standard RNN</strong> of the same size. ## Following a sentence through the cell

Take "the film was not very good" and watch what an LSTM does with it, one token at a time.

At each step the cell receives the current word's embedding and its own two states from the previous step, computes four things from them, and produces new states.

|Step|Word|What the gates plausibly do|
|---|---|---|
|1|the|Little to store; state stays near its initial value|
|2|film|Input gate opens on subject dimensions; "film" is the topic|
|3|was|Tense recorded; subject retained (forget gate near 1)|
|4|not|A negation dimension is set; this is the important step|
|5|very|Intensifier stored; negation retained|
|6|good|Candidate is strongly positive &mdash; and the negation dimension is still set|

The interesting step is 4. "Not" carries no sentiment on its own; its job is to invert what follows. A trained cell stores that in some dimension and keeps it (forget gate near 1) so that at step 6 the positive candidate for "good" is combined with an active negation signal.

That is what a bag-of-words model cannot do: to it, this sentence contains "good" and is therefore positive.

## Four computations per step

<p class="mono-font">f&#7511; = &sigma;(W&#7584;[h&#7511;&#8331;&#8321;, x&#7511;])&nbsp;&nbsp;&nbsp;i&#7511; = &sigma;(W&#7522;[h&#7511;&#8331;&#8321;, x&#7511;])</p>
<p class="mono-font">g&#7511; = tanh(W&#7509;[h&#7511;&#8331;&#8321;, x&#7511;])&nbsp;&nbsp;o&#7511; = &sigma;(W&#8338;[h&#7511;&#8331;&#8321;, x&#7511;])</p>
<p class="mono-font">c&#7511; = f&#7511; &#8857; c&#7511;&#8331;&#8321; + i&#7511; &#8857; g&#7511;&nbsp;&nbsp;&nbsp;&nbsp;h&#7511; = o&#7511; &#8857; tanh(c&#7511;)</p>

All four transformations take the same input and are computed as a single fused matrix multiplication in practice, then split.

The two states do different jobs. The <strong>cell state</strong> is long-term memory, updated additively so information can persist for many steps. The <strong>hidden state</strong> is the working output &mdash; passed to the next layer, to the prediction head, and to the next step's gate computations.

## What comes out, and what you use

For a 20-word sentence, a single-layer LSTM with 256 hidden units produces a 20&times;256 tensor: one hidden state per word.

Which part you use depends on the task:

<strong>Classification.</strong> The final hidden state summarises the whole sentence &mdash; or better, pool over all states with a mean or max, since the final state is biased towards the end of the input.

<strong>Tagging</strong> (named entities, part of speech). Use every hidden state, one prediction per word.

<strong>Generation.</strong> Feed each hidden state to an output layer over the vocabulary, and the predicted token becomes the next step's input.

<strong>As an encoder.</strong> The final state (or all states, with attention) is passed to a decoder.

```python
lstm = nn.LSTM(300, 256, batch_first=True)
out, (h, c) = lstm(embedded)      # out: (batch, seq, 256)

pooled = out.mean(dim=1)          # better than h[-1] for classification
```

- <strong>Check Many-to-One vs Many-to-Many:</strong> In Many-to-One (like Sentiment Analysis), only the final $H_t$ is pushed up to the classifier to make the final $Y$ decision. In Many-to-Many (like Language Translation or Text Generation), an output is generated at every step.

## Details that matter with real text

<strong>Pack variable-length sequences.</strong> Sentences in a batch have different lengths, so short ones are padded. Without `pack_padded_sequence`, the LSTM processes the padding, and the final hidden state describes the padding rather than the last real word.

```python
from torch.nn.utils.rnn import pack_padded_sequence, pad_packed_sequence

packed = pack_padded_sequence(embedded, lengths, batch_first=True,
                              enforce_sorted=False)
out, (h, c) = lstm(packed)
out, _ = pad_packed_sequence(out, batch_first=True)
```

<strong>Consider bidirectionality.</strong> For classification and tagging, where the whole sentence is available, running one LSTM forward and another backward and concatenating gives each position both left and right context. It typically helps materially. Never use it for generation or streaming, where the future does not exist.

<strong>Clip gradients.</strong> `clip_grad_norm_` with a threshold of 1&ndash;5. Recurrent models are the classic case for it, and omitting it eventually produces a `NaN` run.

<strong>Keep it shallow.</strong> One or two layers. Deep recurrent stacks are hard to train and rarely repay the cost.

## Where it beats and loses to a transformer

<strong>An LSTM wins</strong> when memory must be bounded &mdash; streaming inference carries one fixed-size state regardless of how much text has passed, while a transformer's KV cache grows with every token. It also wins on small datasets, where its inductive bias helps and a transformer trained from scratch overfits, and on-device, where it is small and needs no attention kernels.

<strong>A transformer wins</strong> on long-range dependencies (any two positions are one step apart), on parallelism (all positions computed at once, so training scales), and consequently on anything requiring scale.

|Task|Reasonable choice|
|---|---|
|Sentiment on a few thousand labelled reviews|LSTM, or a fine-tuned small transformer|
|Streaming transcription with bounded memory|LSTM|
|Document-level question answering|Transformer|
|On-device text classification|LSTM or a distilled transformer|
|Anything generative at quality|Transformer|

## One sentence, one token at a time, gates shown

An LSTM reading a real sentence, with all four gates printed at every token and the cell state tracked alongside. The interesting part is which tokens make the gates move.

```python-run
import numpy as np

rng = np.random.default_rng(0)

vocab = ["the", "film", "was", "not", "very", "good", ".", "but", "acting",
         "excellent"]
idx = {w: i for i, w in enumerate(vocab)}
V, D, H = len(vocab), 6, 4
E = rng.normal(0, 0.6, (V, D))

def sigmoid(z):
    return 1 / (1 + np.exp(-np.clip(z, -30, 30)))

Wf = rng.normal(0, 0.5, (D + H, H)); bf = np.ones(H)
Wi = rng.normal(0, 0.5, (D + H, H)); bi = np.zeros(H)
Wc = rng.normal(0, 0.5, (D + H, H)); bc = np.zeros(H)
Wo = rng.normal(0, 0.5, (D + H, H)); bo = np.zeros(H)

def step(x, h, c):
    z = np.concatenate([x, h])
    f = sigmoid(z @ Wf + bf)
    i = sigmoid(z @ Wi + bi)
    g = np.tanh(z @ Wc + bc)
    o = sigmoid(z @ Wo + bo)
    c_new = f * c + i * g
    return o * np.tanh(c_new), c_new, (f, i, g, o)

sent = "the film was not very good . but acting excellent".split()
print("the pipeline before the LSTM sees anything:")
print("   text   : %r" % " ".join(sent))
print("   ids    : %s" % [idx[w] for w in sent])
print("   vectors: %d rows of %d numbers" % (len(sent), D))
print()

h, c = np.zeros(H), np.zeros(H)
print("then one step per token. these are unit 0's gates:")
print("%10s %9s %9s %11s %9s %12s %11s"
      % ("token", "forget", "input", "candidate", "output", "cell c[0]", "h[0]"))
for w in sent:
    h, c, (f, i, g, o) = step(E[idx[w]], h, c)
    print("%10s %9.4f %9.4f %11.4f %9.4f %12.4f %11.4f"
          % (w, f[0], i[0], g[0], o[0], c[0], h[0]))
print()
print("read the forget column: it stays high, so the cell state carries")
print("across the whole sentence rather than resetting at each token. that")
print("is the default behaviour the bias of 1.0 sets up.")
print()

print("WHAT THE STATE IS DOING. track the magnitude of the whole cell:")
h, c = np.zeros(H), np.zeros(H)
mags = []
for w in sent:
    h, c, _ = step(E[idx[w]], h, c)
    mags.append(np.linalg.norm(c))
for w, m in zip(sent, mags):
    print("   %-10s |c| = %.4f  %s" % (w, m, "#" * int(m * 12)))
print("   it drifts upward without ever resetting -- rising and dipping with")
print("   each token, but never returning to where it started. an untrained")
print("   cell has no reason to flush, so the state wanders until the tanh")
print("   and the gates balance it. a trained one learns when to clear.")
print()

print("THE SENTENCE-LEVEL PREDICTION comes from the FINAL state only:")
Wy = rng.normal(0, 0.5, (H, 2))
print("   final h = %s" % np.round(h, 4))
print("   logits  = %s -> class %d" % (np.round(h @ Wy, 4), int((h @ Wy).argmax())))
print("   everything the model concluded about %d tokens is in those %d"
      % (len(sent), H))
print("   numbers. that is the many-to-one shape.")
print()

print("AND HERE IS WHY 'not' IS HARD. compare two sentences that differ by")
print("one word early on:")
pairs = ("the film was not very good .".split(),
         "the film was very very good .".split())
finals = []
for s in pairs:
    hh, cc = np.zeros(H), np.zeros(H)
    for w in s:
        hh, cc, _ = step(E[idx[w]], hh, cc)
    finals.append(hh)
    print("   %-34s final h = %s" % (" ".join(s), np.round(hh, 4)))
print("   distance between them: %.4f" % np.linalg.norm(finals[0] - finals[1]))
print("   the difference survives to the end here, three tokens later. push")
print("   the 'not' further back and it fades:")
for gap in (1, 4, 10, 25):
    base = ["the", "film", "was", "not"] + ["very"] * gap + ["good", "."]
    alt = ["the", "film", "was", "very"] + ["very"] * gap + ["good", "."]
    outs = []
    for s in (base, alt):
        hh, cc = np.zeros(H), np.zeros(H)
        for w in s:
            hh, cc, _ = step(E[idx[w]], hh, cc)
        outs.append(hh)
    print("      %2d token%s after 'not': difference %.6f"
          % (gap, "" if gap == 1 else "s", np.linalg.norm(outs[0] - outs[1])))
print("   an LSTM holds it longer than a plain RNN would, and not forever.")
print("   that is the honest limit, and it is what attention removed by")
print("   giving 'good' a direct link back to 'not' regardless of distance.")
```

## Questions people ask

<strong>Does an LSTM read left to right?</strong> Yes, unless bidirectional, in which case a second pass reads right to left and the outputs are concatenated.

<strong>Should I use the last hidden state or pool?</strong> Pool, for classification &mdash; the last state over-weights the end of the sequence.

<strong>How long a text can it handle?</strong> Hundreds of tokens reliably. Beyond that, information from the start is largely gone.

<strong>Do I need embeddings before the LSTM?</strong> Yes &mdash; token ids must become vectors first, either from a learned embedding layer or pretrained vectors.

<strong>Why is my final hidden state meaningless?</strong> Almost certainly unpacked padding: the state describes the pad tokens.

<strong>One layer or two?</strong> Two at most for most tasks; the second sometimes helps and often does not.

## Recap in one screen

- At each token the cell computes four transformations, updates the cell state additively, and emits a gated hidden state.
- The cell state carries long-term memory; the hidden state is the working output at each step.
- "Not ... good" is the canonical demonstration: the negation is stored and applied several steps later.
- Pool over hidden states for classification; use all of them for tagging.
- Pack variable-length batches, clip gradients, keep it shallow, and consider bidirectionality when the whole input is available.
