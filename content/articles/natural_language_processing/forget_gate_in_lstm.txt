title: The Forget Gate: Deciding What to Erase
intro: Before an LSTM writes anything new, it decides what of the past is still worth keeping. That single decision is what makes long-term memory possible.

## What the Gate Actually Is

The Forget Gate is a small neural layer with a <strong>sigmoid</strong> output. It reads the merged vector $[H_{t-1}, X_t]$ and produces one number between 0 and 1 <em>for every slot in the cell state</em>:

$$f_t = \sigma(W_f \cdot [H_{t-1}, X_t] + b_f)$$

Those numbers are then multiplied element-by-element into the old memory: $f_t \odot C_{t-1}$. A slot that receives <strong>1</strong> is copied forward perfectly. A slot that receives <strong>0</strong> is erased. Everything in between is partial fading.

## It Is a Dimmer, Not a Switch

The word "gate" suggests open or closed, but the sigmoid makes it a <strong>dimmer per dimension</strong>. In a real trained LSTM the forget vector might look like $[0.98, 0.03, 0.71, 0.99, \dots]$ &mdash; the cell holds on to some facts with near-perfect fidelity while dumping others in the same time step.

This is the crucial difference from a plain RNN. An RNN squashes its <em>entire</em> state through $\tanh$ at every step, so everything decays together. The LSTM decides <em>slot by slot</em>, so a subject noun can survive twenty words while a comma is discarded immediately.

## Forgetting Compounds — and That Is the Whole Story

Memory does not decay once, it decays <em>repeatedly</em>. If the gate emits roughly the same value $f$ each step, the fraction of the original signal still present after $n$ steps is:

$$\text{survival} = f^{\,n}$$

Because this is exponential, small differences in $f$ produce enormous differences in reach. Play with the slider in the <strong>Forget Gate Lab</strong> and watch the two survival bars:

- $f = 0.5$ &mdash; after only 5 steps just <strong>3%</strong> remains. This is effectively short-term memory.
- $f = 0.9$ &mdash; after 20 steps about <strong>12%</strong> survives. Usable long-range context.
- $f = 1.0$ &mdash; the memory is <strong>perfectly preserved</strong>, no matter how many steps pass.

That last case is the reason LSTMs defeat the vanishing gradient. When $f_t \approx 1$, the update becomes $C_t \approx C_{t-1} + \text{something}$ &mdash; pure addition. Gradients flowing backwards along this path are multiplied by $f_t \approx 1$ instead of being squashed, so they survive the trip.

## A Practitioner's Trick: Positive Forget Bias

At initialisation the weights are near zero, so $f_t \approx \sigma(0) = 0.5$ &mdash; the network starts out forgetting half its memory every single step and struggles to learn anything long-range. The standard fix is to initialise the forget-gate bias $b_f$ to <strong>+1 or +2</strong>, which pushes the gate to roughly 0.73&ndash;0.88 from the start. The cell begins life inclined to remember, and learns what to discard from there.

## Deciding what to drop

The forget gate is the first thing an LSTM cell computes, and it answers one question: <em>of everything currently in memory, how much of each part should survive this step?</em>

<p class="mono-font">f&#7511; = &sigma;(W&#7584; &middot; [h&#7511;&#8331;&#8321;, x&#7511;] + b&#7584;)</p>

It takes the previous hidden state and the current input, produces a vector the same width as the cell state, and squashes every element through a sigmoid to between 0 and 1. Then:

<p class="mono-font">c&#7511; = f&#7511; &#8857; c&#7511;&#8331;&#8321; + (new information)</p>

The multiplication is <strong>elementwise</strong>, which is the crucial detail. Each dimension of the cell state is scaled independently, so the gate can keep one dimension entirely (a coefficient of 1) while erasing another (a coefficient of 0) in the same step.

|Gate value|Effect on that dimension|
|---|---|
|1.0|Keep completely|
|0.7|Keep most of it, decay slowly|
|0.3|Mostly discard|
|0.0|Erase entirely|

## What it learns to do

Concretely, in a language model, the forget gate learns to clear state at boundaries.

Suppose a dimension of the cell state tracks the grammatical number of the current subject, so that the verb can agree with it. When a new sentence begins, that information is no longer relevant &mdash; it would actively mislead. A trained forget gate learns to output near 0 for that dimension when it sees a full stop, and near 1 while the sentence continues.

Other observed behaviours: clearing after a closing bracket, resetting on a topic shift, and dropping a tracked entity once a new one is introduced.

The gate does not "know" any of this. It is a learned function of the previous state and the current input, and these behaviours are what minimising the loss produced.

## Why it is the gradient's protector

The forget gate is also the reason LSTMs handle long sequences, and the mechanism is a single derivative.

Differentiating the cell update with respect to the previous cell state gives:

<p class="mono-font">&part;c&#7511; / &part;c&#7511;&#8331;&#8321; = f&#7511;</p>

That is it &mdash; the forget gate itself. So the gradient flowing back through k steps is multiplied by the product of k forget-gate values.

If the network has learned to keep a piece of information, those values are near 1, and the product stays near 1 across many steps. The gradient reaches back essentially undamped, and the network can learn that something 100 steps ago mattered.

Compare a plain RNN, where the per-step factor is the derivative of a tanh times a weight matrix &mdash; a quantity nothing constrains to be near 1, and which is usually below it. That is the whole difference between failing at 20 steps and succeeding at 200.

There is a practical corollary: <strong>the forget gate bias is often initialised to 1</strong> (rather than 0), so the gate starts open and information is preserved by default. The network then learns when to close it. Initialising it at 0 means the gate starts half-closed, memory decays from the first step, and training is measurably slower.

## The gate that decides what to throw away

The forget gate multiplies the old memory by a number between 0 and 1. That single multiplication is what makes an LSTM's gradient survive, and what makes it possible to clear the memory on purpose.

```python-run
import numpy as np

def sigmoid(z):
    return 1 / (1 + np.exp(-np.clip(z, -30, 30)))

print("the gate is one sigmoid layer over [input, previous hidden]:")
print("    f = sigmoid(Wf @ [x, h] + bf)")
print("    c = f * c_old + (new stuff)")
print()
print("sigmoid output, and what each value does to the memory:")
for z in (-6, -3, -1, 0, 1, 3, 6):
    f = sigmoid(z)
    kept = "%.4f" % f
    print("   pre-activation %+3d -> f = %s -> keeps %5.1f%% of the old memory"
          % (z, kept, 100 * f))
print("   it never reaches exactly 0 or 1, which matters: a hard 0 would")
print("   also zero the gradient, and a hard 1 would let the state grow")
print("   without bound.")
print()

print("ONE ELEMENT of memory, over 30 steps, at four fixed gate values:")
print("%8s %12s %12s %12s %12s" % ("step", "f=0.99", "f=0.90", "f=0.70", "f=0.50"))
states = {f: 1.0 for f in (0.99, 0.90, 0.70, 0.50)}
for t in range(1, 31):
    for f in states:
        states[f] *= f
    if t in (1, 3, 5, 10, 20, 30):
        print("%8d %12.6f %12.6f %12.6f %12.6f"
              % (t, states[0.99], states[0.90], states[0.70], states[0.50]))
print()
print("a memory's half-life is set entirely by its forget gate:")
for f in (0.99, 0.95, 0.90, 0.70, 0.50):
    print("   f = %.2f -> half-life %6.1f steps" % (f, np.log(0.5) / np.log(f)))
print("   that is the knob. a unit with f near 1 is a register; a unit with")
print("   f near 0.5 is a short-term buffer. a trained network has both.")
print()

print("WHY THE GRADIENT SURVIVES. the derivative of c_t with respect to")
print("c_(t-1) is just f. so across k steps it is the PRODUCT of the gates:")
print("%10s %16s %16s %16s" % ("steps back", "f=0.99", "f=0.90", "plain RNN"))
for k in (10, 50, 100, 500):
    rnn = 0.7 ** k          # a typical RNN Jacobian norm below 1
    print("%10d %16.3e %16.3e %16.3e" % (k, 0.99 ** k, 0.90 ** k, rnn))
print("   at 100 steps a gate of 0.99 still passes 37 percent of the")
print("   gradient. an RNN has passed 3e-16, which is nothing.")
print()
print("   and note there is no weight matrix in that product. a plain RNN")
print("   multiplies by W at every step, so the gradient is shaped by")
print("   eigenvalues the model does not directly control. here it is")
print("   multiplied by a number the model chooses, per unit, per timestep.")
print()

print("CLEARING ON PURPOSE. the useful half of the gate is that it can go")
print("low deliberately. a sentence boundary is the classic example:")
tokens = ["the", "cat", "sat", ".", "a", "dog", "ran"]
c = 1.0
print("%8s %10s %14s %s" % ("token", "f", "memory after", ""))
for tok in tokens:
    f = 0.05 if tok == "." else 0.95      # a learned gate would do this itself
    c = f * c + (0.3 if tok != "." else 0.0)
    print("%8s %10.2f %14.4f %s"
          % (tok, f, c, "<- flushed" if tok == "." else ""))
print("   nothing programmed that rule. a trained gate learns to drop when")
print("   the context it was holding stops being relevant, and to hold when")
print("   it does not.")
print()

print("the bias is initialised to 1 for a specific reason:")
for b in (0.0, 1.0, 2.0):
    print("   bf = %.1f -> gate starts at %.4f, and %.1f%% of the memory"
          % (b, sigmoid(b), 100 * sigmoid(b) ** 10))
    print("            survives 10 steps before any training happens")
print("   starting the gate shut means starting with no gradient path")
print("   through time, so the model cannot learn that long dependencies")
print("   exist. starting it open gives training something to work with.")
print()
print("a GRU merges this gate with the input gate into one: whatever it")
print("forgets, it replaces by exactly that much. that is one fewer thing")
print("to learn and one fewer degree of freedom, and in practice the two")
print("architectures perform very similarly.")
```

## In one line

The Forget Gate is the only component that can <em>remove</em> information from an LSTM's long-term memory, and it does so multiplicatively and permanently. Keeping it near 1 turns the cell state into a protected highway across time; letting it drift toward 0 collapses the LSTM back into a forgetful RNN. Next, see how new information gets written in: the <strong>Input Gate</strong>.

## The three gates together

|Gate|Activation|Question|Applied to|
|---|---|---|---|
|Forget|Sigmoid|What should I drop?|The old cell state|
|Input|Sigmoid|What new information is worth storing?|The candidate|
|Output|Sigmoid|What should I expose now?|tanh of the cell state|

All three use a sigmoid, because a gate must be a fraction between 0 and 1. The <em>content</em> they control &mdash; the candidate memory &mdash; uses tanh, because content should be able to be negative.

Note that forget and input are separate gates in an LSTM, which means the cell can keep everything <em>and</em> add new information at full strength in the same step. A GRU merges them into one update gate with coefficients `z` and `1 − z`, so keeping more necessarily means adding less. That is the expressiveness the GRU trades away for a quarter fewer parameters.

## Inspecting a trained gate

Forget-gate activations are unusually interpretable for a neural network internal, and they are worth looking at when debugging a sequence model.

```python
# PyTorch's fused LSTM does not expose gates; a manual cell does
class Cell(nn.Module):
    def forward(self, x, state):
        h, c = state
        gates = self.W(torch.cat([h, x], dim=-1))
        f, i, g, o = gates.chunk(4, dim=-1)
        f, i, o = f.sigmoid(), i.sigmoid(), o.sigmoid()
        c = f * c + i * g.tanh()
        h = o * c.tanh()
        return h, (h, c), f          # return f to inspect it
```

What to look for:

<strong>Forget values stuck near 0</strong> across the whole sequence mean memory is being wiped every step, and the cell is behaving like a plain feed-forward layer. Check the bias initialisation.

<strong>Forget values stuck near 1</strong> mean nothing is ever cleared, so the state accumulates without bound and old information crowds out new.

<strong>Sharp drops at sentence or clause boundaries</strong> are the healthy pattern &mdash; the gate has learned where context resets.

## Questions people ask

<strong>Why is it called "forget" when 1 means keep?</strong> The value is the <em>retention</em> coefficient. The name refers to the gate's purpose, not to its numeric direction &mdash; a genuine source of confusion.

<strong>Can it forget completely?</strong> A sigmoid never reaches exactly 0, so it asymptotes rather than erasing outright. In practice values of 0.01 are effectively erasure.

<strong>Why initialise the bias to 1?</strong> So the gate starts open and memory is preserved by default, which trains faster and better than starting half-closed.

<strong>Does the forget gate cause vanishing gradients?</strong> It is the reason they are <em>avoided</em> &mdash; when it is near 1, the gradient passes back undamped. Consistently small values would cause decay, which is what the bias initialisation guards against.

<strong>Is it shared across dimensions?</strong> No &mdash; it produces one value per cell-state dimension, so each can be managed independently.

<strong>Do GRUs have a forget gate?</strong> Not separately. Its update gate does the job of both forget and input, with coupled coefficients.

## Recap in one screen

- The forget gate outputs one retention coefficient per cell-state dimension, between 0 and 1.
- It multiplies the old cell state elementwise, so each dimension is kept or cleared independently.
- Trained gates learn to clear state at sentence, clause and topic boundaries.
- `∂cₜ/∂cₜ₋₁` is exactly the forget gate &mdash; near 1 means the gradient survives many steps.
- Initialise its bias to 1 so memory is preserved by default and the network learns when to clear.
