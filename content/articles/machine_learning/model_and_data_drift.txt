title: Model and Data Drift
intro: Drift is a change in inputs, outcomes, or the relationship between them after deployment. Monitoring helps find changes that may affect model performance, but a distribution shift alone does not prove the model has degraded.

## Three kinds of change

Drift is a change in the data a deployed model receives, the outcomes it predicts, or the relationship between them. Monitoring can reveal changes that deserve investigation, but a shift alone does not prove model performance has fallen.

- **Covariate shift:** the input distribution (P(X)) changes while the relationship between inputs and outcomes is assumed stable. For example, a customer base may become younger.
- **Label or prior shift:** the outcome prevalence (P(Y)) changes, such as a higher rate of fraud. This can alter calibration and the best decision threshold.
- **Concept drift:** the conditional relationship <code>P(Y | X)</code> changes. The same inputs now lead to different outcomes, perhaps because customer behavior or policy changed.

In practice, these changes can occur together. A model’s measured performance may also fall because of data-quality, software, or serving changes. Drift is a signal to investigate, not a diagnosis or automatic command to retrain.

## Monitor predictions and outcomes

Log the model version, prediction time, inputs allowed by policy, prediction, and eventual outcome. Compare input and score distributions with a reference period to spot changes early; these checks need no labels, but cannot tell whether accuracy changed. When labels arrive, monitor the task metric and confusion matrix over time, including important subgroups.

Define investigation thresholds from the system’s normal variation and business risk rather than treating one statistic as a universal alarm. Check data collection, feature pipelines, class prevalence, calibration, and performance before retraining. Record the training window and evaluation results so a new model can be compared with the deployed one and rolled back if needed.

## Common mistakes

- **Calling every input shift a failure:** covariates can move while performance remains adequate.
- **Waiting only for labels:** outcome labels may be delayed, so input monitoring can provide an early warning.
- **Retraining automatically on a drift alert:** noisy or unrepresentative recent data can make a model worse.
- **Checking only aggregate performance:** subgroup changes can disappear in an overall average.
