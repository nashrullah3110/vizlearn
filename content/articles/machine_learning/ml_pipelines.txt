title: Machine-Learning Pipelines
intro: A pipeline bundles preprocessing and a model into one fitted workflow. It keeps each transformation inside the training split during validation and makes the same steps available at prediction time.

## What a pipeline does

Many preprocessing steps learn from data. A scaler estimates means and standard deviations; an imputer estimates fill values; a feature selector uses the target. Fit those steps before splitting and information from validation or test rows can influence the model. A pipeline fits each step on the training portion and applies it to held-out rows.

## Worked example: feature selection before cross-validation

Suppose 300 rows contain only random features and random labels. If you select the 20 features most correlated with the labels using all 300 rows, then cross-validate a model, each validation fold has already influenced which features were selected. The accuracy can look better than chance even though the data has no predictive signal.

Put feature selection and the model in a pipeline passed to cross-validation. Each fold then selects features using its training rows only and measures on its held-out rows. A pipeline does not guarantee a correct evaluation by itself: the split must still reflect the task, and repeated tuning on the same validation results can overfit those results.

## Compose steps for different columns

In scikit-learn, `Pipeline` chains transformations and a final estimator. `ColumnTransformer` can route numeric columns through an imputer and scaler, categorical columns through an imputer and encoder, and pass the combined representation to a model. Pipeline parameters use names such as `scale__with_mean` or `model__C`, so a search can compare preprocessing and model settings together.

For example, a numeric scaler should be fitted only on each training fold. The fitted pipeline then applies those stored statistics to validation data. At deployment, save the fitted pipeline and pass raw records through it, which reduces the chance that training and serving use different preprocessing code.

## What pipelines do not solve

- **Wrong split strategy:** use group-aware splits for related records and time-aware splits for future prediction.
- **Target or future leakage:** a feature that contains the answer or information unavailable at prediction time remains invalid inside a pipeline.
- **Resampling in ordinary scikit-learn pipelines:** resampling must happen on training folds only; use an imbalanced-learn pipeline for samplers such as SMOTE.
- **Every transformation needs fitting:** a fixed log transform has no learned parameters, though keeping it in the workflow may still improve reproducibility.
