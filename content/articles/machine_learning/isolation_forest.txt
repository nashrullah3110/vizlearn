title: Isolation Forest
intro: Isolation Forest ranks unusual observations by how few random tree splits are needed to separate them. It is useful when labels are scarce, but the score and threshold need to be interpreted for the dataset and task.

## How isolation reveals anomalies

Many anomaly detectors model what normal data looks like and flag points that do not fit. Isolation Forest reverses the question: how quickly can random partitions isolate a point? Unusual points often have shorter paths than points in dense regions.

## From path length to anomaly score

Each tree repeatedly chooses a feature and a split value. The number of splits needed to isolate a point is its path length. Isolation Forest averages path lengths across trees and normalises for the sample size; shorter paths produce higher anomaly scores under the convention shown here.

An isolated point may be separated by one or two splits because many random cuts fall in the empty space around it. A point inside a dense group usually needs more cuts. This score ranks points; it is not a probability that a point is truly anomalous.

## Explore the forest

1. Set **Trees** to 5, then raise it toward 60. Change **Forest seed** to compare runs. With more trees, the flagged set should become less sensitive to a single random forest.
2. Adjust **Score threshold** and inspect how many points are flagged. The cutoff changes the decision; it does not change the underlying observations or prove that a point is an anomaly.
3. Change **Points sampled per tree** to see how the subsample affects paths and the result.

The visualiser uses a two-dimensional example. In an application, inspect flagged cases and validate the threshold with domain knowledge or labelled examples when available.

## Strengths and limitations

Isolation Forest does not require labelled anomalies or a distance metric, and it can be efficient on large datasets. Its random axis-aligned splits can be less effective when anomalies are only locally unusual, when irrelevant features dominate the splits, or when the meaningful structure is strongly rotated or dependent across features.

The threshold is a separate decision from the ranking. Some implementations expose a contamination setting to choose a cutoff based on an assumed fraction of outliers; that assumption should reflect the use case, not be treated as a measured anomaly rate. Compare with [Local Outlier Factor](https://scikit-learn.org/stable/modules/outlier_detection.html#local-outlier-factor) when local density differences matter, or [DBSCAN](dbscan_clustering.html) when density-based clusters are the goal.

## Sources and next steps
