title: Decision Trees
intro: A decision tree predicts by applying feature-based rules from a root to a leaf. The path is easy to inspect, but a deep tree can fit noise and change sharply when the data changes.

## How the tree makes predictions

A decision tree predicts by following feature questions from a root to a leaf; a leaf stores a class or numeric prediction. The example on this page uses categorical splits and information gain, while other tree learners can use different criteria.

## How a split is chosen

The tree looks for a feature question that makes the resulting groups less mixed. For binary classes with positive fraction p, entropy is:

<p><strong>H(p) = −p log₂(p) − (1 − p) log₂(1 − p)</strong></p>

Entropy is 0 when a group contains one class only and 1 bit when the classes are evenly mixed. Information gain is the parent’s entropy minus the size-weighted average entropy of its child groups. The tree picks the split with the greatest gain, then repeats the process in each child until a stopping rule applies.

For example, start with 10 cases: five Yes and five No, so entropy is 1 bit. Suppose a “sunny?” question makes one child with four Yes cases and no No cases (entropy 0), and a second child with one Yes and five No (entropy about 0.65). The weighted child entropy is 0.4 × 0 + 0.6 × 0.65 = 0.39 bits. The split gains about 1 − 0.39 = 0.61 bits.

This page uses information gain and categorical features. Other tree implementations may use Gini impurity or continuous thresholds; check the estimator’s splitting rules before assuming every tree grows the same way.

The example shows the rule-building process, not an automatic claim that the chosen tree will generalise. A tree can keep splitting until it memorises its training examples.

## When trees are useful

Tree paths are readable as a sequence of decisions, and the model can represent nonlinear boundaries and feature interactions without scaling numeric inputs. A small, pruned tree can be a useful explanation or baseline.

The main risk is overfitting. Limit depth, require enough samples per leaf, or prune using validation data. A high information-gain feature is useful for this tree’s split; it does not prove that the feature causes the outcome. Deep trees can also be unstable: a small change in training data may produce a different early split and a different tree. Ensembles such as [random forests](random_forest.html) reduce some of that instability at the cost of a less transparent prediction process.
