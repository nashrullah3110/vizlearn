title: Training on an Imbalanced Dataset
intro: When one class is rare, average training loss and accuracy can hide poor detection of that class. The right response depends on the metric, error costs, and how the model will be used.

## What imbalance changes

When positives are rare, a classifier can achieve high accuracy by mostly predicting the majority class while missing the cases that matter. With 1% positives, always predicting negative gives 99% accuracy and zero recall, so evaluate class-specific errors as well as the overall score.

Imbalance alone does not prove a model is wrong. First measure performance in a way that reflects the task: inspect the confusion matrix, precision, recall, F1, and a precision-recall curve. Compare results with the prevalence baseline and decide what false positives and false negatives cost.

## Three different interventions

- **Change the decision threshold:** keeps the fitted model fixed and trades precision for recall. Tune on validation data and inspect the resulting workload.
- **Change loss weights:** class weights make errors on a rare class count more during fitting. This can shift the learned boundary but does not create new examples.
- **Change the training sample:** oversampling adds or synthesizes minority examples; undersampling removes majority examples. This changes the data seen during fitting and can increase overfitting or discard useful variation.

Try threshold adjustment and sensible evaluation first. If the model still fails the task, compare weights or resampling using the same validation procedure.

## Read the visualizer

Set **Class 0 Ratio** to 50, then press **Retrain Both Nets**. Increase it to 95 and retrain again. The two classes become less evenly represented, and the learned decision region can shift. The demonstration isolates class balance in a small synthetic problem; real performance also depends on feature overlap, sample size, model choice, and random variation.

The visualizer shows why accuracy can remain high while minority-class recall falls. It does not show that changing the ratio alone is always the right fix. Compare class-specific errors and choose a strategy against a defined validation objective.

## Compare weighting and resampling

|Method|What changes|Trade-off|
|---|---|---|
|Class weighting|Contribution of each class to training loss|Can improve minority recall; may increase false positives or harm probability calibration|
|Undersampling|Some majority examples are removed|Cheaper training; discarded examples may contain useful subgroups|
|Random oversampling|Minority rows are repeated|Simple; exact duplicates can encourage memorization|
|SMOTE|Synthetic minority rows are interpolated between neighbours|Can help numeric features; may create unrealistic points in sparse, categorical, or high-dimensional data|

With 99,500 negative and 500 positive examples, balanced class weights assign a positive example about 199 times the negative example’s weight. This changes the loss contribution; it does not make the observed sample representative of every deployment setting. Check probability calibration before using weighted-model scores as probabilities.

## Prevent a misleading evaluation

Split before resampling. Apply oversampling or undersampling only inside each training fold; otherwise near-duplicates or synthetic relatives can cross into validation or test data. Use a pipeline or an imbalanced-learn pipeline to keep sampling within the fold. Preserve the real class distribution in validation and test sets unless the deployment distribution is intentionally different.

ROC AUC measures ranking across thresholds and can be useful, but it does not tell how many alerts will be correct at the operating threshold. Precision-recall results expose that trade-off more directly when positives are scarce. Report the positive prevalence and a confusion matrix at the chosen threshold.
