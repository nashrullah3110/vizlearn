title: Feature and Permutation Importance
intro: Permutation importance measures how much a model’s score changes when a feature is shuffled. It describes reliance for a chosen model and dataset, not causal importance.

## The idea



Permutation importance is the drop in a fitted model’s chosen score after one feature is shuffled. It describes reliance for that model, metric and dataset; it does not show that a feature causes the outcome.

## Reading the chart

The example compares a strong signal, a weak signal, noise and a duplicate
copy of the strong signal. The model is a random forest.

`noise` scores about zero, which is correct and reassuring.

Now compare `signal` with `copy of signal`. They contain the same information,
so shuffling either one leaves its twin available to the forest. Each can
therefore receive a much smaller score drop than the signal provides as a
group.

## Why: correlated features hide each other

The method shuffles one column at a time. Some trees can use `signal`, while
others use its copy. Shuffling only the copy leaves the original signal intact,
so the score may barely change. Low importance here means the model can rely on
the substitute; it does not mean the information is useless.

The metric is measured **one column at a time**, and with linked features
that is the wrong unit of analysis. The honest reading isn't "the copy doesn't
matter" but "either one largely substitutes for the other, and this method can't
say that".

The effect depends on how the fitted model uses the features. With exact
duplicates, a linear model may divide its coefficients between columns; a tree
ensemble may use one as a substitute for the other. In either case, a
single-column shuffle can understate the value of a correlated group.

This is the main limitation to check before interpreting the chart: the result
can look plausible even when correlated features mask one another.

What to do about it:

**Group related features** and, where appropriate, permute the group together.
This estimates the value of the group, not the unique contribution of each
member.

**Check the correlation matrix** before reading any importance chart.

Conditional permutation methods can preserve dependencies between features,
but require a suitable conditional model and a clearly defined question.

## Held-out data, not training data

Importance measured on the training set can reward memorisation. A feature
used to fit noise may appear valuable there even though it does not help on new
data.

On held-out data, the method estimates how much that feature helps the chosen
score generalise. Use data that was not used to fit the model, and choose a
metric that reflects the task. The [scikit-learn guide](https://scikit-learn.org/stable/modules/permutation_importance.html)
explains this evaluation procedure.

Comparing the two can be diagnostic: a feature that scores highly on training
data but little on validation data may be associated with overfitting.

## Against a tree's built-in importance

Random forests and boosted trees expose `feature_importances_`, often based on
the mean decrease in impurity. It is available from the fitted model without
an extra scoring pass, but can favour high-cardinality features because they
offer more candidate split points. A random ID can therefore receive a
misleadingly high score.

Permutation importance avoids that particular split-count bias, but costs a
re-scoring pass per feature and can be used with models that have no built-in
importance measure.

## Repeats

Shuffling is random, so one result is noisy. Increase **Shuffles per feature**
to estimate the average score drop and its variation across repeats. More
repeats cost more scoring time; choose enough to see whether the ranking is
stable for this dataset.

## Where it goes wrong

**Reading it on linked features.** The central trap.

**Measuring it on training data.** The model may have memorised patterns that
do not generalise.

**Treating it as causal.** It says the model used a feature, not that the feature
causes the outcome.

**Checking across models.** Importance is scaled to one fitted model. A
different model can rank the same features differently and both be right about
themselves.

## Experiments to try

1. Set **Shuffles per feature** to 1, then raise it toward 12. Repeated shuffles average out some random variation, though they take longer.
2. Change **Shuffle seed**. The bars can move because each run uses different permutations; large swings suggest the estimates are noisy.

## Runnable example

The example measures importance on held-out data, compares a duplicated signal
before and after removing its copy, and switches scoring metrics to show that
importance depends on the question being measured.

```python-run
import numpy as np
from sklearn.datasets import make_classification
from sklearn.ensemble import RandomForestClassifier
from sklearn.inspection import permutation_importance
from sklearn.model_selection import train_test_split
rng = np.random.default_rng(0)
X, y = make_classification(n_samples=3000, n_features=6, n_informative=3,
                           n_redundant=0, flip_y=0.08, shuffle=False,
                           random_state=0)
X = np.column_stack([X, rng.normal(size=len(X)), X[:, 0]])
names = ["real_0", "real_1", "real_2", "filler_3", "filler_4", "filler_5",
         "pure_noise", "copy_of_real_0"]
Xtr, Xte, ytr, yte = train_test_split(X, y, test_size=0.3, random_state=0)
rf = RandomForestClassifier(n_estimators=250, random_state=0).fit(Xtr, ytr)
r = permutation_importance(rf, Xte, yte, n_repeats=10, random_state=0)
print("the trap. real_0 and copy_of_real_0 are the same column:")
for i in (0, 7):
    print("  %-16s permutation %.4f" % (names[i], r.importances_mean[i]))
print("  shuffling either leaves its twin available to the forest.")
print()
print("drop the copy and refit:")
keep = [i for i in range(8) if i != 7]
rf2 = RandomForestClassifier(n_estimators=250, random_state=0).fit(Xtr[:, keep], ytr)
r2 = permutation_importance(rf2, Xte[:, keep], yte, n_repeats=10, random_state=0)
print("  real_0 importance is now %.4f, up from %.4f."
      % (r2.importances_mean[0], r.importances_mean[0]))
print("  the column did not become more useful. it stopped sharing credit.")
print()
print("correlated features SPLIT their importance. a zero means 'the model")
print("can get by without it', not 'this column is useless'.")
print()
print("measure on held-out data and use the metric you care about:")
r3 = permutation_importance(rf, Xte, yte, n_repeats=10, random_state=0,
                            scoring="roc_auc")
order = np.argsort(-r3.importances_mean)
print("  scored by ROC AUC instead of accuracy:")
for i in order[:4]:
    print("    %-16s %.4f" % (names[i], r3.importances_mean[i]))
```
