title: Grid Search and Random Search
intro: Grid search tests every combination from fixed parameter lists; random search samples combinations from chosen distributions. With a limited evaluation budget, random search can explore more useful values when only a few parameters strongly affect performance.

## What the search budget buys

Both methods compare model configurations using validation scores. Grid search is systematic over a small, discrete set; random search spends each trial on a new sample from the parameter ranges. The choice depends on the search space and the cost of each fit.

## Why the search space matters

Suppose there are two parameters, but only one has a large effect on validation score. A grid with ten values for each parameter uses 100 trials to test each value of the important parameter only ten times. A random search with the same 100-trial budget can sample many more distinct values along both ranges. If the second parameter barely matters, more of those trials cover useful settings of the first.

This is not a guarantee that one random run will win. Results depend on the ranges, sampling distributions, noise in the validation score and random seed. Bergstra and Bengio’s [random-search study](https://jmlr.org/papers/v13/bergstra12a.html) explains why random search can be more efficient when only a subset of hyperparameters matters.

## Choosing a method

| Use | When it fits |
|---|---|
| Grid search | A few parameters have small, meaningful discrete sets, or an exhaustive check is important. |
| Random search | Ranges are broad, some parameters matter more than others, or each fit is expensive. |
| A staged search | Random search identifies a promising region, then a smaller grid compares nearby values. |

Choose distributions that match the parameter. For a learning rate spanning several orders of magnitude, sample on a logarithmic scale; a uniform sample over raw values will concentrate most trials near the upper end. Keep the validation strategy fixed, and reserve the test set until the final evaluation. If fits are costly, successive halving can stop weak configurations early; Bayesian optimisation is another option when each evaluation is expensive.
