title: Logistic Regression
intro: Logistic regression turns a weighted sum of features into a probability for a class. Its decision boundary is linear in the features, while its coefficients describe changes in log-odds.

## Predicting a class with a probability

Logistic regression estimates a probability, then applies a threshold to make a class prediction. It is a useful baseline when the log-odds of the outcome can be described by a linear combination of the input features.

## From a score to a probability

For features x₁, …, xₚ, the model first calculates a linear score:

<p><strong>z = w₁x₁ + … + wₚxₚ + b</strong></p>

It maps that score through the sigmoid function:

<p><strong>p = 1 / (1 + e<sup>−z</sup>)</strong></p>

Equivalently, log(p / (1 − p)) = z. The weights therefore act on log-odds, not directly on probability. A threshold—often 0.5 by default—turns p into a predicted class. Changing the threshold changes labels without changing the fitted probabilities.

## Work through one prediction

Use weights w₁ = w₂ = 1 and bias b = −10, as in the visualiser. For the point (4, 4), z = 4 + 4 − 10 = −2, so p = sigmoid(−2) ≈ 0.119. The model assigns about a 12% probability to class B. At (6, 6), z = 2 and p ≈ 0.881. At (5, 5), z = 0 and p = 0.5, exactly on the boundary for a 0.5 threshold.

## Regularisation and feature scale

Scikit-learn’s <code>LogisticRegression</code> uses L2 regularisation by default, with <code>C=1.0</code>. C is the inverse of regularisation strength: smaller values penalise large coefficients more strongly. Regularisation helps keep estimates finite and reduces overfitting; see the official [LogisticRegression documentation](https://scikit-learn.org/stable/modules/linear_model.html#logistic-regression) for solver and penalty options.

Because the penalty acts on coefficient sizes, feature units matter. A change of units changes the coefficient needed to represent the same effect and therefore changes how strongly it is penalised. Scale numeric features when their units differ, and fit the scaler only on each training split. A pipeline keeps that order intact:

~~~python
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

model = make_pipeline(
    StandardScaler(),
    LogisticRegression(C=1.0, max_iter=1000),
)
model.fit(X_train, y_train)
probabilities = model.predict_proba(X_test)[:, 1]
~~~

## Assumptions and common mistakes

- **Reading a coefficient as a probability change.** A one-unit increase in xⱼ changes the log-odds by wⱼ, with other features held fixed. The corresponding odds ratio is exp(wⱼ); the probability change depends on the starting point.
- **Treating 0.5 as a universal threshold.** It is appropriate only under particular probability and error-cost assumptions. Choose a threshold on validation data when false-positive and false-negative costs differ; see [threshold tuning](threshold_tuning.html).
- **Expecting a curved boundary from raw features.** The boundary is linear in the supplied features. Nonlinear patterns require transformed features or a different model.
- **Interpreting coefficients with strongly correlated inputs.** Predictions may remain useful while individual coefficients become unstable and difficult to interpret.
