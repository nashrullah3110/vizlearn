title: Global Average Pooling against Flatten
intro: The step between the convolutions and the classifier. Why the obvious version wastes most of the model's params.

## Two ways to collapse a block

Convolutional layers output a 3D block: height &#215. Width &#215. Channels. A
classifier needs a single vector. a thing has to turn one into the other, and
there are two picks.

**Flatten** reads each value in the block into one long vector. For a
7&#215;7&#215;512 map that is 25,088 numbers, and the dense layer that follows
needs a weight for each of them per class.

**Global mean pooling** takes the mean of each channel over its whole spatial
extent. each 7&#215;7 slice turns one number, and the block turns 512
numbers.

## Count them

Drag the controls and watch the readout. At the defaults &mdash;
7&#215;7&#215;512 into 10 classes:

```
flatten  ->  7 * 7 * 512 * 10  =  250,880 weights
GAP      ->          512 * 10  =    5,120 weights
```

Forty-nine times fewer, and 49 is just 7&#215;7. The ratio is always the
spatial area of the feature map. This Is why the saving grows as the map gets
larger.

Set classes to 1000, as in ImageNet, and the flattened version needs 25 million
weights in a single layer. Early architectures really did this: **VGG-16 keeps
about 90% of its 138 million params in its final dense layers**, and almost
all of that is the first one right away after the flatten.

## What pooling gives up, and what it buys

Blending discards **where** in the map each activation was. If channel 7
reacts to wheels, flatten preserves that the wheels were at the bottom left,
and GAP records only that there were wheels.

For classification that is often the right trade. The question is whether a car
is present, not where the wheels sat, and the convolutional layers underneath
have already coded spot-sensitive structure into which channels fire.

Three things are bought in exchange.

**Far fewer params**, and so much less overfitting. A dense layer with
25 million weights on a dataset of 50,000 images is an invitation to store.

**Any input size.** The mean of a channel is one number even so of the
spatial dims, so a GAP network accepts a 224-pixel image or a 400-pixel one
without modification. A flattened network can't: 25,088 weights expect just
25,088 inputs, which is why older models are rigid about input size.

**Interpretability.** With GAP followed by a single dense layer, each class score
is a weighted sum of channel means. That weighting is just what Class
Activation Mapping uses to give a heatmap, and [Grad-CAM](grad_cam.html)
generalises it.

## What replaced the debate

each modern architecture uses GAP. ResNet, Inception, MobileNet, EfficientNet
and the convolutional stems of hybrid transformers all end with a global pool and
one dense layer.

The exception worth knowing is **Vision Transformers**. This Often use a
dedicated class token instead &mdash; a learned vector that attends to all the
[patches](vision_transformer_patches.html) and carries the summary. Some ViT
variants pool the patch tokens instead and report it works about as well.

## The parameters it deletes

The saving is exact and it's large. A 7&times;7&times;512 feature map into 10
classes, two ways to reach the classifier:

|method|weights in that layer|

## Where it goes wrong

**Pooling too early.** GAP belongs after the last convolutional block. Applied
midway it destroys the spatial structure the left layers need.

**Using flatten because a tutorial did.** Most tutorials predate the change.
Check what the param count is doing before accepting it.

**Expecting GAP to fix a small feature map.** With a 1&#215;1 map there's
nothing to mean and the two are the same.

**Losing global max pooling exists.** It takes the max instead of the
mean, and for tasks where one strong local response matters more than an mean
&mdash; some spotting and audio tasks. It can be the better choice.

## Questions people ask

<strong>What does global average pooling do?</strong> It averages each feature map to a single number, turning an H by W by C block into a vector of C values.

<strong>Why replace the flatten and dense layers with it?</strong> Flattening feeds millions of values into a dense layer, which holds most of the model's parameters. Pooling removes those weights and cuts overfitting.

<strong>Does it work with any input size?</strong> Yes, because the average is taken over whatever spatial size arrives. A network ending in global average pooling accepts images of different resolutions.

<strong>What does it throw away?</strong> All spatial position information. It knows how strongly a feature fired somewhere, but not where.

<strong>How is it related to class activation maps?</strong> Because each channel is reduced to one average, the final weights connect channels directly to classes. Weighting the feature maps by those weights shows where the class evidence was.

<strong>Is global max pooling an alternative?</strong> It keeps the strongest response instead of the mean. Max suits sparse, detection-like features, while average gives smoother, more stable signals.

## Replacing the flatten layer with one number per channel

Global mean pooling merges a whole feature map to a single number per channel. It looks like it throws away almost all -- and that is just what makes it work, in a way this measures against the flatten-and-dense option it replaced.

```python-run
import numpy as np
rng = np.random.default_rng(2)
C, H, W = 8, 6, 6
fmap = np.abs(rng.normal(0.2, 0.15, (C, H, W)))
fmap[2, 1:3, 1:3] = 3.4
fmap[5, 4:6, 3:5] = 3.1
print("A FEATURE MAP with %d channels of %dx%d." % (C, H, W))
print("GAP takes the mean over the spatial axes: (%d,%d,%d) -> (%d,)."
      % (C, H, W, C))
gap = fmap.mean(axis=(1, 2))
print("%-12s %12s %12s %12s" % ("channel", "GAP", "max", "where max is"))
for c in range(C):
    r, cc = np.unravel_index(fmap[c].argmax(), (H, W))
    print("%-12d %12.4f %12.4f %12s" % (c, gap[c], fmap[c].max(),
                                        "(%d,%d)" % (r, cc)))
print("   channels 2 and 5 stand out. the vector says WHAT, not WHERE.")
print()
NCLASS = 10
flat_params = C * H * W * NCLASS + NCLASS
gap_params = C * NCLASS + NCLASS
print("THE PARAMETER ARGUMENT:")
print("%-40s %14s" % ("head design", "parameters"))
print("%-40s %14d" % ("flatten (%d)->dense(%d)" % (C*H*W, NCLASS), flat_params))
print("%-40s %14d" % ("GAP (%d)->dense(%d)" % (C, NCLASS), gap_params))
print("%-40s %14.1fx" % ("ratio", flat_params / gap_params))
print("   for a real backbone the gap is enormous:")
print("%-24s %10s %14s %14s" % ("backbone", "final map", "flatten", "GAP"))
for name, c, h, w in (("VGG-16", 512, 7, 7), ("ResNet-50", 2048, 7, 7),
                      ("MobileNetV2", 1280, 7, 7)):
    print("%-24s %10s %14s %14s"
          % (name, "%dx%dx%d" % (c, h, w),
             "{:,}".format(c*h*w*1000+1000), "{:,}".format(c*1000+1000)))
print("   GAP deletes almost all of VGG-16's 124M classifier parameters.")
```

The next block shows the argument that matters more: a GAP head accepts any input resolution, while a flatten head is wired to exactly one spatial size.

```python-run
C, H, W = 8, 6, 6
print("INPUT SIZE. a flatten head is wired to one spatial size:")
print("%-22s %14s %18s %14s" % ("input image", "final map", "flatten", "GAP"))
for side in (192, 224, 288, 384):
    h = side // 32
    print("%-22s %14s %18d %14d"
          % ("%dx%d" % (side, side), "%dx%dx%d" % (C, h, h), C * h * h, C))
print("   the flatten column changes with every size; GAP never does.")
print("   the same trained head works on any resolution -- that is why")
print("   GAP is in every modern backbone.")
```

The next block demonstrates what GAP does to training: it enforces translation invariance so that the same object in two different corners produces identical representations.

```python-run
import numpy as np
C, H, W = 8, 6, 6
a_left = np.zeros((C, H, W)); a_left[2, 0:2, 0:2] = 3.0
a_right = np.zeros((C, H, W)); a_right[2, 4:6, 4:6] = 3.0
print("TRANSLATION INVARIANCE. same class, different corners:")
print("   example A: channel 2 fires top-left")
print("   example B: channel 2 fires bottom-right")
fa, fb = a_left.reshape(-1), a_right.reshape(-1)
ga, gb = a_left.mean(axis=(1, 2)), a_right.mean(axis=(1, 2))
def cos(u, v):
    return float(u @ v / (np.linalg.norm(u) * np.linalg.norm(v) + 1e-12))
print("%-34s %14s" % ("representation", "cosine similarity"))
print("%-34s %14.4f" % ("flattened (%d numbers)" % fa.size, cos(fa, fb)))
print("%-34s %14.4f" % ("after GAP (%d numbers)" % ga.size, cos(ga, gb)))
print("   to a flatten head these are ORTHOGONAL -- it has to learn the")
print("   class twice, once per position.")
print("   after GAP they are identical. invariance is enforced for free,")
print("   and that is why GAP heads generalise from less data.")
```

The next block covers the price: GAP cannot represent position, so it fails at tasks that need coordinates or counts.

```python-run
import numpy as np
C, H, W = 8, 6, 6
print("THE PRICE. GAP cannot represent position:")
print("%-36s %s" % ("task", "GAP as the head?"))
for task, ok in (("image classification", "yes -- the standard choice"),
                 ("object detection", "no -- boxes need coordinates"),
                 ("semantic segmentation", "no -- output is per-pixel"),
                 ("counting objects", "no -- mean, not sum"),
                 ("pose estimation", "no -- position IS the label")):
    print("%-36s %s" % (task, ok))
print()
print("the counting row is subtle. watch what actually happens:")
one = np.zeros((C, H, W)); one[2, 1:3, 1:3] = 3.0
two = np.zeros((C, H, W)); two[2, 1:3, 1:3] = 3.0; two[2, 4:6, 3:5] = 3.0
big = np.zeros((C, H, W)); big[2, 1:3, 1:5] = 3.0
print("   one object  -> GAP = %.4f" % one.mean(axis=(1, 2))[2])
print("   two objects -> GAP = %.4f" % two.mean(axis=(1, 2))[2])
print("   one BIGGER  -> GAP = %.4f" % big.mean(axis=(1, 2))[2])
print("   the last two are identical: count is confounded with SIZE.")
print("   no downstream layer can separate them, because the distinction")
print("   was destroyed. that is the real failure -- an ambiguity baked")
print("   into the representation.")
print("   if a task needs count or location, the spatial axes must")
print("   survive to the output, which is what detection and segmentation")
print("   architectures are built to do.")
```
