title: Object Detection with Bounding Boxes: A Practical Guide
intro: Classification tells you what. A regression head tells you where.

## Start here

An object detector's output head does two jobs per candidate region: classify what's there, and regress four numbers describing where it is precisely — typically a box center, width and height, or the offsets needed to nudge a fixed anchor box onto the real object. The classification half is an ordinary softmax problem. The localization half is what this module is about, and <a href="iou_and_non_max_suppression.html" style="color: var(--accent-primary)">IoU</a> sits at the center of it twice: once inside the training loss, and again in how the model gets graded afterward.

## IoU as loss, IoU as grade

A natural localization loss is simply <code>1 − IoU</code> between the predicted box and the ground truth box: 0 when they coincide exactly, approaching 1 as they stop overlapping at all. At evaluation time, the same IoU number gets a different job — a detection is usually scored as a <strong>true positive</strong> only if its IoU with the matching ground truth box clears a threshold, conventionally <strong>0.5</strong> under the PASCAL VOC convention. A box can be visibly "close" and still count as a complete miss if it doesn't clear that bar.

## Classification says what; detection says what and where

A classifier answers one question about a whole image. A detector answers two questions about every object in it: <em>what is it</em>, and <em>where is it</em> &mdash; expressed as a rectangle.

A bounding box is four numbers, and there are three common conventions:

|Format|Numbers|Used by|
|---|---|---|
|`(x_min, y_min, x_max, y_max)`|Two corners|Pascal VOC, most libraries|
|`(x, y, width, height)`|Top-left corner and size|COCO|
|`(cx, cy, w, h)` normalised|Centre and size, 0&ndash;1|YOLO|

Mixing them up is the single most common bug in detection code, and it fails quietly: boxes appear in roughly plausible places and the metrics are mysteriously poor. Always check which convention a dataset and a model each expect.

Each box also carries a class label and a confidence score, so one detection is: a rectangle, a name, and a number between 0 and 1.

## The hard parts

Detection is substantially harder than classification for reasons that are structural rather than incidental.

<strong>The number of outputs varies.</strong> A network produces a fixed-size output; an image may contain zero objects or fifty. Every detector architecture is, at heart, a way of handling that mismatch.

<strong>Objects vary enormously in scale.</strong> A pedestrian may be 20 pixels tall or 500. A single feature map has one effective scale, which is why detectors predict from several feature maps at once.

<strong>Localisation and classification are different tasks</strong> with different losses, trained jointly &mdash; typically a cross-entropy for the class and a regression loss (smooth L1, or a direct IoU loss) for the coordinates.

<strong>The background dominates.</strong> Most candidate positions contain nothing at all, often by a thousand to one. That extreme imbalance is why focal loss &mdash; which down-weights easy, well-classified examples &mdash; was invented for detection specifically.

## Two families of detector

<strong>Two-stage detectors</strong> (R-CNN, Fast R-CNN, Faster R-CNN) first propose regions that might contain something, then classify and refine each proposal. More accurate, historically slower, and still preferred where precision matters more than latency.

<strong>One-stage detectors</strong> (YOLO, SSD, RetinaNet) predict boxes and classes directly from the feature maps in a single pass. Much faster, and the accuracy gap has largely closed &mdash; which is why most production systems now use them.

<strong>Anchor-based versus anchor-free</strong> is the other axis. Anchor-based methods place a set of predefined box shapes at every position and learn offsets from them. Anchor-free methods (FCOS, CenterNet, recent YOLO versions) predict boxes directly, removing the anchor hyperparameters that were always awkward to tune.

<strong>DETR</strong> and its successors take a third route entirely, treating detection as set prediction with a transformer and removing the need for non-maximum suppression &mdash; conceptually cleaner, and slower to train.

## Four numbers, and everything that depends on them

A bounding box is four numbers, and almost every detection bug comes from a disagreement about which four. This works through the formats, the conversions, IoU, non-max suppression and the loss -- all of it arithmetic you can check line by line.

```python-run
import numpy as np

print("THE SAME BOX, IN FOUR CONVENTIONS. every library picks one and")
print("every one of them is called 'the box':")
box_xyxy = (20.0, 30.0, 80.0, 90.0)
x1, y1, x2, y2 = box_xyxy
w, h = x2 - x1, y2 - y1
cx, cy = x1 + w / 2, y1 + h / 2
IMGW, IMGH = 200.0, 150.0
print("%-26s %-34s %s" % ("format", "values", "used by"))
print("%-26s %-34s %s"
      % ("xyxy (corners)", str(box_xyxy), "torchvision, COCO eval"))
print("%-26s %-34s %s"
      % ("xywh (top-left + size)", str((x1, y1, w, h)), "COCO annotations"))
print("%-26s %-34s %s"
      % ("cxcywh (centre + size)", str((cx, cy, w, h)), "YOLO, DETR"))
print("%-26s %-34s %s"
      % ("normalised cxcywh",
         "(%.3f, %.3f, %.3f, %.3f)"
         % (cx / IMGW, cy / IMGH, w / IMGW, h / IMGH), "YOLO label files"))
print("   they describe the identical rectangle. mixing two of them")
print("   produces boxes that are silently wrong rather than an error,")
print("   which is why this is the first thing to check when a detector")
print("   trains to a loss that falls but a mAP that does not.")
print()
print("   the conversions, both directions, so you can check them:")
print("      xyxy -> cxcywh:  cx=(x1+x2)/2  cy=(y1+y2)/2  w=x2-x1  h=y2-y1")
print("      cxcywh -> xyxy:  x1=cx-w/2  y1=cy-h/2  x2=cx+w/2  y2=cy+h/2")
back = (cx - w / 2, cy - h / 2, cx + w / 2, cy + h / 2)
print("      round trip: %s -- max error %.1e"
      % (str(back), max(abs(a - b) for a, b in zip(back, box_xyxy))))
print()

print("ONE MORE DISAGREEMENT, and it is the nastiest: is the coordinate a")
print("pixel INDEX or a pixel EDGE?")
print("      a box covering pixel columns 0 to 9 inclusive is")
print("         x1=0, x2=9   if coordinates are indices  -> width 9")
print("         x1=0, x2=10  if coordinates are edges     -> width 10")
print("   the difference is one pixel, and it changes every area, every")
print("   IoU and every reported score by a little. modern code uses")
print("   edges, so width is exactly x2-x1. the original Pascal VOC used")
print("   indices and added 1, which is why VOC numbers and COCO numbers")
print("   for the same model differ slightly.")
print()

def iou(a, b):
    ix1, iy1 = max(a[0], b[0]), max(a[1], b[1])
    ix2, iy2 = min(a[2], b[2]), min(a[3], b[3])
    inter = max(0.0, ix2 - ix1) * max(0.0, iy2 - iy1)
    aa = (a[2] - a[0]) * (a[3] - a[1])
    bb = (b[2] - b[0]) * (b[3] - b[1])
    return inter / (aa + bb - inter)

print("IoU: intersection over union. the intersection is a rectangle, so")
print("it is four max/min operations and a multiply:")
truth = (20.0, 30.0, 80.0, 90.0)
cases = [("exact", (20., 30., 80., 90.)),
         ("shifted 10px right", (30., 30., 90., 90.)),
         ("half the size, centred", (35., 45., 65., 75.)),
         ("twice the size, centred", (-10., 0., 110., 120.)),
         ("touching, not overlapping", (80., 30., 140., 90.)),
         ("miles away", (150., 10., 190., 50.))]
print("%-28s %12s %12s %12s %10s"
      % ("prediction", "intersect", "union", "IoU", "counts?"))
for name, b in cases:
    ix1, iy1 = max(truth[0], b[0]), max(truth[1], b[1])
    ix2, iy2 = min(truth[2], b[2]), min(truth[3], b[3])
    inter = max(0.0, ix2 - ix1) * max(0.0, iy2 - iy1)
    union = ((truth[2] - truth[0]) * (truth[3] - truth[1])
             + (b[2] - b[0]) * (b[3] - b[1]) - inter)
    v = inter / union
    print("%-28s %12.0f %12.0f %12.4f %10s"
          % (name, inter, union, v, "yes" if v >= 0.5 else "no"))
print("   note the fourth row. a prediction that CONTAINS the object")
print("   completely still scores only %.2f, because union punishes the"
      % iou(truth, cases[3][1]))
print("   extra area. IoU cares about agreement, not about coverage --")
print("   a box around the whole image finds every object and scores")
print("   almost nothing.")
print()

print("NON-MAX SUPPRESSION. a detector fires many times on one object, so")
print("the duplicates have to be removed. sort by confidence, take the")
print("best, delete everything that overlaps it too much, repeat:")
DETS = [((20., 30., 80., 90.), 0.94),
        ((24., 33., 84., 92.), 0.88),        # same object
        ((18., 28., 76., 86.), 0.79),        # same object
        ((110., 40., 170., 100.), 0.72),     # a second object
        ((115., 45., 175., 104.), 0.65),     # same second object
        ((38., 48., 98., 108.), 0.51)]      # a third, overlapping the first

def nms(dets, thr):
    order = sorted(range(len(dets)), key=lambda i: -dets[i][1])
    keep, killed = [], {}
    while order:
        i = order.pop(0)
        keep.append(i)
        rest = []
        for j in order:
            v = iou(dets[i][0], dets[j][0])
            if v > thr:
                killed[j] = (i, v)
            else:
                rest.append(j)
        order = rest
    return keep, killed

for thr in (0.5, 0.3):
    keep, killed = nms(DETS, thr)
    print("   threshold %.1f -> keeps %d of %d:" % (thr, len(keep), len(DETS)))
    for i in range(len(DETS)):
        if i in keep:
            print("      det %d (conf %.2f)  KEPT" % (i, DETS[i][1]))
        else:
            j, v = killed[i]
            print("      det %d (conf %.2f)  suppressed by det %d, IoU %.3f"
                  % (i, DETS[i][1], j, v))
print("   the threshold is a real trade-off and there is no safe default.")
print("   det 5 is the interesting one: its IoU with det 0 is %.3f, so it"
      % iou(DETS[5][0], DETS[0][0]))
print("   survives at 0.5 and is deleted at 0.3. it is a genuinely")
print("   different object that happens to overlap the first one, and no")
print("   threshold can tell that apart from a duplicate -- NMS sees only")
print("   the overlap, never what is inside the boxes.")
print("   too high a threshold leaves duplicates; too low deletes real")
print("   objects in crowds. this is precisely the failure that")
print("   soft-NMS (decay the score instead of deleting) and DETR")
print("   (predict a fixed set, no NMS at all) were designed around.")
print()

print("THE LOSS. detection needs a regression loss on the coordinates, and")
print("the obvious choices are all subtly wrong:")
print("%-22s %14s %14s %16s"
      % ("prediction error", "L2 loss", "L1 loss", "smooth L1"))
for e in (0.1, 0.5, 1.0, 3.0, 10.0):
    sl1 = 0.5 * e * e if abs(e) < 1 else abs(e) - 0.5
    print("%-22.1f %14.3f %14.3f %16.3f" % (e, e * e, abs(e), sl1))
print("   L2 explodes on outliers: a 10-pixel error contributes %.0f,"
      % (10.0 ** 2))
print("   %.0fx as much as a 1-pixel error, so a single badly-placed box"
      % (10.0 ** 2 / 1.0))
print("   dominates the batch. L1 does not, but its gradient is constant,")
print("   so it never settles down near zero. smooth L1 is L2 below 1 and")
print("   L1 above -- fine gradients where you are close, bounded")
print("   influence where you are far.")
print()
print("   AND EVEN SMOOTH L1 IS OPTIMISING THE WRONG THING. two")
print("   predictions with the same coordinate error can have very")
print("   different IoU:")
for name, b in (("small object, off by 10", (20., 30., 40., 50.)),
                ("large object, off by 10", (20., 30., 120., 130.))):
    shifted = (b[0] + 10, b[1], b[2] + 10, b[3])
    print("      %-28s L1 error %2.0f, IoU %.3f"
          % (name, 10.0, iou(b, shifted)))
print("   identical loss, very different quality. that mismatch is why")
print("   modern detectors optimise IoU directly -- GIoU, DIoU, CIoU --")
print("   rather than the coordinates. the metric and the loss should be")
print("   the same thing whenever you can arrange it.")
```

## Things to try

1. <strong>Read the starting position.</strong> The predicted box is offset and undersized relative to the ground truth — overlap is low, loss is close to 1, and it does not count as a match.
2. <strong>Drag dx and dy toward 0.</strong> IoU climbs as the boxes line up spatially, and the loss falls in lockstep — this is the gradient signal a real localization head would be trained on.
3. <strong>Now close dw and dh too.</strong> Position alone isn't enough — a box in the right place but the wrong size still loses IoU on both sides.
4. <strong>Watch the Match readout as IoU crosses 0.5.</strong> It flips from a miss to a match at exactly that boundary, even though the loss was already improving smoothly well before the flip.

## Summing up

<code>1 − IoU</code> is a smooth, differentiable signal that a network can actually be trained against. Whether a detection counts as correct at evaluation time is not smooth at all — it's a hard threshold on that same IoU number. A model can make genuine, loss-reducing progress on a box for a long stretch before that progress ever shows up as a correct detection in your metrics.

## How detections are scored

<strong>IoU (Intersection over Union)</strong> measures how well a predicted box overlaps a true one:

<p class="mono-font">IoU = area of overlap / area of union</p>

It runs from 0 (no overlap) to 1 (perfect). A prediction usually counts as correct if its IoU with a ground-truth box of the same class exceeds a threshold &mdash; 0.5 is the traditional choice.

<strong>Non-maximum suppression</strong> is the cleanup step. A detector typically fires several times on the same object, so NMS keeps the highest-scoring box and discards any box overlapping it by more than a threshold. Without it, every object is reported three or four times.

<strong>mAP (mean Average Precision)</strong> is the standard headline metric. For each class, sweep the confidence threshold, build a precision-recall curve, take its area; then average across classes. COCO's version averages further over IoU thresholds from 0.5 to 0.95, which rewards precise localisation rather than approximate boxes.

The practical reading: mAP@0.5 tells you whether objects are found; mAP@0.5:0.95 tells you whether the boxes are tight.

## Annotation, and where projects actually fail

Detection datasets are expensive, and the quality of the boxes sets the ceiling on the model.

- <strong>Be consistent about tightness.</strong> Does the box include the shadow? The handle? The occluded part? Write the rule down before annotating, because a model trained on inconsistent boxes learns the inconsistency.
- <strong>Label every instance.</strong> A missed object is trained as background, which actively teaches the model not to detect it.
- <strong>Decide on occlusion and truncation rules</strong> for objects half out of frame.
- <strong>Watch class imbalance.</strong> Rare classes need either more examples or a weighted loss.
- <strong>Match augmentation to the boxes.</strong> Flipping, rotating or cropping an image must transform the coordinates too &mdash; libraries such as Albumentations do this correctly, and hand-rolled pipelines frequently do not.

A few hundred well-annotated images plus a pretrained backbone will usually outperform thousands of sloppy ones.

## Questions people ask

<strong>Which detector should I start with?</strong> A recent YOLO or a torchvision Faster R-CNN, fine-tuned from pretrained weights. Training a detector from scratch needs far more data than most projects have.

<strong>How much data do I need?</strong> With transfer learning, a few hundred annotated images per class gets a usable model. Thousands for production reliability.

<strong>What IoU threshold should I use for NMS?</strong> 0.5 is typical. Lower it if duplicates persist, raise it if genuinely overlapping objects are being suppressed.

<strong>Why are small objects missed?</strong> Because they occupy few pixels in the feature maps used for prediction. Feature pyramids, higher-resolution input and tiled inference are the standard responses.

<strong>What is the difference from segmentation?</strong> Detection gives boxes; semantic segmentation labels every pixel; instance segmentation gives per-object masks. Boxes are cheaper to annotate and often enough.

<strong>How do I detect objects in video?</strong> Detect per frame, then associate detections across frames with a tracker (SORT, ByteTrack) to give each object a persistent identity.

## Recap in one screen

- Detection outputs a box, a class and a confidence for every object present.
- Box formats differ between datasets &mdash; corners, corner-plus-size, and normalised centre-plus-size.
- Two-stage detectors propose then classify; one-stage detectors predict directly and are now the practical default.
- IoU measures overlap, NMS removes duplicates, and mAP is the headline metric.
- Annotation consistency sets the ceiling; augmentation must transform the boxes as well as the image.
