title: Resizing and Interpolation
intro: What happens between the pixels, and why the answer looks different each time.

## Enlarging invents; shrinking discards

Resizing is two different problems wearing one name.

**Enlarging** asks for pixels that were never measured. A 4&#215;4 image
stretched to 8&#215;8 needs 64 values where 16 exist. The extra 48 have to
come from a place, and wherever they come from, they're a guess. No
interpolation method adds info &mdash; the choice is only about which
plausible guess to make.

**Shrinking** has too much data rather than too little, and the risk is
throwing away the wrong parts.

## Nearest neighbour

For each output pixel, work out where it lands in the input and copy whichever
input pixel is closest. That is all.

It's the fastest possible method, and it's **exact** in one key sense:
each output value is a value that truly appeared in the input. Nothing is
averaged, so nothing is invented that wasn't there.

The cost is blockiness. Neighbouring output pixels that map to the same input
pixel are the same, so enlarging makes flat squares with hard steps between
them. Straight edges come out as staircases.

That is often just right. Pixel art must be scaled with nearest neighbour or
it stops being pixel art. A segmentation mask where pixel value 3 means "road"
must be scaled with nearest neighbour. Blending 3 and 5 gives 4, which
might mean "building" &mdash; a label is a name, not a quantity, and names do
not mean.

## Bilinear

For each output pixel, find the four input pixels nearby its spot and
take a weighted mean, with weights from how close the spot is to each.
Linear in one direction, then linear in the other. Hence bilinear.

Edges become smooth and the staircase goes away. The cost is softness: a blend
of nearby pixels is always softer than the originals, so sharp edges turn into
ramps. Enlarge by a large factor and the result is blurry, not blocky.

Switch between the two above with the downscale factor set high. The same
info is present in both. Only the guessing strategy differs, and it's
easy to see that neither is simply better.

**Bicubic** extends the idea to sixteen nearby pixels with a cubic weight
function. It's sharper than bilinear because the cubic curve overshoots
slightly at edges, adding a small amount of local contrast. Photo editors
default to it for that reason. The overshoot is also its failure mode: it can
give faint halos beside high-contrast edges.

| Method | Reads | Speed | Good for | Fails at |
|---|---|---|---|---|
| Nearest | 1 pixel | fastest | pixel art, label masks | photographs |
| Bilinear | 4 pixels | fast | general enlargement | large factors |
| Bicubic | 16 pixels | slower | photographs | can halo |
| Area | a block | fast | shrinking | not for enlarging |

## Shrinking is a different failure

To halve an image, it's tempting to keep each second pixel. This is wrong,
and wrong in a way that looks like a bug elsewhere in the program.

Consider a pattern of alternating black and white columns. Keep each second
column and you may get all the black ones. A solid black image. Shift by
one and you get solid white. Detail finer than the new sampling grid doesn't
disappear gracefully. It reappears as a fully different, false pattern.
This is **aliasing**, and it's why photos of striped shirts on video
develop rainbow moiré.

The fix is to mean before sampling. **Area interpolation** takes the mean of
each input pixel that falls inside each output pixel's footprint, so nothing
is silently dropped. Gaussian blurring before downsampling reaches the same
end, and is what an image pyramid does at each level.

This matters for machine learning in detail. A dataset resized with a
naive-sampling routine has aliased artefacts that vary with the first
detail, and a network will happily learn them.

## Bilinear, worked, and why masks forbid it

Bilinear interpolation reads the four input pixels around a fractional spot and
takes a distance-weighted mean &mdash; linear across, then linear down. For an
output point landing at fraction (0.25, 0.75) inside a cell whose corners are 10
(top-left), 20 (top-right), 30 (bottom-left), 40 (bottom-right):

|step|value|
|---|---|
|top edge: 10&middot;0.75 + 20&middot;0.25|12.5|
|bottom edge: 30&middot;0.75 + 40&middot;0.25|32.5|
|down: 12.5&middot;0.25 + 32.5&middot;0.75|**27.5**|

The output 27.5 is a value that never appeared in the input. That is the whole
point for a photo: it smooths the staircase that nearest neighbour would leave.

But a *label mask* must never be resized this way. If 3 means "road" and 5
means "sky", a blend of 4 might be a class that is neither. Class labels are
names, not amounts, and names cannot be mixed. Use nearest neighbour for masks.

Shrinking is a third case. Keeping each second pixel can alias &mdash; a striped
pattern can vanish or flip &mdash; so you need to blur first (area method), not
guess between samples.

Bicubic uses sixteen nearby pixels with a cubic weight that overshoots slightly
at edges. That adds a little local contrast, which is why photo editors default
to it. The overshoot can also leave faint halos beside sharp edges.

Shrinking trips people up in a different way. Keeping each second pixel of a
stripe pattern can return a solid block of one colour, because detail finer than
the new grid shows up as a false pattern. That is aliasing &mdash; the same
effect as moiré on a striped shirt on video. The fix is to blur before sampling
(area method, or a Gaussian blur, which is what an image pyramid does). It
matters for ML too: a dataset resized by naive sampling carries false patterns
that vary with the input detail, and a network will learn them.

## Where it goes wrong

**Bilinear on a label mask.** Blending class indices makes indices that
mean a thing else. Nearest neighbour, always.

**Enlarging to fix a low-detail input.** Upscaling before feeding a model
adds no info and costs work. Learned super-detail is a
different thing fully &mdash; it hallucinates plausible detail from a prior,
which is handy for viewing and dangerous for reading.

**Repeated resizes.** Each interpolation softens. Resize once from the first
rather than in steps.

**Skipping aspect ratio.** Stretching to a square distorts each shape in the
frame. Pad to the target aspect ratio, then resize.

## Nearest, bilinear, and why downscaling needs a blur first

Resizing asks for pixel values at coords that don't exist. Each method is a guess. This measures three guesses against a known ground truth. Then shows the failure that catches everyone -- that shrinking an image right isn't an interpolation problem at all.

```python-run
import numpy as np

def f(y, x):
    return 128 + 90*np.sin(x*0.55)*np.cos(y*0.42) + 20*np.sin(x*0.2 + y*0.3)

H, W, SY, SX = 8, 10, 3, 3
OH, OW = H * SY, W * SX
src = f(*np.mgrid[0:H, 0:W])

def coords(o, s, scale):
    return (np.arange(o) + 0.5) / scale - 0.5

def nearest(a, oh, ow):
    yy = np.clip(np.round(coords(oh, a.shape[0], SY)).astype(int), 0, a.shape[0]-1)
    xx = np.clip(np.round(coords(ow, a.shape[1], SX)).astype(int), 0, a.shape[1]-1)
    return a[np.ix_(yy, xx)]

def bilinear(a, oh, ow):
    cy = np.clip(coords(oh, a.shape[0], SY), 0, a.shape[0]-1)
    cx = np.clip(coords(ow, a.shape[1], SX), 0, a.shape[1]-1)
    y0 = np.floor(cy).astype(int); y1 = np.minimum(y0+1, a.shape[0]-1)
    x0 = np.floor(cx).astype(int); x1 = np.minimum(x0+1, a.shape[1]-1)
    wy = (cy - y0)[:, None]; wx = (cx - x0)[None, :]
    top = a[np.ix_(y0, x0)]*(1-wx) + a[np.ix_(y0, x1)]*wx
    bot = a[np.ix_(y1, x0)]*(1-wx) + a[np.ix_(y1, x1)]*wx
    return top*(1-wy) + bot*wy

truth = f(*np.meshgrid(coords(OH, H, SY), coords(OW, W, SX), indexing="ij"))
print("UPSCALING %dx%d -> %dx%d, nearest vs bilinear:" % (H, W, OH, OW))
print("%-16s %12s %12s %14s" % ("method", "mean err", "worst err", "cost/pixel"))
for name, fn, cost in (("nearest", nearest, "1 read"),
                       ("bilinear", bilinear, "4 reads")):
    out = fn(src, OH, OW)
    e = np.abs(out - truth)
    print("%-16s %12.2f %12.2f %14s" % (name, e.mean(), e.max(), cost))
print("   bilinear cuts the mean error by a large factor, for 4x the reads.")
```

Bicubic interpolation fits a cubic curve through four neighbours instead of blending two. It costs 16 reads per pixel but halves bilinear's error.

```python-run
import numpy as np
def f(y, x):
    return 128 + 90*np.sin(x*0.55)*np.cos(y*0.42) + 20*np.sin(x*0.2 + y*0.3)
H, W, SY, SX = 8, 10, 3, 3
src = f(*np.mgrid[0:H, 0:W]); OH, OW = H*SY, W*SX
def coords(o, s, scale):
    return (np.arange(o) + 0.5) / scale - 0.5
def bilinear(a, oh, ow):
    cy = np.clip(coords(oh, a.shape[0], SY), 0, a.shape[0]-1)
    cx = np.clip(coords(ow, a.shape[1], SX), 0, a.shape[1]-1)
    y0 = np.floor(cy).astype(int); y1 = np.minimum(y0+1, a.shape[0]-1)
    x0 = np.floor(cx).astype(int); x1 = np.minimum(x0+1, a.shape[1]-1)
    wy = (cy - y0)[:, None]; wx = (cx - x0)[None, :]
    top = a[np.ix_(y0, x0)]*(1-wx) + a[np.ix_(y0, x1)]*wx
    bot = a[np.ix_(y1, x0)]*(1-wx) + a[np.ix_(y1, x1)]*wx
    return top*(1-wy) + bot*wy
def cubic_w(t):
    t = np.abs(t)
    return np.where(t <= 1, 1.5*t**3 - 2.5*t**2 + 1,
                    np.where(t < 2, -0.5*t**3 + 2.5*t**2 - 4*t + 2, 0))
def bicubic(a, oh, ow):
    def axis(a, o, scale, ax):
        c = coords(o, a.shape[ax], scale)
        base = np.floor(c).astype(int)
        out = np.zeros([o if i == ax else a.shape[i] for i in range(2)])
        for k in range(-1, 3):
            idx = np.clip(base + k, 0, a.shape[ax] - 1)
            w = cubic_w(c - (base + k))
            out += np.take(a, idx, axis=ax) * (w[:, None] if ax == 0 else w[None, :])
        return out
    return axis(axis(a, oh, SY, 0), ow, SX, 1)
truth = f(*np.meshgrid(coords(OH, H, SY), coords(OW, W, SX), indexing="ij"))
b_err = np.abs(bilinear(src, OH, OW) - truth)
c_err = np.abs(bicubic(src, OH, OW) - truth)
print("BICUBIC vs BILINEAR on %dx%d -> %dx%d upscale:" % (H, W, OH, OW))
print("%-12s %10s %10s %12s" % ("method", "mean err", "max err", "cost/pixel"))
print("%-12s %10.2f %10.2f %12s" % ("bilinear", b_err.mean(), b_err.max(), "4 reads"))
print("%-12s %10.2f %10.2f %12s" % ("bicubic", c_err.mean(), c_err.max(), "16 reads"))
print("   bicubic halves bilinear's error, for 4x the memory reads.")
```

The next block examines what nearest and bilinear actually produce per-pixel, showing how nearest repeats values while bilinear smooths between them.

```python-run
import numpy as np
def f(y, x):
    return (128 + 90 * np.sin(x * 0.55) * np.cos(y * 0.42)
            + 20 * np.sin(x * 0.2 + y * 0.3))
H, W, SY, SX = 8, 10, 3, 3

    return (np.arange(o) + 0.5) / scale - 0.5
def nearest(a, oh, ow):
    yy = np.clip(np.round(coords(oh, a.shape[0], SY)).astype(int), 0, a.shape[0] - 1)
    xx = np.clip(np.round(coords(ow, a.shape[1], SX)).astype(int), 0, a.shape[1] - 1)
    return a[np.ix_(yy, xx)]
def bilinear(a, oh, ow):
    cy = np.clip(coords(oh, a.shape[0], SY), 0, a.shape[0] - 1)
    cx = np.clip(coords(ow, a.shape[1], SX), 0, a.shape[1] - 1)
    y0 = np.floor(cy).astype(int); y1 = np.minimum(y0 + 1, a.shape[0] - 1)
    x0 = np.floor(cx).astype(int); x1 = np.minimum(x0 + 1, a.shape[1] - 1)
    wy = (cy - y0)[:, None]; wx = (cx - x0)[None, :]
    top = a[np.ix_(y0, x0)] * (1 - wx) + a[np.ix_(y0, x1)] * wx
    bot = a[np.ix_(y1, x0)] * (1 - wx) + a[np.ix_(y1, x1)] * wx

print("WHAT NEAREST ACTUALLY DOES. one output row, upscaled 3x:")
print("   nearest:  " + " ".join("%4.0f" % v for v in n_out[9][:12]))
print("   bilinear: " + " ".join("%4.0f" % v for v in b_out[9][:12]))
print("   truth:    " + " ".join("%4.0f" % v for v in truth[9][:12]))
print("   nearest repeats each value 3 times -- those flat runs are the")
print("   blocky squares you see when a thumbnail is blown up.")
```

The next block shows that bilinear interpolation is not truly linear along a diagonal -- it is linear in each axis separately, which makes a curved surface.

```python-run
import numpy as np
def f(y, x):
    return (128 + 90 * np.sin(x * 0.55) * np.cos(y * 0.42)
            + 20 * np.sin(x * 0.2 + y * 0.3))
src = f(*np.mgrid[0:8, 0:10])
def bilerp_at(a, y, x):
    y0, x0 = int(np.floor(y)), int(np.floor(x))
    wy, wx = y - y0, x - x0
    return ((a[y0, x0] * (1 - wx) + a[y0, x0 + 1] * wx) * (1 - wy)
            + (a[y0 + 1, x0] * (1 - wx) + a[y0 + 1, x0 + 1] * wx) * wy)
print("BILINEAR IS NOT LINEAR IN THE COORDINATES. walk the diagonal")
print("from corner (2,3) to corner (3,4):")
print("%8s %14s %14s %10s" % ("t", "bilinear", "straight line", "gap"))
for t in (0.0, 0.25, 0.5, 0.75, 1.0):
    b = bilerp_at(src, 2 + t, 3 + t)
    line = src[2, 3] * (1 - t) + src[3, 4] * t
    print("%8.2f %14.3f %14.3f %10.3f" % (t, b, line, b - line))
print("   the endpoints agree and the middle does not. 'bilinear' means")
print("   linear in each variable SEPARATELY, which is a curved surface.")
```

The next block demonstrates the downscaling failure: subsampling a stripe pattern causes aliasing, while averaging first preserves the correct brightness.

```python-run
import numpy as np

FH, FW = 6, 48
stripes = np.where((np.arange(FW) // 2) % 2 == 0, 220.0, 40.0)
stripes = np.tile(stripes, (FH, 1))
print("DOWNSCALING FAILURE. take a fine stripe pattern:")
print("   input row (every 2 columns alternate light/dark):")
print("   " + "".join("#" if v > 128 else "." for v in stripes[0]))
print("   the true average brightness is %.0f." % stripes.mean())
print()
print("   shrink 4x by just taking every 4th column -- what 'nearest' is:")
sub = stripes[:, ::4]
print("   " + "".join("#" if v > 128 else "." for v in sub[0]))
print("   mean %.0f, and every stripe is GONE. the pattern repeats every 4"
      % sub.mean())
print("   columns and we sampled every 4 columns, so we hit the same phase")
print("   each time. that is ALIASING.")
print()
print("   now average each 4-wide block instead -- BLUR, THEN SAMPLE:")
area = stripes.reshape(FH, FW // 4, 4).mean(axis=2)
print("   " + " ".join("%3.0f" % v for v in area[0][:12]))
print("   mean %.0f, matching the input's %.0f."
      % (area.mean(), stripes.mean()))
print()
print("%-34s %12s" % ("4x downscale of the stripes", "result mean"))
print("%-34s %12.1f" % ("true input mean", stripes.mean()))
print("%-34s %12.1f" % ("subsample (nearest)", sub.mean()))
print("%-34s %12.1f" % ("area-average (blur first)", area.mean()))
print()
print("SO THE RULE SPLITS IN TWO:")
print("   UPSCALING is an interpolation problem -- use bilinear or bicubic.")
print("   DOWNSCALING is a filtering problem -- low-pass first, THEN")
print("   sample. this is the single most common resizing bug, and it")
print("   silently corrupts training data.")
```
