title: Reading Errors and Tracebacks: A Practical Guide
intro: The message is the instruction.

## The problem it solves

When Python cannot do what a line asks, it stops and prints a traceback. Read it from the <b>bottom up</b>: the last line is the error type and a plain-English description, and the line just above tells you which line of your code triggered it. Everything higher is the path that led there, which matters only once you have functions calling functions.

## Errors happen at the point of failure, not the point of the mistake

The line named in a traceback is where things <em>broke</em>, which is not always where you went wrong. A variable assigned the wrong value on line 2 may only cause an error on line 40. The traceback gives you a place to start looking, not always the culprit - so check what the values actually are before assuming the named line is at fault.

## Things to try

1. <strong>Run the first editor.</strong> Note that <em>about to fail</em> prints first: everything before the error ran normally, and execution stopped at the failing line.
2. <strong>Read it bottom-up.</strong> The last line says <code class='mono-font'>IndexError: list index out of range</code>; the line above names line 3. Three items, so the highest valid index is 2.
3. <strong>Run the second editor as-is.</strong> A NameError for <code class='mono-font'>totl</code> - a typo of <code class='mono-font'>total</code>, which is what that error almost always means.
4. <strong>Work through the rest.</strong> Comment out the NameError line, uncomment the TypeError one, and run. Repeat for ValueError and ZeroDivisionError, reading each message before fixing it.

## Where that leaves you

A traceback is read bottom-up: the last line is the error type and description, the line above is where it happened. The common types each point at a specific fix - NameError at a typo, TypeError at a conversion, ValueError at the data, IndexError and KeyError at something you asked for that is not there. The named line is where it broke, which is not always where the mistake was.
