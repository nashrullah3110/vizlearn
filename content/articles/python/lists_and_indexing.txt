intro: A row of boxes, numbered from zero.

## Start here

A list holds several values in a fixed order under one name. You write it with square brackets and commas. The order you put things in is the order they stay in, which is what separates a list from the unordered collections you will meet later.

## Why counting starts at zero

An index is best read as "how far from the start", not "which one". The first item is zero steps from the start, so it is at index 0. Once you read it that way, <code class='mono-font'>colours[2]</code> being the third colour stops feeling like a trick.

## Try it yourself

1. <strong>Run the first editor.</strong> Check that <code class='mono-font'>colours[0]</code> is <em>red</em> and <code class='mono-font'>colours[2]</code> is <em>blue</em> - the third one.
2. <strong>Ask for one too far.</strong> Add <code class='mono-font'>print(colours[4])</code> and run. Four items, so the last index is 3: Python raises <code class='mono-font'>IndexError</code> rather than inventing a value.
3. <strong>Run the second editor and watch the list change.</strong> The same list is printed three times and differs each time, because the methods modify it in place.
4. <strong>Compare the last two lines.</strong> <code class='mono-font'>sorted(stack)</code> prints in order, but the following <code class='mono-font'>print(stack)</code> shows the original untouched. Swap in <code class='mono-font'>stack.sort()</code> and the difference is obvious.

## Worth remembering

A list is an ordered, changeable row of values indexed from zero. Reading past the end raises IndexError instead of guessing, and the difference between a method that returns a new list and one that edits the original is worth learning early - it explains most beginner bugs involving None.
