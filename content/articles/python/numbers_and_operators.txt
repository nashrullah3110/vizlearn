title: Numbers and Operators: A Practical Guide
intro: Python 3 split division into two on purpose — each half is what a different kind of code actually wants.

## The problem it solves

Older languages gave you one division that returned a whole number, quietly throwing away the fraction. Python 3 decided that was a silent bug factory: true division <code class="mono-font">/</code> keeps the fraction and answers in <code class="mono-font">float</code>; floor division <code class="mono-font">//</code> is the "whole-number division" people were actually reaching for — useful for splitting a list into equal chunks, or turning seconds into minutes.

## What modulo is for

<code class="mono-font">%</code> returns the remainder after floor division: <code class="mono-font">7 % 3</code> is <code class="mono-font">1</code> because 7 is 2 threes and 1 left over. It is the operator behind the two most common checks in data work: <code class="mono-font">n % 2 == 0</code> tests whether a number is even, and <code class="mono-font">index % length</code> wraps an index around a list, which is exactly how carousels and round-robins keep from falling off the end.

## Guided experiments

1. <strong>Read the first four lines.</strong> Line by line: 3.5, then 3 (fraction thrown away), then 1 (the leftover), then 1024. Note that <code class="mono-font">7 // 2</code> gives 3 while <code class="mono-font">7 / 2</code> gives 3.5 — same inputs, different promises.
2. <strong>Check the types.</strong> In the second editor, <code class="mono-font">4 + 2.0</code> returns <code class="mono-font">6.0</code>, a float, because one operand was a float. Every operator follows this rule: the float wins.
3. <strong>Break on zero.</strong> Add <code class="mono-font">print(1 / 0)</code> to either editor and run. <code class="mono-font">ZeroDivisionError</code> is Python telling you the operation is undefined — the message names the exact line that caused it.
4. <strong>Explore modulo yourself.</strong> Replace the numbers with a few of your own, one pair at a time, and check the pattern: <code class="mono-font">x % y</code> is always between <code class="mono-font">0</code> and <code class="mono-font">y - 1</code>. That boundedness is why it is so useful for wrapping.

## In one line

Python has three division-shaped operators for three different jobs: <code class="mono-font">/</code> when you want the exact answer, <code class="mono-font">//</code> when you want whole-number chunks, and <code class="mono-font">%</code> when you want the remainder that chunking throws away. Getting the right one wrong is a classic source of bugs that produce no error at all — the program just silently rounds. When numbers misbehave, check your operators before your logic.
