intro: A neural network is one operation repeated: multiply by a matrix, add a bias, bend the result. Depth is just how many times you do it.

## One layer, written out

Each layer takes the previous layer's output and applies

a<sup>(l)</sup> = f(W<sup>(l)</sup> a<sup>(l&minus;1)</sup> + b<sup>(l)</sup>)

where W is a weight matrix, b is a bias vector, and f is the activation. Stack these and the network can represent increasingly complex functions &mdash; but only because f is non-linear. Remove it and the whole stack collapses into a single matrix.

## Counting the parameters

Take 4 input features &rarr; one hidden layer of 8 &rarr; 3 output classes.

- Input to hidden: <span class="mono-font">4 &times; 8 = 32</span> weights, plus 8 biases = <strong>40</strong>
- Hidden to output: <span class="mono-font">8 &times; 3 = 24</span> weights, plus 3 biases = <strong>27</strong>
- Total: <strong>67 learnable parameters</strong>

Add a second hidden layer of 8 and you insert another <span class="mono-font">8 &times; 8 + 8 = 72</span> &mdash; more than doubling the model. Parameter count grows with the <em>product</em> of adjacent layer widths, which is why wide layers next to each other get expensive fast.

## Why stacking layers buys anything

A layer computes a weighted sum and applies an activation. Stack two <em>linear</em> layers and you have gained nothing at all: the composition of two matrix multiplications is another matrix multiplication, so a hundred linear layers collapse to a single equivalent one.

The activation is what breaks that collapse. Because it is non-linear, the composition cannot be flattened, and each additional layer can express something the previous one could not. This is the entire reason depth exists &mdash; remove the activations and a deep network is exactly as powerful as logistic regression, however many layers it has.

## What the hidden layers represent

The universal approximation theorem says one sufficiently wide hidden layer can approximate any continuous function to arbitrary accuracy. That is reassuring and almost useless in practice, because “sufficiently wide” can mean exponentially many neurons.

Depth is what makes it tractable. Layers build features hierarchically: in a vision network the first layer responds to edges, the second to corners and textures assembled from those edges, the third to object parts, and so on. Each layer reuses the previous layer’s features rather than rediscovering them, so a deep network needs far fewer neurons than a shallow one to express the same function.

## Choosing width and depth

There is no formula, but there are reliable starting points. Begin with one or two hidden layers for tabular data; deeper networks rarely help there and images or sequences are better served by architectures designed for them. Set the width somewhere between the input and output sizes, and prefer a rough funnel &mdash; wider near the input, narrowing toward the output.

Then let the training curves decide. If the model cannot drive training loss down it lacks capacity, so widen or deepen it. If training loss is near zero while validation loss climbs, it has too much capacity for the data available, and the answer is regularisation or more data rather than a smaller network. Increase capacity until the model can overfit, then regularise back &mdash; that order is far more reliable than guessing an architecture up front.

## Layers of weighted sums, with a bend between them

A neural network is a chain of very simple operations. Each layer takes a vector of numbers, multiplies it by a matrix of weights, adds a bias, and pushes the result through a non-linear function.

<p class="mono-font">a<sup>(1)</sup> = f(W<sup>(1)</sup>x + b<sup>(1)</sup>)&nbsp;&nbsp;&rarr;&nbsp;&nbsp;a<sup>(2)</sup> = f(W<sup>(2)</sup>a<sup>(1)</sup> + b<sup>(2)</sup>)&nbsp;&nbsp;&rarr;&nbsp;&nbsp;&hellip;</p>

That is the whole forward pass. A network with 175 billion parameters is doing exactly this, many times.

The three parts of the architecture:

- <strong>Input layer</strong> &mdash; one unit per feature. Not really a layer; it holds the data.
- <strong>Hidden layers</strong> &mdash; where the representation is built. "Deep" simply means more than one or two.
- <strong>Output layer</strong> &mdash; one unit per class for classification, one for a single regression target.

## Why the non-linearity is the whole point

Remove the activation function and stack two layers: `W₂(W₁x) = (W₂W₁)x`. That is a single matrix. A hundred stacked linear layers can express exactly what one can &mdash; a straight boundary.

Insert a non-linear bend between them, and the layers stop collapsing. Each one can reshape the space the next one sees, so the network can represent curves, corners and disjoint regions.

This is the answer to "why not just use one very wide layer?" The universal approximation theorem says one hidden layer, made wide enough, can approximate any continuous function. In practice depth is dramatically more efficient: a function that needs an exponentially wide shallow network can often be represented by a narrow deep one, because layers <em>compose</em> features rather than enumerating them.

## What each layer learns

The layers build a hierarchy, and it is visible when you inspect trained networks.

|Depth|On images|On text|
|---|---|---|
|Layer 1|Edges, colour blobs|Character and word shapes|
|Middle|Textures, parts|Phrases, syntax|
|Deep|Objects|Meaning, topic, intent|

This is why you cannot usefully read a single weight in a deep network: a feature's influence is spread across many paths, and the meaningful units are combinations rather than individual neurons.

It is also why <strong>transfer learning</strong> works. Early layers learn primitives that apply to almost any task in the domain, so they can be reused; only the last layers are specific to the original labels.

## Training, in four steps

1. <strong>Forward pass.</strong> Push a batch through the network and get predictions.
2. <strong>Loss.</strong> Compare predictions with the truth, producing one number.
3. <strong>Backward pass.</strong> Compute how much each weight contributed to that number &mdash; the chain rule, applied backwards.
4. <strong>Update.</strong> Nudge every weight against its gradient, scaled by the learning rate.

Repeat for every batch, for many epochs. Nothing else happens. Everything else in deep learning &mdash; optimisers, normalisation, schedules, regularisation &mdash; is a refinement of one of those four steps.

## Try this above

1. Set <strong>Input Features</strong> to 4, one <strong>Hidden Layer</strong> of 8, and <strong>Output Classes</strong> to 3, then count the connections against the arithmetic above.
2. Add a second hidden layer and watch the connection count jump rather than creep.
3. Widen one hidden layer and note that the layers on <em>both</em> sides of it grow, because it participates in two weight matrices.

## What usually goes wrong

<strong>Depth without non-linearity.</strong> Stacking linear layers gains you nothing at all mathematically &mdash; it is the single most common misunderstanding about why deep networks work.<strong>A first hidden layer far wider than the input.</strong> Four inputs into a 512-unit layer adds thousands of parameters without adding any information; there were only ever four numbers to work with. Width is worth adding where there is signal to spread out, not at the front by default.

## In one line

Multiply, add a bias, bend &mdash; repeated, with the bend being the part that matters.

## The choices you actually make

|Decision|Typical answer|
|---|---|
|Hidden layers|Start with 2&ndash;3 for tabular data; use a proven architecture for images or text|
|Units per layer|64&ndash;512, often narrowing towards the output|
|Hidden activation|ReLU, or GELU in transformers|
|Output activation|None for regression, softmax for multi-class, sigmoid for multi-label|
|Loss|MSE for regression, cross-entropy for classification|
|Optimiser|AdamW|
|Learning rate|1e-3 for Adam, then tune &mdash; the most important hyperparameter|
|Batch size|32&ndash;256, as large as memory allows|
|Regularisation|Weight decay, dropout, early stopping|

Two notes on that table. The output layer usually has <em>no</em> activation in modern frameworks, because the loss function applies softmax or sigmoid internally in a numerically stable way &mdash; applying it twice is a real and quiet bug. And the learning rate deserves its label: it affects results more than the number of layers, the width, or the choice of optimiser.

## When a neural network is the wrong tool

Deep learning is not the default answer to a modelling problem. It wins decisively on <strong>unstructured</strong> data &mdash; images, audio, text, video &mdash; where the raw input has spatial or sequential structure a network can exploit.

On <strong>tabular</strong> data, gradient-boosted trees usually match or beat a neural network while needing less tuning, less data and no GPU. This has been tested repeatedly and the result is consistent.

Three other reasons to look elsewhere: you have a few hundred rows, you need to explain each decision to a regulator, or you need the model to extrapolate outside the range it was trained on.

## Common mistakes

- <strong>Forgetting to scale the inputs.</strong> Networks assume roughly unit-scale features; unscaled columns make the first layer's activations enormous and training unstable.
- <strong>Applying softmax in the model and again in the loss.</strong> Trains slowly, silently.
- <strong>A learning rate that is wrong by an order of magnitude.</strong> Too high diverges to `NaN`; too low crawls. Find it with a short learning-rate sweep.
- <strong>No validation set,</strong> so overfitting is invisible until deployment.
- <strong>Too big a model for the data.</strong> With a few thousand rows, a smaller network plus regularisation beats a larger one.
- <strong>Not shuffling the training data,</strong> so batches contain one class at a time and batch normalisation's statistics become meaningless.

## A whole network, forty lines, no framework

Two layers, a forward pass, a backward pass and a training loop -- on a problem a linear model cannot touch. Everything a framework does is here, just written out.

```python-run
import numpy as np

rng = np.random.default_rng(0)

# two interleaving spirals: no straight line separates them
def spiral(n, label, turns=1.6):
    t = np.linspace(0.3, turns * np.pi, n)
    r = t * 0.9
    off = label * np.pi
    x = np.column_stack([r * np.cos(t + off), r * np.sin(t + off)])
    return x + rng.normal(0, 0.12, x.shape)

X = np.vstack([spiral(220, 0), spiral(220, 1)])
y = np.r_[np.zeros(220), np.ones(220)].reshape(-1, 1)
perm = rng.permutation(len(X))
X, y = X[perm], y[perm]
split = 330
Xtr, Xte, ytr, yte = X[:split], X[split:], y[:split], y[split:]
print("two interleaving spirals: %d train rows, %d test rows, 2 features."
      % (len(Xtr), len(Xte)))
print()

# a linear model, for reference
w_lin = np.linalg.lstsq(np.column_stack([Xtr, np.ones(len(Xtr))]), ytr, rcond=None)[0]
lin_pred = (np.column_stack([Xte, np.ones(len(Xte))]) @ w_lin > 0.5)
print("logistic-style linear fit: test accuracy %.4f  <- barely better than"
      % (lin_pred == (yte > 0.5)).mean())
print("guessing, because the classes wrap around each other.")
print()

H = 24
W1 = rng.normal(0, np.sqrt(2 / 2), (2, H)); b1 = np.zeros((1, H))
W2 = rng.normal(0, np.sqrt(2 / H), (H, 1)); b2 = np.zeros((1, 1))
print("a network: 2 -> %d (relu) -> 1 (sigmoid). %d parameters."
      % (H, W1.size + b1.size + W2.size + b2.size))
print()

def forward(Xb):
    z1 = Xb @ W1 + b1
    a1 = np.maximum(0, z1)
    z2 = a1 @ W2 + b2
    a2 = 1 / (1 + np.exp(-z2))
    return z1, a1, a2

def bce(a2, yb):
    a2 = np.clip(a2, 1e-9, 1 - 1e-9)
    return -np.mean(yb * np.log(a2) + (1 - yb) * np.log(1 - a2))

lr, n = 0.5, len(Xtr)
print("%8s %12s %12s %12s" % ("epoch", "train loss", "train acc", "test acc"))
for epoch in range(2001):
    z1, a1, a2 = forward(Xtr)
    if epoch % 400 == 0:
        _, _, te = forward(Xte)
        print("%8d %12.6f %12.4f %12.4f"
              % (epoch, bce(a2, ytr), ((a2 > 0.5) == (ytr > 0.5)).mean(),
                 ((te > 0.5) == (yte > 0.5)).mean()))
    dz2 = (a2 - ytr) / n
    dW2 = a1.T @ dz2
    db2 = dz2.sum(axis=0, keepdims=True)
    dz1 = (dz2 @ W2.T) * (z1 > 0)
    dW1 = Xtr.T @ dz1
    db1 = dz1.sum(axis=0, keepdims=True)
    W2 -= lr * dW2; b2 -= lr * db2
    W1 -= lr * dW1; b1 -= lr * db1
print()

print("that is the whole thing. eight lines of backward pass and four updates.")
print()

print("what the hidden layer learned -- each unit is one line through the plane:")
_, a1, _ = forward(Xte)
alive = (a1 > 0).mean(axis=0)
print("  fraction of test rows each hidden unit fires on:")
print("   ", np.round(np.sort(alive)[::-1], 3))
print("  %d of %d units are dead (never fire on any test row)."
      % ((alive == 0).sum(), H))
print("  the live ones each carve the plane with one relu boundary, and the")
print("  output layer combines them. %d straight cuts approximate a curve."
      % (alive > 0).sum())
print()

print("width is the knob that decides whether it can:")
for h in (2, 4, 8, 24, 64):
    r2 = np.random.default_rng(1)
    A1 = r2.normal(0, 1.0, (2, h)); B1 = np.zeros((1, h))
    A2 = r2.normal(0, np.sqrt(2 / h), (h, 1)); B2 = np.zeros((1, 1))
    for _ in range(2000):
        Z1 = Xtr @ A1 + B1; H1 = np.maximum(0, Z1)
        A_ = 1 / (1 + np.exp(-(H1 @ A2 + B2)))
        d2 = (A_ - ytr) / n
        dA2 = H1.T @ d2; dB2 = d2.sum(axis=0, keepdims=True)
        d1 = (d2 @ A2.T) * (Z1 > 0)
        dA1 = Xtr.T @ d1; dB1 = d1.sum(axis=0, keepdims=True)
        A2 -= 0.5 * dA2; B2 -= 0.5 * dB2; A1 -= 0.5 * dA1; B1 -= 0.5 * dB1
    Ht = np.maximum(0, Xte @ A1 + B1)
    acc = ((1 / (1 + np.exp(-(Ht @ A2 + B2))) > 0.5) == (yte > 0.5)).mean()
    print("  %2d hidden units (%3d parameters): test accuracy %.4f"
          % (h, 2 * h + h + h + 1, acc))
print()
print("two units cannot do it -- two lines are not enough boundary. by 8 it")
print("is solved. that is the universal approximation theorem in practice:")
print("enough hidden units can approximate any continuous function, and the")
print("theorem says nothing at all about how many 'enough' is, or whether")
print("gradient descent will find them.")
```

## Questions people ask

<strong>How many layers should I use?</strong> For tabular data, two or three. For images and text, start from a proven architecture rather than designing one.

<strong>What is an epoch?</strong> One full pass through the training data. Batches are the chunks within it, and one update happens per batch.

<strong>Why does my loss go to `NaN`?</strong> Learning rate too high, a `log(0)` in the loss, or unscaled inputs. Check in that order.

<strong>Do I need a GPU?</strong> For images and text, effectively yes. For small tabular models, a CPU is fine.

<strong>How much data do I need?</strong> Thousands of examples per class as a rough floor, and far fewer if you fine-tune a pretrained model.

<strong>Why is it called a "neuron"?</strong> Historical analogy to biology. The resemblance is loose; a unit is a weighted sum with a threshold, not a cell.

## Recap in one screen

- Each layer is a matrix multiply, a bias, and a non-linear function.
- Without the non-linearity, any number of layers collapses into one.
- Layers build a hierarchy of features, which is why depth and transfer learning both work.
- Training is forward pass, loss, backward pass, update &mdash; repeated.
- Excellent on images, audio and text; usually beaten by boosted trees on tabular data.
