title: How Loss is Calculated: A Practical Guide
intro: The loss is the single number that training is allowed to care about. Every gradient in the network is a derivative of this one value.

## What a loss function has to do

A loss collapses a whole batch of predictions into one scalar, and it has to do so in a way that is differentiable &mdash; otherwise there is nothing to descend. Which function you pick depends on what you are predicting.

- <strong>Regression</strong> &mdash; mean squared error: <span class="mono-font">MSE = mean((y &minus; &#375;)<sup>2</sup>)</span>
- <strong>Classification</strong> &mdash; cross-entropy: <span class="mono-font">&minus;&Sigma; y log(&#375;)</span>

## Both, with real numbers

<strong>MSE.</strong> Predictions <span class="mono-font">[2.5, 0.0, 2.0]</span> against targets <span class="mono-font">[3.0, &minus;0.5, 2.0]</span>. The errors are 0.5, 0.5 and 0. Squared: 0.25, 0.25, 0. Mean: <strong>0.167</strong>. Squaring means one error of 2.0 costs more than four errors of 0.5.<strong>Cross-entropy.</strong> If the model gives the correct class a probability of 0.7, the loss is <span class="mono-font">&minus;ln(0.7) = 0.357</span>. If it gives that class only 0.05, the loss is <span class="mono-font">&minus;ln(0.05) = 3.00</span> &mdash; roughly eight times worse. Being confidently wrong is punished far harder than being uncertain.

## Try this above

1. Raise <strong>Batch Size</strong> and watch the reported loss steady. Averaging over more samples reduces the sample-to-sample swing without changing what is being measured.
2. Increase <strong>Dropout</strong> and note training loss climbing. That is expected &mdash; you are deliberately handicapping the network during training.
3. Add hidden capacity with <strong>Hidden</strong> and watch how quickly loss falls across <strong>Epochs</strong>.

## What usually goes wrong

<strong>Comparing loss values that are not comparable.</strong> A loss summed over a batch and a loss averaged over a batch differ by a factor of the batch size. Two runs with different batch sizes or different reduction settings are not measuring the same thing, and neither is a run that changed loss function mid-experiment.<strong>MSE on a classifier.</strong> It technically works and trains badly. When the model is confidently wrong, cross-entropy produces a large gradient and MSE produces a small one, so the model is slowest to fix exactly the errors that matter most.<strong>Unscaled regression targets.</strong> Squared error on values around 300,000 produces enormous gradients. Scale the target, or the first update will destroy the weights.

## In one line

The loss is the only thing the network is optimising &mdash; if it does not measure what you care about, nothing downstream can fix that.
