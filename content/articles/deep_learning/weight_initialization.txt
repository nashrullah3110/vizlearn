title: Weight Initialization Methods: A Practical Guide
intro: The starting values of the weights decide whether a deep network trains at all. Too small and the signal dies; too large and it explodes; all the same and the network never becomes more than one neuron wide.

## Why not zero, and why not all-equal

Initialising each weight to zero seems harmless and fully breaks the network. If all weights in a layer are identical, each neuron in that layer computes the same output, gets the same gradient. And applies the same update &mdash; so they stay identical forever. A layer of 512 such neurons has the expressive power of one.

This is the <strong>symmetry breaking</strong> problem. And it is why setup must be random. Biases can safely start at zero, since the weights now break the symmetry. The scale of the random vals matters as much as their randomness. Each layer multiplies its input by a weight matrix. So output variance is multiplied layer by layer. If the per-layer factor is below 1, outputs shrink geometrically and deep layers see almost nothing. If above 1, they grow and saturate or overflow. **Xavier** (Glorot) setup sets the variance to `2 / (fan_in + fan_out)`. It keeps variance constant through layers with tanh or sigmoid outputs. **He** (Kaiming) setup sets it to `2 / fan_in`. It accounts for the fact that ReLU zeros out half its inputs and would otherwise halve the variance at each layer. With Xavier with ReLU or He with sigmoid are common mistakes that quietly destabilise training. The network trains but converges to a worse solution. And the symptom is indistinguishable from a bad learning rate. This page shows output spreads at each layer under zero, Xavier. And He setup. And lets you switch output functions to see which pairing works.

## The variance is what really matters

Randomness alone is not enough. The <em>scale</em> of the random vals decides whether signal survives depth. Each layer multiplies its input by a weight matrix. So the variance of the outputs is multiplied layer by layer.

If that per-layer factor is below 1, outputs shrink geometrically and the deepest layers see almost nothing. If it is above 1, they grow geometrically and saturate or overflow. The target is a factor of about 1. So outputs keep roughly constant scale from the first layer to the last. And the same for gradients on the way back.

That is the whole design goal. And the named schemes are just other solutions to it:

- <strong>Xavier / Glorot</strong> &mdash; variance <span class="mono-font">2 / (n<sub>in</sub> + n<sub>out</sub>)</span>. Derived for outputs symmetric about zero. So it suits tanh and sigmoid.
- <strong>He / Kaiming</strong> &mdash; variance <span class="mono-font">2 / n<sub>in</sub></span>. ReLU zeroes negative inputs and therefore roughly halves the variance passing through. So He compensates with the extra factor of 2. This is the right default for any ReLU network.
- <strong>LeCun</strong> &mdash; variance <span class="mono-font">1 / n<sub>in</sub></span>, used with SELU and self-scaling networks.

Note that all of them scale with layer width. A 1024-unit layer needs less initial weights than a 64-unit one, since it sums many more terms.

## Why the starting point matters

Training begins from random weights. And the choice of "random" is not arbitrary. Two failure modes bracket the sensible range.

<strong>All zeros.</strong> Each unit in a layer computes the same thing, gets the same gradient. And updates identically. The layer never differentiates and behaves as a single unit forever. Symmetry must be broken. It is why the weights are random at all.

<strong>Too large or too small.</strong> Outputs either grow or shrink as they pass through layers. After twenty layers, outputs that shrink by 0.8 per layer have shrunk to 1% of their first scale. And the gradients follow. The network is dead before the first update.

The goal is a scale that keeps the variance of outputs roughly constant through depth. And that scale depends on the layer's width and its output function.

## The two schemes worth knowing

<strong>Xavier (Glorot)</strong> setup, for tanh and sigmoid:

<p class="mono-font">Var(W) = 2 / (fan_in + fan_out)</p>

<strong>He (Kaiming)</strong> setup, for ReLU:

<p class="mono-font">Var(W) = 2 / fan_in</p>

The gap is the factor of 2. And the reason is direct: ReLU zeroes half its inputs. So it halves the variance passing through. Doubling the initial variance compensates just.

|Activation|Use|
|---|---|
|ReLU, Leaky ReLU|He (`kaiming_normal_`)|
|Tanh, sigmoid|Xavier (`xavier_uniform_`)|
|GELU, SiLU|He, or the framework default|
|Linear output layer|Xavier, or small values|

With Xavier with ReLU is a real if subtle mistake: outputs shrink through depth by a factor of &radic;2 per layer. And a 30-layer network arrives at the loss with almost no signal.

```python
import torch.nn as nn

for m in model.modules():
    if isinstance(m, (nn.Conv2d, nn.Linear)):
        nn.init.kaiming_normal_(m.weight, nonlinearity="relu")
        if m.bias is not None:
            nn.init.zeros_(m.bias)
```

Biases are set up to zero. There is no symmetry problem for them, since the weights now differ.

## Special cases in modern designs

<strong>Batch normalisation's `γ` and `β`</strong> start at 1 and 0. So the layer initially passes its scaled input through unchanged.

<strong>The last block's normalisation in a residual network</strong> is sometimes set up to zero (`γ = 0`). It makes each residual block start as an exact identity. The network begins as a shallow one and deepens it as training proceeds. A trick that steadies very deep and very large nets.

<strong>Transformers</strong> often scale the setup of the output projections by 1/&radic;(2 &times; layers), since the residual stream builds up contributions from each block and would otherwise grow with depth.

<strong>Embeddings</strong> are often set up from a normal spread with a small standard deviation (0.02 is the common choice in language nets).

<strong>Orthogonal setup</strong> for recurrent weight matrices keeps the largest singular value at 1. It is just the condition that stops the hidden state exploding or vanishing over time steps.

## Exploration guide

1. <strong>Train from a reasonable start.</strong> Press <strong>Reset Weights</strong> and then <strong>Train Network</strong>. Outputs stay in a usable range across the layers and the loss falls steadily.
2. <strong>Watch the layer-to-layer scale.</strong> In training, check the output magnitudes at the first and last layers. When setup is right they are comparable. A systematic shrink or growth across depth is the failure this whole topic exists to stop.
3. <strong>Add normalisation.</strong> Enable the batch-norm toggle and press <strong>Reset Weights</strong>, then train again. Convergence turns markedly less sensitive to where the weights started. Normalisation rescales each layer regardless.
4. <strong>Reset repeatedly.</strong> Press <strong>Reset Weights</strong> a few times and train each time. Runs differ, sometimes noticeably. The initial draw is a genuine source of run-to-run variance. It is why single-run comparisons are unreliable.

## Traps worth knowing

- <strong>Zero setup.</strong> Symmetry never breaks and the layer collapses to a single effective neuron. Zero is fine for biases and wrong for weights.
- <strong>A fixed standard deviation such as 0.01 all over.</strong> Ignores layer width. So wide layers explode and deep stacks vanish. This was standard before 2010 and is a large part of why deep networks did not train.
- <strong>Xavier with ReLU.</strong> Understates the variance by a factor of 2, since Xavier does not account for ReLU discarding half the spread. Use He for ReLU.
- <strong>Assuming batch norm makes it irrelevant.</strong> Normalisation reduces the response but does not remove it, very in very deep networks and in the layers before the first normalisation.
- <strong>Reinitialising a pretrained layer.</strong> When fine-tuning, just the new head should be set up. Overwriting the pretrained weights discards all transfer learning was for.

## What to remember

Setup must be random to break symmetry. And scaled to layer width so output and gradient variance stay roughly constant with depth. He setup is the default for ReLU networks since ReLU halves the variance and He’s factor of 2 restores it. Xavier suits tanh and sigmoid. Get this wrong and a deep network either learns nothing or diverges. Before the solver has had any say in the matter.

## How much does it still matter?

Less than it did, and more than nothing.

Batch normalisation and residual connections both reduce response to setup. It is part of why they were such a breakthrough. They made deep networks trainable still from an imperfect starting point. Pretrained weights remove the question fully for transfer learning.

But it still matters in three cases: training from scratch without normalisation layers, very deep or very large nets where small per-layer errors compound. And recurrent networks where the same matrix is applied many times.

And the framework defaults are not always right. PyTorch's default for `nn.Linear` is a uniform spread based on fan-in that predates He setup. And it is not best for ReLU networks. Setting it clearly costs three lines.

## Diagnosing a bad setup

Before training, do a single forward pass and print the standard deviation of the outputs at each layer:

```python
acts = {}
for name, m in model.named_modules():
    if isinstance(m, nn.ReLU):
        m.register_forward_hook(
            lambda mod, i, o, n=name: acts.__setitem__(n, o.std().item()))

model(sample_batch)
for k, v in acts.items():
    print(f"{k:<40} std {v:.4f}")
```

Healthy: roughly close vals throughout. Shrinking towards zero with depth means the setup is too small (or Xavier was used with ReLU). Growing means it is too large. And the first gradient step will be violent.

The same check on the initial loss is worth doing: with C balanced classes it should be about ln(C). A much more value means the initial predictions are confidently wrong. It often means the output layer's weights are too large.

## Zero, too big, too small, and right

Setup decides whether a deep network trains at all. Four schemes on the same design, measured by what happens to the outputs after ten layers.

```python-run
import numpy as np

rng = np.random.default_rng(0)
WIDTH, DEPTH, N = 128, 10, 512

def propagate(scale_fn, act, name):
    a = rng.normal(size=(N, WIDTH))
    stds = []
    for _ in range(DEPTH):
        W = scale_fn(WIDTH)
        a = act(a @ W)
        stds.append(a.std())
    return name, stds

relu = lambda z: np.maximum(0, z)

print("activation std after each of %d layers (should stay constant):\n" % DEPTH)
print("%-32s %9s %9s %9s %9s" % ("scheme", "layer 1", "layer 4", "layer 7", "layer 10"))
for fn, act, name in (
    (lambda w: rng.normal(0, 0.01, (w, w)), relu, "gaussian sd 0.01 (too small)"),
    (lambda w: rng.normal(0, 1.00, (w, w)), relu, "gaussian sd 1.00 (too big)"),
    (lambda w: rng.normal(0, np.sqrt(1 / w), (w, w)), np.tanh, "Xavier/Glorot, tanh"),
    (lambda w: rng.normal(0, np.sqrt(2 / w), (w, w)), relu, "He, relu"),
):
    name, stds = propagate(fn, act, name)
    print("%-32s %9.3e %9.3e %9.3e %9.3e" % (name, stds[0], stds[3], stds[6], stds[9]))
print()
print("sd 0.01 collapses to zero -- no signal reaches the output.")
print("sd 1.00 does the opposite and saturates.")
print("He stays flat. Xavier drifts gently (tanh compresses), but compare")
print("a drift from 0.63 to 0.22 against a collapse to 1e-11.")
print("\nthe rules: Xavier variance 1/n_in (tanh/sigmoid),")
print("He variance 2/n_in (relu -- the 2 compensates for relu halving).")
```

The next block shows where the factor of 2 in He setup comes from.

```python-run
import numpy as np

relu = lambda z: np.maximum(0, z)
rng = np.random.default_rng(0)

print("where the 2 comes from: relu zeroes the negative half.\n")
z = rng.normal(0, 1.0, 400_000)
print("  E[z^2]        for the input      %.4f" % (z ** 2).mean())
print("  E[relu(z)^2]  after relu         %.4f  <- exactly half" % (relu(z) ** 2).mean())
print("  half the values became 0, so the mean of squares halves.")
print("  every layer would halve it again.\n")
z2 = rng.normal(0, np.sqrt(2.0), 400_000)
print("  with weights scaled by sqrt(2): E[relu(z)^2] = %.4f  <- restored"
      % (relu(z2) ** 2).mean())
print("  that is the whole derivation of He initialisation.")
```

Finally, the failure that is not about scale at all: all-zero weights and the symmetry problem.

```python-run
import numpy as np

rng = np.random.default_rng(0)

print("the failure that is not about scale -- all zeros:\n")
W1 = np.zeros((4, 3)); W2 = np.zeros((3, 1))
x = rng.normal(size=(8, 4)); y = rng.normal(size=(8, 1))
for step in range(50):
    h = np.tanh(x @ W1)
    out = h @ W2
    d_out = 2 * (out - y) / len(x)
    dW2 = h.T @ d_out
    dW1 = x.T @ ((d_out @ W2.T) * (1 - h ** 2))
    W1 -= 0.1 * dW1; W2 -= 0.1 * dW2
print("  after 50 steps, the hidden layer's weights:")
print(np.round(W1, 6))
print("  every column is identical. all three hidden units computed the")
print("  same thing, received the same gradient, and updated identically.")
print("  a layer of n units with the same values is a layer of 1 unit.\n")
print("initialisation must be RANDOM, not merely small. randomness breaks")
print("the symmetry between units, and no amount of training breaks it later.\n")
print("biases are the exception -- zero is fine because the weights already")
print("broke the symmetry.")
```

## Questions people ask

<strong>Can I set up all weights to the same non-zero value?</strong> No. The symmetry problem is identical to with zeros. Units must start other.

<strong>Should biases be zero?</strong> Yes, almost always. One exception: setting the output bias of a binary sorter to the log-odds of the positive class speeds up early training on imbalanced data.

<strong>Normal or uniform?</strong> Barely matters &mdash; the variance is what counts. Both are provided for both schemes.

<strong>What about fine-tuning?</strong> The pretrained weights are the setup. Just a newly added head needs initialising. And it should be small so it does not disturb the pretrained features on the first step.

<strong>Does setup affect the final result?</strong> With normalisation and residuals, often just mildly. Other seeds land at close quality. Without them, it can decide whether the net trains at all.

<strong>Why does my loss start enormous?</strong> Output-layer weights too large. Or a label/logit mismatch. Check against ln(count of classes).

## Recap in one screen

- Zeros break the network by symmetry. Wrong scales make outputs grow or vanish through depth.
- He setup (variance 2/fan_in) for ReLU. Xavier (2/(fan_in+fan_out)) for tanh and sigmoid.
- The factor of 2 in He exists since ReLU discards half the signal.
- Biases start at zero. Residual blocks are sometimes started as exact identities.
- Batch normalisation and residuals reduce response. But do not remove the need to get it roughly right.
