title: Backpropagation: A Practical Guide
intro: How a network works out what every weight did wrong, in one pass backwards.

## Quick Context

<a href="gradient_descent_training.html" style="color: var(--accent-primary)">Gradient descent</a> needs a gradient: for every weight in the network, how much the <a href="how_loss_is_calculated.html" style="color: var(--accent-primary)">loss</a> would change if that weight moved a little. Backpropagation is how that number is obtained, for millions of weights, at the cost of roughly one extra forward pass.<p>It is not a learning rule and not an optimiser. It computes derivatives, and nothing else. What to do with them is the optimiser's business.</p>

## Everything is a graph

A network is a long expression, and any expression can be drawn as a graph of small operations: multiply, add, apply a function. The graph above is a single neuron with two inputs, which is already enough to show every mechanic that matters.

m&#8321; = w&#8321;x&#8321; &nbsp; m&#8322; = w&#8322;x&#8322; &nbsp; s = m&#8321;+m&#8322; &nbsp; z = s+b &nbsp; a = &sigma;(z) &nbsp; L = (a &minus; y)&sup2;

The forward pass fills in a value at every node. Crucially, those values are kept &mdash; the backward pass needs them, which is exactly why training a network takes far more memory than running one.

## Each operation knows one thing

Every node needs only its <em>local</em> derivative: how its output responds to its own inputs. It has no idea what the rest of the network looks like, and does not need to.

- <strong>Add</strong> passes the gradient through unchanged to both inputs. This is why <span class="mono-font">&part;L/&part;b</span> equals <span class="mono-font">&part;L/&part;z</span> exactly, every time.
- <strong>Multiply</strong> hands each input the gradient scaled by the <em>other</em> input. So <span class="mono-font">&part;L/&part;w&#8321; = &part;L/&part;m&#8321; &middot; x&#8321;</span> &mdash; a weight's gradient is proportional to the input it was multiplying, which is why an input of zero produces a gradient of zero and why unscaled features distort learning.
- <strong>The sigmoid</strong> contributes <span class="mono-font">a(1 &minus; a)</span>, which peaks at 0.25 and falls to nearly nothing when the neuron saturates.

The chain rule then says: the gradient arriving at a node, times the node's local derivative, is the gradient leaving it. Backpropagation is that single sentence applied repeatedly, in reverse topological order.

## Assigning blame to every weight

Training needs one number per weight: if I nudge this weight slightly, how much does the loss change? With ten million weights, computing that separately ten million times is impossible.

Backpropagation gets all of them in a single backward pass, at roughly the cost of one forward pass. That efficiency is the reason deep learning is practical at all.

The mechanism is the chain rule. A network is nested functions, so the effect of an early weight on the loss is a product of factors, one per layer in between:

<p class="mono-font">&part;L/&part;w<sup>(1)</sup> = &part;L/&part;a<sup>(3)</sup> &times; &part;a<sup>(3)</sup>/&part;a<sup>(2)</sup> &times; &part;a<sup>(2)</sup>/&part;a<sup>(1)</sup> &times; &part;a<sup>(1)</sup>/&part;w<sup>(1)</sup></p>

Computed naively, weights in the same layer would each redo most of that product. Backpropagation works from the loss backwards, carrying the accumulated product with it, and hands each layer exactly the factor it needs. Nothing is recomputed.

## One neuron, worked through with numbers

A single neuron: `z = wx + b`, `a = sigmoid(z)`, loss `L = (a − y)²`.

Take x = 2, w = 0.5, b = 0, y = 1.

<strong>Forward:</strong> z = 1.0, a = sigmoid(1.0) = 0.731, L = (0.731 − 1)² = 0.072.

<strong>Backward,</strong> three factors:

- &part;L/&part;a = 2(a − y) = 2(−0.269) = −0.538
- &part;a/&part;z = a(1 − a) = 0.731 × 0.269 = 0.197
- &part;z/&part;w = x = 2

<strong>Multiply:</strong> &part;L/&part;w = −0.538 × 0.197 × 2 = <strong>−0.212</strong>

Negative, so increasing w lowers the loss. With a learning rate of 0.1 the update is w ← 0.5 + 0.0212 = 0.521 &mdash; a small step in the right direction, which is exactly what gradient descent is.

Notice `a(1 − a)`: it peaks at 0.25 and approaches zero when the neuron saturates near 0 or 1. A confidently wrong sigmoid neuron therefore learns very slowly, which is precisely the argument for cross-entropy loss, whose derivative cancels that term.

## Why the forward pass must be remembered

The backward pass needs the activations computed on the way forward &mdash; `a(1 − a)` needs `a`. So every intermediate result is stored during the forward pass and kept until the backward pass consumes it.

That storage is <strong>activation memory</strong>, and it is what usually limits batch size, not the weights. A ResNet-50's weights are about 100MB; its activations for a batch of 64 images run to several gigabytes.

Two standard responses. <strong>Gradient checkpointing</strong> stores only some activations and recomputes the rest during the backward pass &mdash; trading roughly 30% more compute for a large memory saving. And <strong>mixed precision</strong> stores activations in 16-bit, halving the memory and speeding up the arithmetic.

This also explains why `torch.no_grad()` matters at inference: without gradients, nothing needs to be stored, and memory use drops sharply.

## Exploration guide

1. <strong>Start from the loss.</strong> The page opens with the forward pass already done: values left to right, ending on a single number. Press Reset and Step if you want to watch that part happen too &mdash; but it holds no surprises, it is just the network making a prediction.
2. <strong>Keep stepping.</strong> The gradient starts at the loss as 1, then flows right to left. Each node prints the multiplication it performed, so you can read the chain rule rather than take it on faith.
3. <strong>Compare the two weight gradients.</strong> They differ only by their input: &part;L/&part;w&#8321; carries x&#8321; and &part;L/&part;w&#8322; carries x&#8322;. Set <strong>Input x1</strong> to 0 and its weight's gradient goes to exactly zero &mdash; that weight cannot learn from this example at all.
4. <strong>Check the answer.</strong> The gradient-check panel recomputes &part;L/&part;w&#8321; numerically, by nudging w&#8321; and dividing the change in loss by the change in weight. It agrees with the chain rule to several decimal places, which is the test to reach for whenever a hand-written backward pass looks suspicious.
5. <strong>Saturate the neuron.</strong> Push <strong>Weight w1</strong> and <strong>Bias b</strong> to their maximums so that z is large. The sigmoid flattens, a(1 &minus; a) collapses towards zero, and every gradient behind it shrinks with it. That is <a href="vanishing_vs_exploding_gradient.html" style="color: var(--accent-primary)">the vanishing gradient</a>, visible in one number.
6. <strong>Close the gap.</strong> Drag <strong>Target y</strong> towards the prediction a. The loss collapses and every gradient in the graph shrinks with it, because the whole chain is scaled by 2(a &minus; y) &mdash; when there is nothing left to fix, nothing moves.

## Why it is fast

The obvious way to get gradients is to nudge each weight and re-run the network, exactly as the gradient check does. That costs one forward pass per weight; on a model with a million weights it is hopeless.

Backpropagation gets all of them in one backward pass, because the gradient arriving at a node is shared by everything feeding it. Work is reused rather than repeated &mdash; the same insight that makes dynamic programming fast. This is reverse-mode automatic differentiation, and it is what every deep learning framework implements underneath <span class="mono-font">loss.backward()</span>.

## What trips people up

- <strong>Forgetting to zero the gradients.</strong> Frameworks accumulate into <span class="mono-font">.grad</span> by design, so that a batch can be split across several backward passes. Omit the reset and you are descending on the sum of every batch so far.
- <strong>Saturation.</strong> Sigmoid and tanh have tiny derivatives at their extremes, and a product of tiny numbers vanishes. This is the reason ReLU and its relatives took over, and the reason weight initialisation is treated so carefully.
- <strong>Exploding gradients.</strong> The mirror image: repeated multiplication by numbers above one, common in deep or recurrent stacks. Gradient clipping exists for this.
- <strong>Detaching by accident.</strong> Convert a tensor to a plain number mid-network and the graph is cut there; everything behind it silently gets no gradient at all.
- <strong>Trusting the derivation.</strong> If you write a backward pass by hand, check it numerically. It takes five lines and it finds sign errors immediately.

## Where that leaves you

Backpropagation is the chain rule applied to a computational graph in reverse order: each operation contributes only its own local derivative, and the gradient arriving from downstream is multiplied by it on the way past. An add passes the gradient through untouched, a multiply scales it by the other input, and a saturating activation shrinks it &mdash; which is where vanishing gradients come from. Because every node reuses the gradient already computed for the nodes it feeds, one backward pass yields every weight's gradient at roughly the cost of one forward pass, and that efficiency is the reason training deep networks is possible at all. The forward values have to be kept in memory for it to work, and a numeric gradient check is the fastest way to prove your backward pass is right.

## What goes wrong, and why

Because the chain rule multiplies one factor per layer, deep networks multiply many numbers together &mdash; and that is numerically unstable in both directions.

<strong>Vanishing gradients.</strong> Sigmoid's derivative peaks at 0.25. Ten layers gives 0.25¹⁰ ≈ 0.000001, so early layers barely move. The fixes all target the size of those factors: ReLU (derivative exactly 1 when active), residual connections (an identity path whose derivative is 1), and normalisation layers (which keep activations where the factors stay near 1).

<strong>Exploding gradients.</strong> If the factors average above 1, the product grows without bound and weights become `NaN`. Gradient clipping caps the gradient's norm directly and is standard in recurrent models and transformers.

<strong>Dead ReLUs.</strong> A unit stuck on the negative side has a derivative of exactly 0, receives no gradient, and never recovers. Leaky ReLU, careful initialisation and a lower learning rate all reduce it.

Diagnosing all three is the same action: log the gradient norm per layer. A healthy network shows similar magnitudes throughout; a vanishing one shows orders of magnitude of decay from output to input.

## Automatic differentiation in practice

You will never implement backpropagation by hand. Frameworks record every operation into a graph as the forward pass runs, then walk it backwards applying each operation's known derivative rule.

```python
loss = criterion(model(x), y)

optimizer.zero_grad()    # clear the previous step's gradients
loss.backward()          # backpropagation: fills .grad on every parameter
optimizer.step()         # apply the update
```

The `zero_grad()` line is not optional. PyTorch <em>accumulates</em> gradients into `.grad` rather than replacing them, so forgetting it means each step uses the sum of all previous gradients &mdash; training appears to work and converges to nonsense. (The accumulation behaviour is deliberate: it is how you simulate a large batch on a small GPU, by calling `backward()` several times before `step()`.)

To verify a hand-written gradient, compare it with a numerical one: `(f(x+h) − f(x−h)) / 2h` with h around 1e-5. If they disagree, the analytic version is wrong.

## Every gradient, by hand, checked numerically

Backpropagation is the chain rule applied backwards through a network. Here is a two-layer net where every partial derivative is computed twice -- analytically and numerically -- so you can see they agree.

```python-run
import numpy as np

rng = np.random.default_rng(0)
X = rng.normal(size=(6, 3))
y = rng.integers(0, 2, (6, 1)).astype(float)

W1 = rng.normal(0, 0.5, (3, 4)); b1 = np.zeros((1, 4))
W2 = rng.normal(0, 0.5, (4, 1)); b2 = np.zeros((1, 1))

def sigmoid(z):
    return 1 / (1 + np.exp(-z))

def forward(W1, b1, W2, b2):
    z1 = X @ W1 + b1
    a1 = np.tanh(z1)
    z2 = a1 @ W2 + b2
    a2 = sigmoid(z2)
    loss = -np.mean(y * np.log(a2) + (1 - y) * np.log(1 - a2))
    return z1, a1, z2, a2, loss

z1, a1, z2, a2, loss = forward(W1, b1, W2, b2)
print("forward pass on %d rows: loss %.6f" % (len(X), loss))
print("  x %s -> z1 %s -> a1 %s -> z2 %s -> a2 %s"
      % (X.shape, z1.shape, a1.shape, z2.shape, a2.shape))
print()

print("now walk it backwards. each line is one application of the chain rule:")
n = len(X)
# dL/dz2 for sigmoid + binary cross-entropy collapses to (a2 - y)/n
dz2 = (a2 - y) / n
print("  dL/dz2 = (a2 - y)/n           shape %s" % (dz2.shape,))
dW2 = a1.T @ dz2
db2 = dz2.sum(axis=0, keepdims=True)
print("  dL/dW2 = a1.T @ dL/dz2        shape %s" % (dW2.shape,))
print("  dL/db2 = sum(dL/dz2)          shape %s" % (db2.shape,))
da1 = dz2 @ W2.T
print("  dL/da1 = dL/dz2 @ W2.T        shape %s" % (da1.shape,))
dz1 = da1 * (1 - np.tanh(z1) ** 2)
print("  dL/dz1 = dL/da1 * tanh'(z1)   shape %s" % (dz1.shape,))
dW1 = X.T @ dz1
db1 = dz1.sum(axis=0, keepdims=True)
print("  dL/dW1 = X.T @ dL/dz1         shape %s" % (dW1.shape,))
print("  dL/db1 = sum(dL/dz1)          shape %s" % (db1.shape,))
print()
print("every gradient has the same shape as the thing it updates. that is not")
print("a coincidence -- it is what makes 'W -= lr * dW' type-check.")
print()

print("the check that proves it. nudge each parameter and measure the loss:")
def numeric(param, i, j, h=1e-6):
    up = [W1.copy(), b1.copy(), W2.copy(), b2.copy()]
    dn = [W1.copy(), b1.copy(), W2.copy(), b2.copy()]
    up[param][i, j] += h
    dn[param][i, j] -= h
    return (forward(*up)[4] - forward(*dn)[4]) / (2 * h)

print("%-10s %6s %16s %16s %12s" % ("param", "index", "analytic", "numeric", "diff"))
checks = [("W1", 0, dW1, (0, 0)), ("W1", 0, dW1, (2, 3)), ("b1", 1, db1, (0, 1)),
          ("W2", 2, dW2, (1, 0)), ("W2", 2, dW2, (3, 0)), ("b2", 3, db2, (0, 0))]
worst = 0.0
for name, idx, grad, (i, j) in checks:
    a = grad[i, j]
    num = numeric(idx, i, j)
    worst = max(worst, abs(a - num))
    print("%-10s %6s %16.10f %16.10f %12.2e"
          % (name, "[%d,%d]" % (i, j), a, num, abs(a - num)))
print("  worst disagreement anywhere: %.2e" % worst)
print("  that is floating-point noise, not error. the derivation is right.")
print()

print("and it trains. 400 steps of plain gradient descent:")
lr = 0.5
for step in range(401):
    z1, a1, z2, a2, loss = forward(W1, b1, W2, b2)
    if step % 100 == 0:
        acc = ((a2 > 0.5).astype(float) == y).mean()
        print("  step %3d  loss %.6f  accuracy %.4f" % (step, loss, acc))
    dz2 = (a2 - y) / n
    dW2_ = a1.T @ dz2; db2_ = dz2.sum(axis=0, keepdims=True)
    dz1 = (dz2 @ W2.T) * (1 - np.tanh(z1) ** 2)
    dW1_ = X.T @ dz1; db1_ = dz1.sum(axis=0, keepdims=True)
    W2 -= lr * dW2_; b2 -= lr * db2_
    W1 -= lr * dW1_; b1 -= lr * db1_
print()
print("that is the entire algorithm. a forward pass that caches its")
print("intermediates, a backward pass that reuses them, and a subtraction.")
print("PyTorch's autograd is this, recorded automatically as you compute.")
```

## Questions people ask

<strong>Is backpropagation the same as gradient descent?</strong> No. Backpropagation computes the gradients; gradient descent uses them to update the weights. Two separate steps.

<strong>Why do I need to call `zero_grad()`?</strong> Because gradients accumulate by default. Omitting it is one of the most common PyTorch bugs.

<strong>Does it work through any operation?</strong> Any differentiable one. Non-differentiable steps (argmax, sampling, hard thresholds) block the gradient and need workarounds such as straight-through estimators or the reparameterisation trick.

<strong>How does it handle branching architectures?</strong> Where a value feeds several paths, the gradients from all of them are summed. That is the multivariable chain rule.

<strong>Why is training about three times a forward pass?</strong> Roughly: one forward, one backward of similar cost, plus the weight update.

<strong>Is it biologically plausible?</strong> Not really &mdash; real neurons have no known mechanism for sending precise error signals backwards. It is an engineering algorithm, not a model of the brain.

## Recap in one screen

- Backpropagation computes every weight's gradient in one backward pass using the chain rule.
- It reuses shared factors, which is why training costs about the same as a few forward passes rather than one pass per parameter.
- Activations from the forward pass must be stored, and that memory usually limits batch size.
- Multiplying many factors causes vanishing and exploding gradients; ReLU, residuals, normalisation and clipping are the responses.
- Frameworks do it automatically &mdash; but call `zero_grad()`, because gradients accumulate.
