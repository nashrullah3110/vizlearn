title: Backpropagation: A Practical Guide
intro: How a network works out what every weight did wrong, in one pass backwards.

## Quick Context

<a href="gradient_descent_training.html" style="color: var(--accent-primary)">Gradient descent</a> needs a gradient: for every weight in the network, how much the <a href="how_loss_is_calculated.html" style="color: var(--accent-primary)">loss</a> would change if that weight moved a little. Backpropagation is how that number is obtained, for millions of weights, at the cost of roughly one extra forward pass.

It is not a learning rule and not an optimiser. It computes derivatives, and nothing else. What to do with them is the optimiser's business.

## Everything is a graph

A network is a long expression, and any expression can be drawn as a graph of small operations: multiply, add, apply a function. The graph above is a single neuron with two inputs, which is already enough to show every mechanic that matters.

m&#8321; = w&#8321;x&#8321; &nbsp; m&#8322; = w&#8322;x&#8322; &nbsp; s = m&#8321;+m&#8322; &nbsp; z = s+b &nbsp; a = &sigma;(z) &nbsp; L = (a &minus; y)&sup2;

The forward pass fills in a value at every node. Crucially, those values are kept &mdash; the backward pass needs them, which is exactly why training a network takes far more memory than running one.

## Each operation knows one thing

Every node needs only its <em>local</em> derivative: how its output responds to its own inputs. It has no idea what the rest of the network looks like, and does not need to.

- <strong>Add</strong> passes the gradient through unchanged to both inputs. This is why <span class="mono-font">&part;L/&part;b</span> equals <span class="mono-font">&part;L/&part;z</span> exactly, every time.
- <strong>Multiply</strong> hands each input the gradient scaled by the <em>other</em> input. So <span class="mono-font">&part;L/&part;w&#8321; = &part;L/&part;m&#8321; &middot; x&#8321;</span> &mdash; a weight's gradient is proportional to the input it was multiplying, which is why an input of zero produces a gradient of zero and why unscaled features distort learning.
- <strong>The sigmoid</strong> contributes <span class="mono-font">a(1 &minus; a)</span>, which peaks at 0.25 and falls to nearly nothing when the neuron saturates.

The chain rule then says: the gradient arriving at a node, times the node's local derivative, is the gradient leaving it. Backpropagation is that single sentence applied repeatedly, in reverse topological order.

## Exploration guide

1. <strong>Start from the loss.</strong> The page opens with the forward pass already done: values left to right, ending on a single number. Press Reset and Step if you want to watch that part happen too &mdash; but it holds no surprises, it is just the network making a prediction.
2. <strong>Keep stepping.</strong> The gradient starts at the loss as 1, then flows right to left. Each node prints the multiplication it performed, so you can read the chain rule rather than take it on faith.
3. <strong>Compare the two weight gradients.</strong> They differ only by their input: &part;L/&part;w&#8321; carries x&#8321; and &part;L/&part;w&#8322; carries x&#8322;. Set <strong>Input x1</strong> to 0 and its weight's gradient goes to exactly zero &mdash; that weight cannot learn from this example at all.
4. <strong>Check the answer.</strong> The gradient-check panel recomputes &part;L/&part;w&#8321; numerically, by nudging w&#8321; and dividing the change in loss by the change in weight. It agrees with the chain rule to several decimal places, which is the test to reach for whenever a hand-written backward pass looks suspicious.
5. <strong>Saturate the neuron.</strong> Push <strong>Weight w1</strong> and <strong>Bias b</strong> to their maximums so that z is large. The sigmoid flattens, a(1 &minus; a) collapses towards zero, and every gradient behind it shrinks with it. That is <a href="vanishing_vs_exploding_gradient.html" style="color: var(--accent-primary)">the vanishing gradient</a>, visible in one number.
6. <strong>Close the gap.</strong> Drag <strong>Target y</strong> towards the prediction a. The loss collapses and every gradient in the graph shrinks with it, because the whole chain is scaled by 2(a &minus; y) &mdash; when there is nothing left to fix, nothing moves.

## Why it is fast

The obvious way to get gradients is to nudge each weight and re-run the network, exactly as the gradient check does. That costs one forward pass per weight; on a model with a million weights it is hopeless.

Backpropagation gets all of them in one backward pass, because the gradient arriving at a node is shared by everything feeding it. Work is reused rather than repeated &mdash; the same insight that makes dynamic programming fast. This is reverse-mode automatic differentiation, and it is what every deep learning framework implements underneath <span class="mono-font">loss.backward()</span>.

## What trips people up

- <strong>Forgetting to zero the gradients.</strong> Frameworks accumulate into <span class="mono-font">.grad</span> by design, so that a batch can be split across several backward passes. Omit the reset and you are descending on the sum of every batch so far.
- <strong>Saturation.</strong> Sigmoid and tanh have tiny derivatives at their extremes, and a product of tiny numbers vanishes. This is the reason ReLU and its relatives took over, and the reason weight initialisation is treated so carefully.
- <strong>Exploding gradients.</strong> The mirror image: repeated multiplication by numbers above one, common in deep or recurrent stacks. Gradient clipping exists for this.
- <strong>Detaching by accident.</strong> Convert a tensor to a plain number mid-network and the graph is cut there; everything behind it silently gets no gradient at all.
- <strong>Trusting the derivation.</strong> If you write a backward pass by hand, check it numerically. It takes five lines and it finds sign errors immediately.

## Where that leaves you

Backpropagation is the chain rule applied to a computational graph in reverse order: each operation contributes only its own local derivative, and the gradient arriving from downstream is multiplied by it on the way past. An add passes the gradient through untouched, a multiply scales it by the other input, and a saturating activation shrinks it &mdash; which is where vanishing gradients come from. Because every node reuses the gradient already computed for the nodes it feeds, one backward pass yields every weight's gradient at roughly the cost of one forward pass, and that efficiency is the reason training deep networks is possible at all. The forward values have to be kept in memory for it to work, and a numeric gradient check is the fastest way to prove your backward pass is right.
