title: Logarithms
intro: Logs invert powers, turn products into sums, and make ratios easier to compare.

## Read a logarithm

A logarithm answers: which exponent turns a positive number into the value I want? It reverses exponentiation, so the output of a logarithm is an exponent.

<div class="vz-math-block" role="math" aria-label="b to the power y equals x if and only if log base b of x equals y">b<sup>y</sup> = x &nbsp; ⇔ &nbsp; log<sub>b</sub>(x) = y</div>

For example, <code>log₂(8) = 3</code> because <code>2³ = 8</code>. A real logarithm needs a positive argument <code>x</code> and a positive base <code>b</code> other than 1. The graph and controls below let you change the base and argument and watch that inverse relationship.

## Turn a product into a sum

For positive <code>p</code> and <code>q</code>, the product rule is

<div class="vz-math-block" role="math" aria-label="log base b of p times q equals log base b of p plus log base b of q">log<sub>b</sub>(pq) = log<sub>b</sub>(p) + log<sub>b</sub>(q)</div>

With base 2, the demo's starting values <code>p = 8</code> and <code>q = 4</code> give <code>log₂(32) = 5</code> and <code>log₂(8) + log₂(4) = 3 + 2 = 5</code>. Both sides match. The rule does not say that <code>log(p + q)</code> equals <code>log(p) + log(q)</code>; it applies to multiplication, with the same base and positive inputs.

## Compare bases and scales

Changing the base rescales the output. You can calculate any base using natural logs:

<div class="vz-math-block" role="math" aria-label="log base b of x equals natural log of x divided by natural log of b">log<sub>b</sub>(x) = ln(x) / ln(b)</div>

For instance, <code>log₂(8) = ln(8) / ln(2) = 3</code>. Base 2 is common for bits and powers of two; <code>ln</code> means base <code>e</code>; base 10 is useful for decimal orders of magnitude. Follow the curve as you switch among the visualiser's base presets. For the displayed bases, which are all greater than 1, the logarithm increases with <code>x</code>.

The input must stay positive. As <code>x</code> approaches zero from above, <code>log<sub>b</sub>(x)</code> falls without bound; at zero or below, it is undefined over the real numbers. A logarithmic x-axis changes how horizontal distances are drawn: equal ratios such as 1→10 and 10→100 receive equal spacing. It does not change the function's values.

## Why probability calculations use logs

Independent probabilities multiply. Taking a logarithm turns that product into a sum, which avoids trying to store a very small product directly. Here is a short example: multiplying <code>0.1</code> by itself 400 times underflows to zero in ordinary floating-point arithmetic, but adding the 400 log-values remains representable.

```python-run
import math

probability = 0.1
count = 400
product = probability ** count
log_product = count * math.log(probability)

print("direct product:", product)
print("sum of log probabilities:", log_product)
print("log base 2 of 8:", math.log(8, 2))
```

For a known outcome with predicted probability <code>p</code>, the negative log-likelihood is <code>−ln(p)</code>: assigning a smaller probability gives a larger penalty. At exactly <code>p = 0</code>, this expression is infinite, so practical loss implementations use numerically stable calculations rather than taking the logarithm of a zero probability directly.
