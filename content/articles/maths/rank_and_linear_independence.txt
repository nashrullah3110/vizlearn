title: Rank and Linear Independence: A Practical Guide
intro: How many directions a matrix actually has, as opposed to how many columns it was written with.

## Quick Context

Two columns are <strong>linearly independent</strong> when neither one can be built out of the other. When they are, the combinations <span class="mono-font">s&middot;c&#8321; + t&middot;c&#8322;</span> sweep out the whole plane. When one is a multiple of the other, everything you can build lies on a single line, no matter how hard you pull on s and t.

The <strong>rank</strong> is the count of genuinely independent directions &mdash; the dimension of what the columns can reach. Two columns can have rank 2, rank 1, or rank 0 if both are zero. They can never have rank 3, which is the first useful fact: rank is capped by the number of rows as well as the number of columns.

## Ways of saying the same thing

For a square matrix, all of these are one statement:

- the columns are linearly dependent;
- the <a href="determinant.html" style="color: var(--accent-primary)">determinant</a> is zero;
- the rank is less than the number of columns;
- the matrix has no inverse;
- <span class="mono-font">Ax = 0</span> has a solution other than x = 0;
- at least one <a href="eigenvalues_and_eigenvectors.html" style="color: var(--accent-primary)">eigenvalue</a> is zero.

Column rank always equals row rank, which is a genuinely surprising theorem: the number of independent columns and the number of independent rows are the same number, whatever shape the matrix is.

## Try it yourself

1. <strong>Start independent.</strong> c&#8321; = (2, 1), c&#8322; = (1, 2). The determinant is 3, the rank is 2, and the reachable dots fill the plane in a lattice.
2. <strong>Collapse it.</strong> Press <strong>Make Column 2 A Multiple Of Column 1</strong>. c&#8322; becomes 1.5&times;c&#8321; = (3.0, 1.5), the determinant goes to exactly 0 and every dot falls onto one line. Adding a second column bought you nothing.
3. <strong>Nudge it back.</strong> Move <strong>Column 2 y</strong> by a single notch. The rank jumps straight back to 2 &mdash; rank is a count, so it does not degrade gradually, it steps. That is also why "nearly dependent" needs a different measure entirely.
4. <strong>Try the near-miss.</strong> Set c&#8322; to (3.0, 1.6) instead: the determinant is 0.20, technically rank 2, and the lattice is stretched into a nearly-flat sliver. This is what collinear features look like, and why a fit on them is unstable.
5. <strong>Zero a column.</strong> Set both of c&#8322;'s components to 0. Rank 1 again: a zero column contributes no direction at all.
6. <strong>Zero both.</strong> Rank 0, and the only reachable point is the origin.

## Where this bites in practice

- <strong>The dummy variable trap.</strong> One-hot encode a category into k columns and keep an intercept, and the k dummies sum to the intercept column exactly. The design matrix is rank deficient, <span class="mono-font">X&#7488;X</span> is singular, and ordinary least squares has no unique solution. Dropping one dummy fixes it.
- <strong>Duplicated features.</strong> Height in cm and height in inches are one direction written twice. The rank does not go up; the instability does.
- <strong>More features than rows.</strong> With p &gt; n the rank is at most n, so the columns are guaranteed dependent and the model can fit the training data perfectly for reasons that have nothing to do with the data. Regularisation is the standard answer.
- <strong>Low-rank approximation.</strong> Keeping only the strongest few directions of a matrix is what <a href="../machine_learning/pca.html" style="color: var(--accent-primary)">PCA</a> does, and what the "low rank" in <a href="../gen_ai/lora_in_llms.html" style="color: var(--accent-primary)">LoRA</a> refers to: a big weight update approximated by the product of two thin matrices, because the update did not need every direction.

## Worth remembering

Rank counts the independent directions a matrix's columns actually provide, which is the dimension of everything they can reach. Full rank means the span is as large as it could be and the matrix is invertible; a drop in rank means one column was a combination of the others, the determinant is zero, and both the inverse and the unique solution to Ax = b disappear together. Rank is a count and therefore steps rather than slides, so "nearly dependent" is a separate and more practical concern &mdash; it is what collinear features, duplicated columns and the dummy variable trap all produce, and why low-rank structure is something worth exploiting on purpose.
