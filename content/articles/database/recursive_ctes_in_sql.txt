title: Recursive CTEs for Hierarchies and Sequences
intro: A recursive common table expression repeatedly applies a query to rows it has already produced.

## The two parts
A recursive CTE has an anchor query that starts the result and a recursive term that finds the next rows. The recursive term refers to the CTE itself. Each iteration adds rows until no new rows are produced or a guard stops the process.

<pre><code>WITH RECURSIVE descendants(id, depth) AS (
  SELECT id, 0 FROM employees WHERE manager_id IS NULL
  UNION ALL
  SELECT e.id, d.depth + 1
  FROM employees AS e
  JOIN descendants AS d ON e.manager_id = d.id
  WHERE d.depth &lt; 10
)
SELECT id, depth FROM descendants;</code></pre>

The anchor starts at top-level employees; each step finds direct reports and increments depth. The depth condition is a guard, not proof that the source data is acyclic.

## Termination and cycles
A recursive query needs a reason to stop. A finite hierarchy may terminate naturally, but cycles in graph-like data can revisit a node indefinitely, especially with UNION ALL. You can carry a path or visited set to detect repeats, use a depth bound, or enforce acyclic data elsewhere. These strategies have different costs and syntax by engine.

UNION removes duplicate rows between iterations, which can sometimes stop repeated states but may be more expensive and does not solve every cycle when the recursive row includes changing state such as depth.

## When recursion fits
Recursive CTEs are useful for organizational trees, category paths, dependency walks, and generated sequences. For a known fixed number of levels, ordinary joins may be easier. Inspect limits and recursion behavior on the target engine. See [CTEs](common_table_expressions_in_sql.html).

## Carry a path to avoid revisiting nodes
For a graph with possible cycles, carry a path of visited IDs along with the current node. Before expanding to a neighbor, check that the neighbor is not already in the path. This makes cycle handling explicit, though string paths can be slow or tricky for IDs that contain delimiters; some databases offer arrays or built-in cycle clauses. Also decide whether the output should contain a node once or once per distinct path. Those are different questions and may produce very different row counts.

## Check the output grain
A recursive walk can return a node once, once per path, or once per depth depending on the columns carried through recursion and the duplicate-elimination rule. Adding depth or a path means two visits to the same node are no longer duplicate rows. That may be correct for path analysis but surprising when counting reachable nodes. Decide whether cycles are invalid, whether multiple paths matter, and what the result row represents before choosing UNION versus UNION ALL or adding a distinct step.
