title: Aggregate Functions: Count, Sum, and Average
intro: Aggregates summarize a set of rows into values; understanding NULL and empty input keeps those summaries honest.

## Start with the question
An aggregate calculates a value from several rows. <code>COUNT</code>, <code>SUM</code>, <code>AVG</code>, <code>MIN</code>, and <code>MAX</code> are common examples. They can summarize a whole result or one group at a time. The important detail is which rows each function sees, especially when a column contains <code>NULL</code>.

## What each aggregate counts
<code>COUNT(*)</code> counts rows, including rows with missing values. <code>COUNT(amount)</code> counts only rows where <code>amount</code> is not <code>NULL</code>. <code>SUM(amount)</code> and <code>AVG(amount)</code> also skip <code>NULL</code> values. <code>MIN</code> and <code>MAX</code> compare the non-NULL values. These rules mean that a count of rows and a count of known values can differ.


```sql-run
SELECT COUNT(*) AS rows,
       COUNT(amount) AS known_amounts,
       AVG(amount) AS average_amount
FROM payments;
```


If the rows contain amounts 10, NULL, and 20, the result is three rows, two known amounts, and an average of 15.

## Empty input and groups
An aggregate query without <code>GROUP BY</code> still returns one result row when its input is empty. <code>COUNT(*)</code> returns 0; most other aggregates return <code>NULL</code> because there is no value to combine. <code>COALESCE(SUM(amount), 0)</code> is appropriate only when the application means “no rows” to count as zero.

With <code>GROUP BY</code>, the database produces one output row per distinct grouping key. A group with no matching rows does not appear at all. For filtering groups by an aggregate, use <code>HAVING</code>; use <code>WHERE</code> to remove input rows before they are grouped. See [GROUP BY](groupby_in_sql.html) and [HAVING](having_in_sql.html).

## Averages need a denominator
<code>AVG(amount)</code> is equivalent to the sum of known amounts divided by their count. It is not the same as treating every missing amount as zero. For 10, NULL, and 20, the average is 15; replacing the missing value with zero changes it to 10. Choose the interpretation based on what <code>NULL</code> means in the data.

## Weighted totals and joined rows
Do not average already-calculated averages unless each group has the same number of observations. If one class has 5 students averaging 80 and another has 25 averaging 60, the overall average is weighted by 5 and 25, not the midpoint of 80 and 60. Keep each group’s sum and count if you need to combine summaries. Also check join cardinality before summing: a one-to-many join can repeat a value and inflate the total. Define the row grain first, then aggregate at that grain.
