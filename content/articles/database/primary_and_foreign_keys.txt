title: Primary and Foreign Keys
intro: Keys identify rows and express references between tables, allowing the database to enforce important identity rules.

## A primary key identifies a row
A primary key is a column or set of columns whose values uniquely identify each row and cannot be NULL. A table has one primary-key constraint, though it may contain several columns. A good key is stable and actually unique in the modeled data. SQLite has a historical exception: some non-integer primary-key declarations in ordinary rowid tables can accept NULL. Declare such columns NOT NULL explicitly or use a STRICT or WITHOUT ROWID table when relying on the rule.

A surrogate key such as an integer ID is convenient when no natural identifier is both unique and stable. Natural keys can still be useful as UNIQUE constraints. A surrogate ID does not make other real-world uniqueness rules disappear.

## A foreign key enforces a reference
A foreign key says that a value in one table must match a candidate key in another table, or be NULL if the relationship is optional.

<pre><code>CREATE TABLE orders (
  order_id INTEGER PRIMARY KEY,
  customer_id INTEGER NOT NULL REFERENCES customers(customer_id)
);</code></pre>

This prevents an order from referring to a customer row that does not exist. ON DELETE and ON UPDATE actions determine what happens when the referenced row changes; choose RESTRICT, CASCADE, or SET NULL to match the domain.

In SQLite, foreign-key enforcement must be enabled for each connection with PRAGMA foreign_keys = ON unless configured otherwise. Some engines do not automatically index the child-side foreign-key column, so add an index when joins or parent updates need it.

## Composite keys and design
A composite key uses more than one column when identity is only unique in combination, such as (course_id, student_id) in an enrollment table. If referencing it, the foreign key must include the same key columns. See [normalization](normalization_in_sql.html) and [constraints](constraints_in_sql.html).

## Optional references and uniqueness
A nullable foreign key can represent an optional relationship, but decide whether NULL means “not assigned yet” or “not applicable.” A UNIQUE constraint on a natural identifier may permit multiple NULL values in SQLite and PostgreSQL, so combine it with NOT NULL when every row must have an identifier. Composite keys can prevent duplicate pairs such as the same student enrolling twice in one course. They also enlarge foreign keys and indexes that carry the pair. Choose clarity and stability over minimizing the number of columns.
