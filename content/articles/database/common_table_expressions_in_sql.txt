title: Common Table Expressions: Name the Steps of a Query
intro: A common table expression names a query result for use by the statement that follows it.

## A query with named steps
A common table expression (CTE) is introduced with <code>WITH</code>. It can make a multi-step query easier to read because each step gets a name and can refer to earlier steps. A CTE exists for that statement; it does not create a permanent table.


```sql-run
WITH monthly AS (
  SELECT customer_id, SUM(amount) AS total
  FROM orders
  GROUP BY customer_id
)
SELECT customer_id, total
FROM monthly
WHERE total >= 500;
```


Here the first query groups orders, and the outer query filters those grouped results. The same logic could be written as a subquery; choose the form that makes the data flow easiest to follow. See [subqueries](subqueries_in_sql.html).

## CTEs do not guarantee faster execution
A CTE is a way to structure SQL, not automatically a temporary table or an optimization fence. Engines may inline, materialize, or otherwise transform it. PostgreSQL's behavior depends on features such as whether the CTE is referenced more than once and whether it is marked <code>MATERIALIZED</code>; SQLite also has materialization hints. Check the plan for the database and version you deploy.

Avoid splitting a short query into many one-use CTEs if the names obscure rather than clarify the operation. A CTE can also be referenced multiple times, but repeated work and materialization choices should be measured.

## Recursive CTEs
A recursive CTE repeatedly applies a query to rows produced by an earlier iteration. It has an anchor query for the starting rows and a recursive term for the next rows. This is useful for hierarchies, graph traversal, and generated sequences. It must have a termination condition or a guard such as a depth limit; cycles can otherwise keep producing rows. For a full walk-through, see [recursive CTEs](recursive_ctes_in_sql.html).

## Make dependencies visible
A chain of CTEs is useful when each step has a name that describes a transformation: filtered rows, grouped totals, then a final selection. Keep the sequence short enough that a reader can follow the data from the first CTE to the last. If a CTE is referenced several times, verify whether the engine recomputes it or materializes it. A CTE is also scoped to one statement; if the result must persist or be shared across statements, create a temporary or permanent table instead.
