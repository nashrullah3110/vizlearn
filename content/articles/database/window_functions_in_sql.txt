intro: Go beyond `GROUP BY` to perform calculations across sets of rows while keeping the original rows intact. This guide will make you an expert.

## Quick Context

<strong>Window functions</strong> are a powerful feature in SQL that perform a calculation across a set of table rows that are somehow related to the current row. Unlike aggregate functions (`SUM`, `COUNT`), which collapse rows into a single output row, window functions return a value for <strong>every single row</strong>.

## The Core Idea: A "Window" into Your Data

The magic of window functions is the <code>OVER()</code> clause. This clause defines the "window" or set of rows the function should consider for its calculation. It has two key components:

- <strong><code>PARTITION BY</code></strong>: This divides the rows into groups, or "partitions". The window function is applied independently to each partition. Think of it like a temporary <code>GROUP BY</code> that doesn't collapse the rows.
- <strong><code>ORDER BY</code></strong>: This sorts the rows within each partition. This is crucial for functions that depend on order, like <code>RANK()</code>, <code>LAG()</code>, and <code>LEAD()</code>.

For each row, the function calculates its result based on the other rows in its "window" (its partition).

## Common Use Cases

Window functions are essential for advanced analysis. Here are some classic problems they solve:

```
<span class="text-gray-400">-- Find the top 3 selling employees in each region</span>
SELECT * FROM (
  SELECT Name, Region, Sales,
    RANK() OVER (PARTITION BY Region ORDER BY Sales DESC) as rank_num
  FROM SalesData
) AS ranked_sales
WHERE rank_num <= 3;

<span class="text-gray-400">-- Calculate month-over-month sales growth for each department</span>
SELECT Dept, Month, Sales,
  Sales - LAG(Sales, 1, 0) OVER (PARTITION BY Dept ORDER BY Month) as sales_growth
FROM MonthlySales;
```

## The short of it

- Window functions compute a value for each row based on a "window" of related rows.
- They do <strong>not</strong> collapse rows, preserving the original table's granularity.
- <code>PARTITION BY</code> is like a temporary <code>GROUP BY</code> that defines the window.
- <code>ORDER BY</code> is essential for ranking and sequential functions (<code>LAG</code>, <code>LEAD</code>).
- Use them for ranking, running totals, moving averages, and comparing a row to its peers.
