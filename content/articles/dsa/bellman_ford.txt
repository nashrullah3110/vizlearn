title: Bellman-Ford and Negative Weights
intro: Slower than Dijkstra, but it handles what Dijkstra cannot.

## The idea in brief

<strong>Bellman-Ford</strong> finds shortest paths from one source, like Dijkstra &mdash; but it works with <em>negative</em> edge weights, and it can detect when no shortest path exists at all.

## Why Dijkstra Fails on Negative Edges

Dijkstra is greedy: once it finalises a vertex's distance, it never revisits it. That relies on an assumption &mdash; that adding more edges can only make a path longer.

A negative edge breaks it. A vertex finalised early might later be reachable more cheaply via a negative edge, but Dijkstra has already moved on. Load <strong>Has a negative edge</strong> and watch Bellman-Ford <em>improve</em> a distance in a later pass &mdash; precisely the update Dijkstra would have missed.

## Relax Everything, V−1 Times

Bellman-Ford makes no greedy commitment. It simply relaxes <em>every</em> edge, repeatedly:

Why V&minus;1 passes? A shortest path can contain at most V&minus;1 edges (any more would revisit a vertex, forming a cycle). Each pass guarantees correctness for paths one edge longer, so V&minus;1 passes settle every possible path.

This brute-force honesty costs <strong>O(V&middot;E)</strong> &mdash; considerably slower than Dijkstra's O(E log V).

## Detecting negative cycles

This is Bellman-Ford's distinctive capability, and the reason it is still used despite being slower.

If a cycle's total weight is negative, going round it again always reduces the distance. There is no shortest path &mdash; the answer is negative infinity.

The detection is elegant: after V&minus;1 rounds every genuine shortest path has been found, so <strong>if one more round still improves something, a negative cycle must be reachable</strong>. That is the final loop in the code above.

To find the cycle itself rather than merely detect it: record a predecessor for each vertex, and when the extra round relaxes an edge, walk the predecessor chain backwards V times to land inside the cycle, then trace round it.

Note the phrase "reachable from source". A negative cycle in a disconnected part of the graph does not affect the answer and will not be detected from that source.

Why Dijkstra cannot do this: it finalises each vertex once, on the assumption that no later path can be shorter. A negative edge breaks that assumption silently, so Dijkstra returns a wrong answer rather than an error &mdash; which is worse than failing.

## When Negative Weights Are Real

They sound artificial until you meet them: financial transactions with gains and losses, chemical reactions with energy release, game scoring with penalties and bonuses, or any cost model where some moves refund you.

Related algorithms worth knowing: <strong>Floyd-Warshall</strong> computes all-pairs shortest paths in O(V&sup3;) and also tolerates negative edges; <strong>Johnson's algorithm</strong> reweights a graph with Bellman-Ford so Dijkstra can then run on it safely.

## Shortest paths when weights can be negative

Dijkstra's algorithm is faster and it assumes every edge weight is non-negative. Bellman-Ford drops that assumption, and it can additionally detect when no shortest path exists at all.

The mechanism is <strong>relaxation</strong>, repeated:

<p class="mono-font">if dist[u] + weight(u,v) &lt; dist[v]: dist[v] = dist[u] + weight(u,v)</p>

Apply that to <em>every</em> edge, V&minus;1 times.

```python
def bellman_ford(n, edges, source):
    INF = float("inf")
    dist = [INF] * n
    dist[source] = 0

    for _ in range(n - 1):                    # V-1 rounds
        changed = False
        for u, v, w in edges:
            if dist[u] != INF and dist[u] + w < dist[v]:
                dist[v] = dist[u] + w
                changed = True
        if not changed:
            break                              # converged early

    for u, v, w in edges:                     # one extra round
        if dist[u] != INF and dist[u] + w < dist[v]:
            raise ValueError("negative cycle reachable from source")

    return dist
```

## Why V&minus;1 rounds

A shortest path in a graph with V vertices contains at most V&minus;1 edges &mdash; any more would repeat a vertex, and repeating a vertex means a cycle, which cannot help unless it is negative.

Each round of relaxation guarantees that all shortest paths using one more edge than before are correct. So after round 1 all one-edge shortest paths are settled, after round 2 all two-edge paths, and after V&minus;1 rounds every possible shortest path is found.

That gives O(V &times; E), which is considerably worse than Dijkstra's O((V+E) log V). The `changed` flag helps in practice &mdash; most graphs converge well before V&minus;1 rounds &mdash; and the worst case stands.

|Algorithm|Weights|Complexity|Detects negative cycles|
|---|---|---|---|
|BFS|Unweighted|O(V+E)|N/A|
|Dijkstra|Non-negative|O((V+E) log V)|No|
|Bellman-Ford|Any|O(VE)|Yes|
|Floyd-Warshall|Any, all pairs|O(V&sup3;)|Yes|
|Johnson|Any, all pairs, sparse|O(V&sup2; log V + VE)|Yes|

## Things to try

1. <strong>Run the negative-edge graph.</strong> Watch a distance get <em>improved</em> in a later pass &mdash; the exact case Dijkstra gets wrong.
2. <strong>Count the passes.</strong> V&minus;1 of them, each relaxing every single edge regardless of whether it helps.
3. <strong>Compare with the all-positive graph.</strong> Bellman-Ford still does the full V&minus;1 passes &mdash; it cannot stop early the way Dijkstra can.
4. <strong>Load the negative cycle.</strong> The extra verification pass still finds an improvement, which proves no shortest path exists.
5. <strong>Note the relaxation counter.</strong> Most edge checks change nothing &mdash; that redundancy is the price of handling negative weights.

## In one line

Bellman-Ford relaxes every edge V−1 times instead of committing greedily, so it survives negative weights at O(V·E). One extra pass turns it into a negative-cycle detector. Use Dijkstra when all weights are non-negative; reach for this when they are not.

## Where negative weights actually occur

Negative weights sound artificial, and they arise naturally in several domains.

<strong>Currency arbitrage.</strong> Take the negative logarithm of each exchange rate as the edge weight. A negative cycle then means a sequence of trades returning more currency than it started with &mdash; a risk-free profit. Detecting it is exactly Bellman-Ford's negative-cycle check, and this is a real application in financial systems.

<strong>Net cost with rebates.</strong> A route that earns a subsidy, a process step that recovers energy, a transaction with a refund &mdash; all give edges with negative net cost.

<strong>Difference constraints.</strong> Systems of inequalities of the form x&#7522; &minus; x&#7514; &le; c are solved by building a graph with edge weights c and running Bellman-Ford. Infeasibility appears as a negative cycle. This is used in scheduling and in compiler optimisation.

<strong>Reduced costs</strong> in linear programming and network flow algorithms, where potentials produce negative-weight residual edges.

So the algorithm's role is: <strong>the one to reach for when weights might be negative, and the one that tells you when the question has no answer.</strong>

## SPFA, the practical optimisation

The Shortest Path Faster Algorithm is Bellman-Ford with a queue: only relax edges leaving vertices whose distance actually changed, rather than sweeping every edge every round.

```python
from collections import deque

def spfa(n, graph, source):
    INF = float("inf")
    dist = [INF] * n
    dist[source] = 0
    in_queue = [False] * n
    count = [0] * n                            # relaxations per vertex
    q = deque([source]); in_queue[source] = True

    while q:
        u = q.popleft(); in_queue[u] = False
        for v, w in graph[u]:
            if dist[u] + w < dist[v]:
                dist[v] = dist[u] + w
                if not in_queue[v]:
                    q.append(v); in_queue[v] = True
                    count[v] += 1
                    if count[v] >= n:
                        raise ValueError("negative cycle")
    return dist
```

On typical graphs this is dramatically faster than the naive sweep &mdash; often close to O(E). Its worst case remains O(VE), and adversarial inputs exist that trigger it, so it is a practical optimisation rather than a complexity improvement.

The counter provides negative-cycle detection: a vertex entering the queue V or more times means it is being improved indefinitely.

## Distributed routing, and the count-to-infinity problem

Bellman-Ford is naturally distributed: each node needs only its neighbours' distance estimates, not global knowledge. That is why it underlies <strong>distance-vector routing protocols</strong> such as RIP, where routers exchange distance tables with neighbours.

It also has a famous failure mode there. When a link goes down, routers can slowly increment each other's estimates &mdash; A thinks it can reach the destination via B, B thinks via A &mdash; converging towards infinity one step at a time. That is the <strong>count-to-infinity</strong> problem, and the mitigations (split horizon, poison reverse, a maximum hop count of 16 in RIP) are all workarounds for it.

Link-state protocols such as OSPF avoid it by having every router build a complete map and run Dijkstra locally. That is the practical trade: Bellman-Ford needs no global view and converges slowly; Dijkstra needs the whole topology and converges immediately.

## Questions people ask

<strong>When should I use Bellman-Ford over Dijkstra?</strong> Only when weights can be negative, or when you need negative-cycle detection. Otherwise Dijkstra is much faster.

<strong>What happens if I use Dijkstra with negative weights?</strong> It returns a wrong answer without any error, because it finalises vertices too early.

<strong>Why exactly V&minus;1 rounds?</strong> A shortest path uses at most V&minus;1 edges, and each round settles paths one edge longer.

<strong>How do I find the negative cycle, not just detect it?</strong> Track predecessors; from a vertex relaxed in the extra round, walk back V times to land in the cycle, then trace it.

<strong>Is SPFA always faster?</strong> Usually, and not in the worst case &mdash; adversarial graphs still force O(VE).

<strong>What about all-pairs shortest paths with negative edges?</strong> Floyd-Warshall for dense graphs, or Johnson's algorithm (Bellman-Ford once, then Dijkstra from each vertex) for sparse ones.

## Recap in one screen

- Relax every edge V&minus;1 times; each round settles shortest paths one edge longer.
- It handles negative weights, which Dijkstra cannot &mdash; and Dijkstra fails silently rather than erroring.
- One extra round that still improves something proves a reachable negative cycle exists.
- O(VE), which is slow; SPFA's queue makes it fast in practice without improving the worst case.
- It is the basis of distance-vector routing, along with the count-to-infinity problem that follows.
