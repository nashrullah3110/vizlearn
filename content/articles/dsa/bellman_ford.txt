title: Bellman-Ford and Negative Weights
intro: Slower than Dijkstra, but it handles what Dijkstra cannot.

## The idea in brief

<strong>Bellman-Ford</strong> finds shortest paths from one source, like Dijkstra &mdash; but it works with <em>negative</em> edge weights, and it can detect when no shortest path exists at all.

## Why Dijkstra Fails on Negative Edges

Dijkstra is greedy: once it finalises a vertex's distance, it never revisits it. That relies on an assumption &mdash; that adding more edges can only make a path longer.

A negative edge breaks it. A vertex finalised early might later be reachable more cheaply via a negative edge, but Dijkstra has already moved on. Load <strong>Has a negative edge</strong> and watch Bellman-Ford <em>improve</em> a distance in a later pass &mdash; precisely the update Dijkstra would have missed.

## Relax Everything, V−1 Times

Bellman-Ford makes no greedy commitment. It simply relaxes <em>every</em> edge, repeatedly:

Why V&minus;1 passes? A shortest path can contain at most V&minus;1 edges (any more would revisit a vertex, forming a cycle). Each pass guarantees correctness for paths one edge longer, so V&minus;1 passes settle every possible path.

This brute-force honesty costs <strong>O(V&middot;E)</strong> &mdash; considerably slower than Dijkstra's O(E log V).

## Detecting Negative Cycles

If a cycle's edges sum to a negative number, you can loop it forever and drive the distance to negative infinity &mdash; no shortest path exists.

Bellman-Ford detects this elegantly. After V&minus;1 passes everything should be final, so it runs <strong>one extra pass</strong>. If any distance still improves, a negative cycle must exist. Load the third graph and watch that final pass fire.

This is not a curiosity: it is used to detect arbitrage in currency exchange, where taking the log of exchange rates turns a profitable loop into a negative cycle.

## When Negative Weights Are Real

They sound artificial until you meet them: financial transactions with gains and losses, chemical reactions with energy release, game scoring with penalties and bonuses, or any cost model where some moves refund you.

Related algorithms worth knowing: <strong>Floyd-Warshall</strong> computes all-pairs shortest paths in O(V&sup3;) and also tolerates negative edges; <strong>Johnson's algorithm</strong> reweights a graph with Bellman-Ford so Dijkstra can then run on it safely.

## Things to try

1. <strong>Run the negative-edge graph.</strong> Watch a distance get <em>improved</em> in a later pass &mdash; the exact case Dijkstra gets wrong.
2. <strong>Count the passes.</strong> V&minus;1 of them, each relaxing every single edge regardless of whether it helps.
3. <strong>Compare with the all-positive graph.</strong> Bellman-Ford still does the full V&minus;1 passes &mdash; it cannot stop early the way Dijkstra can.
4. <strong>Load the negative cycle.</strong> The extra verification pass still finds an improvement, which proves no shortest path exists.
5. <strong>Note the relaxation counter.</strong> Most edge checks change nothing &mdash; that redundancy is the price of handling negative weights.

## In one line

Bellman-Ford relaxes every edge V−1 times instead of committing greedily, so it survives negative weights at O(V·E). One extra pass turns it into a negative-cycle detector. Use Dijkstra when all weights are non-negative; reach for this when they are not.
