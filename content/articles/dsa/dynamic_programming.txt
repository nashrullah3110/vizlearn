## What this is




Dynamic programming solves overlapping subproblems once and stores their answers for reuse. It applies when a problem has a manageable set of states and an optimal solution can be built from smaller states; a recurrence defines how those states relate.

## The Two Conditions

- <strong>Overlapping subproblems</strong> &mdash; the naive recursion asks the same question repeatedly. <span class="mono-font">fib(30)</span> computes <span class="mono-font">fib(10)</span> thousands of times.
- <strong>Best substructure</strong> &mdash; the best solution is built from best solutions to subproblems. True for shortest paths and knapsack; false for problems where a locally best choice can block a better global one.

If only the first holds you can still memoise for speed. If neither holds, DP is the wrong tool.

## Memoisation vs Tabulation

- <strong>Memoisation (top-down)</strong> &mdash; write the natural recursion, add a cache, return early on a hit. Minimal change to readable code, and it only computes subproblems you really need. Costs stack space.
- <strong>Tabulation (bottom-up)</strong> &mdash; fill a table from the smallest subproblem upward, no recursion at all. No stack risk and often faster, but you must work out the correct fill order yourself.

## Where it is used in practice

- <strong>`diff` and version control</strong> &mdash; longest common subsequence on lines.
- <strong>Spell checking and fuzzy matching</strong> &mdash; edit distance.
- <strong>Bioinformatics</strong> &mdash; Needleman-Wunsch and Smith-Waterman sequence alignment are DP.
- <strong>Speech recognition</strong> &mdash; the Viterbi algorithm finds the most likely state sequence.
- <strong>Resource allocation and scheduling</strong> &mdash; knapsack variants.
- <strong>Text justification</strong> &mdash; the line-breaking algorithm in TeX.
- <strong>Reinforcement learning</strong> &mdash; value iteration is DP over states.

That list is worth noticing because DP has a reputation as an interview topic. It is in fact behind a few tools you use daily.

## Common mistakes

- <strong>A state that omits relevant information.</strong> If two situations represented by the same state can lead to different answers, the state is incomplete. This is a common cause of incorrect DP solutions.
- <strong>Missing or wrong base cases.</strong> Off-by-one at the boundary propagates everywhere.
- <strong>Mutable default arguments as caches.</strong> `def f(n, memo={})` shares one cache across all calls. This sometimes helps and sometimes leaks between unrelated inputs.
- <strong>Recursion depth.</strong> Top-down on n = 100,000 exceeds Python's stack limit. Convert to iteration.
- <strong>Unhashable arguments with `lru_cache`.</strong> Lists cannot be cached; convert to tuples.
- <strong>Filling the table in the wrong order,</strong> so a state is computed before its dependencies.
