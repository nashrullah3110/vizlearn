title: Interpolation Search
intro: Interpolation search estimates where a target belongs from its numeric value, then probes near that position. It can beat binary search on sorted, roughly uniform data but can degrade to a linear scan.

## Estimate a position

Binary search always probes the midpoint. Interpolation search estimates a probe from the target’s value relative to the current endpoints. This can reduce work on sorted data with roughly uniform spacing, but performs poorly on clustered values.

```text
probe = low + (target - A[low]) * (high - low) / (A[high] - A[low])
```

The formula estimates where the target falls between the endpoint values. Compare `A[probe]` with the target and keep only the appropriate side, as in binary search.

For evenly spaced values `[10, 20, 30, ..., 100]`, a target of 80 is estimated near its actual index. For highly uneven spacing, the estimate may be poor and the range may shrink by only one item at a time.

## Follow a search

Use **Array Size** and **Search Target**, then press **Reset Array** and **Next Step** to see the probe move. **Auto-Run** completes the search. The array must be sorted in ascending order, and the probe must be clamped to the current bounds. If the endpoint values are equal, the denominator is zero; check for the target or stop before evaluating the formula.

## Complexity and when to use it

For sorted data whose values are close to uniformly distributed, interpolation search can take about <code>O(log log n)</code> probes on average. That bound depends on the distribution assumption. In the worst case, such as strongly clustered or exponentially spaced values, it can take <code>O(n)</code> probes. Binary search has <code>O(log n)</code> worst-case time regardless of value distribution.

Choose interpolation search only when keys are numeric, sorted, and their spacing makes the estimate useful. For unknown or uneven distributions, binary search is the safer choice. Include the cost of sorting if the input is not already sorted.

## Common mistakes

- **Using unsorted data:** comparisons no longer identify a side to discard.
- **Assuming uniform spacing:** skewed values can produce poor probes.
- **Ignoring equal endpoints:** the position formula divides by zero.
- **Expecting it always to beat binary search:** measure on the actual data and include setup costs.
