title: Fibonacci Search
intro: Fibonacci search finds a value in a sorted array by probing Fibonacci-number offsets. It uses additions and subtractions to divide the remaining range into uneven parts.

## How it narrows the range

First choose a Fibonacci number at least as large as the array length. Probe at an offset based on a smaller Fibonacci number, compare the target with that value, and discard the range that cannot contain it. Then use the next smaller Fibonacci offsets for the remaining range.

For an array of 10 items, the sequence reaches 13, which covers the array. Each comparison keeps the search within the current bounds. As in binary search, the array must be sorted; otherwise a comparison cannot tell which side to discard.

## Try a search

Set **Array Size** to 10 and choose a **Search Target** near the beginning, middle, or end. Press **Next Step** to follow the probes; use **Auto-Run** to complete the search, then **Reset Array** to try another target. The probes are not always at the midpoint because Fibonacci numbers define the split sizes.

## Cost and practical use

The Fibonacci sequence grows exponentially, so the number of probes is <code>O(log n)</code>, like binary search. Fibonacci search can compute probe positions with additions and subtractions after setting up the sequence, rather than calculating a midpoint by division. This mattered on some older or constrained hardware. On modern general-purpose systems, binary search is usually the simpler default, and Fibonacci search is not generally faster.

The uneven split does not make it an external-memory search method. For data stored in disk pages, structures such as B-trees are designed to reduce page reads.

## Common mistakes

- **Searching unsorted input:** the range-discard step is no longer valid.
- **Probing outside the array:** clamp or guard each index against the current bounds.
- **Treating it as an optimization by default:** benchmark on the target hardware and data before replacing binary search.
