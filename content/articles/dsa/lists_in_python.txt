## A dynamic array, not a linked list


A Python list is a dynamic array: a contiguous block of references with spare capacity for growth. This gives fast indexing and amortized constant-time appends, while inserting near the front shifts later elements and takes linear time.

|Operation|Complexity|Why|
|---|---|---|
|`lst[i]`|O(1)|Direct offset into the block|
|`lst.append(x)`|O(1) amortised|Writes into spare capacity|
|`lst.pop()`|O(1)|Removes from the end|
|`lst.insert(0, x)`|O(n)|Shifts every element right|
|`lst.pop(0)`|O(n)|Shifts every element left|
|`x in lst`|O(n)|Linear scan|

## Indexing and slicing

Indices count from 0, and negative indices count from the end: <span class="mono-font">lst[-1]</span> is the last element, <span class="mono-font">lst[-2]</span> the second-last.

A slice takes <span class="mono-font">[start:stop:step]</span>, where start is inclusive, stop is exclusive. And any part may be omitted. With <span class="mono-font">lst = [10, 20, 30, 40, 50]</span>:

lst[1:4]&nbsp;&nbsp;&rarr; [20, 30, 40]&nbsp;&nbsp;&nbsp;# stop is excluded

lst[:3]&nbsp;&nbsp;&nbsp;&rarr; [10, 20, 30]

lst[::2]&nbsp;&nbsp;&rarr; [10, 30, 50]&nbsp;&nbsp;&nbsp;# every second element

lst[::-1]&nbsp;&rarr; [50, 40, 30, 20, 10]&nbsp;# reversed

The exclusive stop is deliberate: it makes <span class="mono-font">lst[:k] + lst[k:]</span> reconstruct the first for any k. And it makes the length of a slice simply <span class="mono-font">stop &minus; start</span>. Every slice returns a <strong>new list</strong>, so slicing an n-element list costs O(n) time and O(n) memory. Slicing in a loop is a common accidental quadratic.

## Copying, and the aliasing trap

A list holds references, so copying has two levels.

```python
a = [1, 2, 3]
b = a               # NOT a copy - another name for the same list
b.append(4)
print(a)            # [1, 2, 3, 4]

c = a.copy()        # shallow copy - a new list, same objects inside
c = a[:]            # same thing
c = list(a)         # same thing
```

<strong>Shallow</strong> means the new list is separate, and the objects it points to are shared:

```python
grid = [[0, 0], [0, 0]]
flat = grid.copy()
flat[0].append(9)
print(grid)         # [[0, 0, 9], [0, 0]] - the inner lists are shared
```

Use `copy.deepcopy()` when the nested objects must be free.

The same aliasing produces the most notorious Python gotcha:

```python
board = [[0] * 3] * 3        # three references to ONE row
board[0][0] = 1
print(board)                 # [[1,0,0], [1,0,0], [1,0,0]]

board = [[0] * 3 for _ in range(3)]     # three separate rows - correct
```

`[x] * n` repeats the <em>reference</em> n times. For immutable values that is harmless; for mutable ones it is a bug.

## Exploration guide

1. <strong>Watch the exclusive stop.</strong> Set <strong>Start</strong> to 1 and <strong>Stop</strong> to 4. Then press <strong>Run Expression</strong>. Three elements come back, not four &mdash; index 4 is the boundary, not a member.
2. <strong>Reverse with a negative step.</strong> Set <strong>Step</strong> to &minus;1 and leave start and stop empty. The whole list comes back reversed, and it is a copy: the first is untouched.

## What trips people up

- <strong>The mutable default argument.</strong> <span class="mono-font">def f(items=[])</span> creates the list once, when the function is defined, so calls share it. Use <span class="mono-font">None</span> as the default and build the list inside.
- <strong>Removing items while iterating.</strong> Deleting shifts later elements and can make a loop skip items. Iterate over a copy or build a new list with a comprehension.
- <strong>Using <span class="mono-font">pop(0)</span> as a queue.</strong> It shifts the remaining elements. Use <span class="mono-font">collections.deque</span> for efficient operations at both ends.

## Sorting, and the in-place trap

```python
items = [3, 1, 2]

items.sort()                  # sorts IN PLACE, returns None
new = sorted(items)           # returns a NEW sorted list

items = items.sort()          # BUG - items is now None
```

That last line is the classic mistake, and it follows a Python convention: <strong>methods that mutate return `None`</strong>, exactly so this error fails loudly rather than silently.

The `key` parameter is where the useful power is:

```python
words.sort(key=len)                              # by length
people.sort(key=lambda p: (p.surname, p.first))  # by surname, then first name
items.sort(key=lambda x: -x.score)               # descending by score
```

Sorting by a tuple gives multi-key sorting in one pass. And because Timsort is <strong>stable</strong>, sorting by one key. Then another also works. The second sort preserves the first's order within ties, which is how "sort by department. Then by name within department" is done as two sorts.

## Choosing the right structure

|Need|Use|
|---|---|
|Indexed access, ordered items|`list`|
|Add/remove at both ends|`collections.deque`|
|Membership testing|`set` &mdash; O(1) instead of O(n)|
|Key-value lookup|`dict`|
|Fixed record, hashable|`tuple`|
|Counting|`collections.Counter`|
|Grouping|`collections.defaultdict(list)`|
|Numeric arrays, maths|`numpy.ndarray`|
|Sorted order maintained|`bisect.insort`, or `sortedcontainers`|

The membership row is the one that most often matters:

```python
# O(n^2) - 'in' scans the list for every item
for x in items:
    if x in other_list: ...

# O(n) - build a set once
other = set(other_list)
for x in items:
    if x in other: ...
```

For repeated membership checks, this avoids scanning the full list for each query.
