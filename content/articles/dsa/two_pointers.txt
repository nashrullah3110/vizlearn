title: Two Pointers
intro: One pass instead of two nested loops &mdash; when the data lets you rule things out.

## What this is

The <strong>two pointers</strong> technique uses two indices moving through a sequence in a coordinated way. It typically replaces a nested loop, turning <strong>O(n&sup2;)</strong> into <strong>O(n)</strong> with no extra memory.

## The Classic: Pair Sum

Find two numbers in a sorted array that sum to a target. Brute force checks all pairs: O(n&sup2;). Two pointers starts one at each end:

- Sum too <strong>small</strong>? Move the <em>left</em> pointer right &mdash; only larger values lie that way.
- Sum too <strong>large</strong>? Move the <em>right</em> pointer left &mdash; only smaller values lie that way.
- Exactly right? Done.

Each move eliminates an entire set of pairs from consideration without ever testing them. The pointers only ever move toward each other, so the whole search is one pass.

## Why Sorting Is Essential

The technique depends on knowing what moving a pointer <em>does</em>. On a sorted array, moving left rightwards can only increase the sum &mdash; that guarantee is what makes it safe to discard everything you skipped.

On unsorted data no such guarantee exists, and the method is simply wrong. If your input is not sorted you must either sort first (O(n log n)) or use a hash set instead (O(n) time, O(n) space).

## The Three Patterns

- <strong>Converging</strong> &mdash; start at both ends and move inward. Pair sum, palindromes, container with most water.
- <strong>Same direction (fast/slow)</strong> &mdash; both start at the left, one advances faster. Removing duplicates in place, finding the middle of a linked list, cycle detection.
- <strong>Two sequences</strong> &mdash; one pointer per array. Merging sorted arrays, which is exactly the merge step in merge sort.

## Container With Most Water

A subtler case worth understanding. Given heights, pick two lines forming the largest water container. Area is <span class="mono-font">min(height) &times; width</span>.

Start wide and always move the <strong>shorter</strong> line inward. Why is that safe? Moving the taller one can only reduce the width while the area stays capped by the same shorter line &mdash; so it can never improve. Moving the shorter one at least gives a chance of a taller limit. That single argument is what makes the greedy pointer movement correct.

## Guided tour

1. <strong>Run pair sum and step through.</strong> Watch each move discard a whole block of pairs the brute force would have tested.
2. <strong>Compare the two counters.</strong> Two pointers does roughly n comparisons where brute force does n&sup2;/2.
3. <strong>Change the target</strong> so no pair exists. The pointers still meet in one pass and correctly report failure.
4. <strong>Try the palindrome check</strong> &mdash; the same converging pattern, comparing characters instead of summing.
5. <strong>Run container with most water</strong> and watch it always move the shorter bar. That is the greedy choice the correctness argument justifies.

## Where that leaves you

Two pointers replaces nested loops with a single coordinated pass, in O(1) extra space. It works only when moving a pointer changes the result predictably — usually because the data is sorted. Recognising that condition is the whole skill.
