title: Binary Search Trees
intro: Binary search made into a structure &mdash; and what happens when it loses its shape.

## What a binary search tree gives you


A binary search tree stores ordered values in nodes: smaller keys go left and larger keys go right. Search, insert, and delete follow one path, taking <code>O(h)</code> time for tree height <code>h</code>. A balanced tree has logarithmic height; an unbalanced one can become a linear chain.

## Search, Insert, Delete

Searching is a walk: compare with the current node, go left if smaller, right if larger, stop when equal or when you fall off the tree. Insertion follows the same walk and attaches the new node where the search failed.

Deletion is the fiddly one, with three cases:

- <strong>Leaf</strong> &mdash; just remove it.
- <strong>One child</strong> &mdash; the child takes its place.
- <strong>Two children</strong> &mdash; replace the value with its <em>in-order successor</em> (the smallest value in the right subtree), then delete that successor. Only this choice preserves the BST rule.

## In-Order Traversal Sorts For Free

Visit left subtree, then the node, then the right subtree. Because of the BST rule, this emits every value in <strong>ascending sorted order</strong> &mdash; press <em>In</em> and read the output.

The other two orders have their own uses: <strong>pre-order</strong> (node first) is how you copy or serialise a tree, and <strong>post-order</strong> (node last) is how you delete one safely, since children are freed before their parent.

## The Fatal Weakness

Press <strong>Sorted input</strong>. Inserting already-sorted values means every new value is larger than everything before it, so it always goes right. The tree becomes a single downward chain &mdash; a linked list wearing a tree costume.

Height goes from O(log n) to O(n), and every operation degrades with it. This is not a rare edge case: inserting sorted data is extremely common in practice.

## Which Is Why Self-Balancing Trees Exist

<strong>AVL trees</strong> and <strong>red-black trees</strong> detect when a subtree grows lopsided and perform <em>rotations</em> to restore balance, guaranteeing O(log n) regardless of insertion order. Red-black trees are what back <span class="mono-font">std::map</span> in C++ and <span class="mono-font">TreeMap</span> in Java.<p>Compare the height readout after pressing <em>Balanced</em> versus <em>Sorted input</em> with the same values &mdash; the gap is exactly what balancing buys.</p>

## BST or Hash Table?

A hash table is faster for pure lookup &mdash; O(1) versus O(log n). But a BST keeps its data <strong>ordered</strong>, which a hash table cannot. Use a tree when you need sorted iteration, range queries ("all values between 20 and 50"), or nearest-neighbour lookups. Use a hash table when you only ever ask "is this exact key present?".

## The degenerate case

Insert 1, 2, 3, 4, 5 into an empty BST in that order and every node becomes the right child of the last. The tree is a linked list, and every operation is O(n).

<strong>Sorted input produces the worst possible tree.</strong> That is not a rare pathological case &mdash; inserting records in id order, or in date order, is entirely normal.

Three responses:

<strong>Self-balancing trees.</strong> AVL and red-black trees rotate on insertion to keep the height O(log n) automatically. This is what production implementations use.

<strong>Randomised insertion order,</strong> if you control it. Expected height O(log n).

<strong>A different structure.</strong> A sorted array with binary search, or a skip list, or a B-tree for disk-based data.

|Tree|Balance rule|Character|
|---|---|---|
|AVL|Heights differ by at most 1|Strictly balanced; faster lookups|
|Red-black|Colour rules bound the height|Fewer rotations; faster insertion|
|B-tree|Many keys per node|Designed for disk pages|
|Treap|Random priorities|Simple, probabilistic balance|

Red-black trees are what most standard libraries use for ordered maps &mdash; C++'s `std::map`, Java's `TreeMap` &mdash; because they balance insertion and lookup cost well.
