title: Heaps and Priority Queues
intro: Weaker ordering than a BST, and that is exactly the point.

## The problem it solves


A <strong>heap</strong> is a complete binary tree obeying one rule: every parent is smaller than both its children (a <em>min-heap</em>) or larger than both (a <em>max-heap</em>). It says nothing about siblings &mdash; the tree is only partially ordered.

That partial ordering is what makes a heap useful. It guarantees the smallest (or largest) element is always at the root, and it can be maintained in O(log n) per insertion or removal.

## Why Partial Ordering Is Better Here

A BST fully sorts its data, which costs effort to maintain. A heap only guarantees the extreme value sits at the root. If all you ever ask is "what is the smallest item?", full sorting is wasted work.

That weaker promise makes the structure cheap to maintain: <strong>O(1)</strong> to read the root, <strong>O(log n)</strong> to insert or remove it. Note that heaps are <em>terrible</em> at searching for an arbitrary value &mdash; that is O(n), because the ordering gives you no guidance below the root.

## Sift Up and Sift Down

- <strong>Insert</strong> &mdash; place the new value at the end of the array (the only spot that keeps the tree complete), then <em>sift up</em>: repeatedly swap with the parent while it is out of order. At most one swap per level, so O(log n).
- <strong>Extract root</strong> &mdash; take the root, move the <em>last</em> element into its place, then <em>sift down</em>: repeatedly swap with the smaller child until order is restored. Again O(log n).

The swap counter shows this: even with 15 elements, no operation needs more than about 4 swaps.

## Try it yourself

1. <strong>Insert a value smaller than the root.</strong> Watch it bubble all the way to the top &mdash; one swap per level, never more.
2. <strong>Insert a large value.</strong> It stays near the bottom with no swaps at all &mdash; the average insert is far cheaper than the worst case.

## The limitation: no efficient search or update

A heap answers "what is the smallest?" and nothing else. Finding an arbitrary element requires scanning &mdash; O(n) &mdash; because siblings are unordered.

That matters for algorithms that want to <strong>decrease a key</strong>: Dijkstra ideally updates a node's priority in place, and a binary heap cannot locate that node quickly. The standard workaround is lazy deletion &mdash; push a new entry and skip stale ones when popped &mdash; which is why Dijkstra implementations carry that check.

If you need both priority access and lookup, the usual answer is a heap plus a dictionary from item to its position, maintained together. That is more code and it is what a proper indexed priority queue provides.

|Need|Structure|
|---|---|
|Smallest or largest, repeatedly|Heap|
|Sorted iteration|Sorted list, or a balanced tree|
|Lookup by key|Hash table|
|Range queries|Balanced tree|
|Priority plus lookup|Heap plus an index dictionary|

## A worked heap trace

Building a max-heap from [3, 9, 2, 1, 4, 5] by sifting down from the middle backwards makes the O(n) build concrete.

Indices 5, 4, 3 are leaves and need nothing. Start at index 2:

|Step|Node|Children|Action|Array|
|---|---|---|---|---|
|Start|&mdash;|&mdash;|&mdash;|[3, 9, 2, 1, 4, 5]|
|i = 2|2|5 (index 5)|Swap|[3, 9, <strong>5</strong>, 1, 4, <strong>2</strong>]|
|i = 1|9|1, 4|Already largest|[3, 9, 5, 1, 4, 2]|
|i = 0|3|9, 5|Swap with 9|[<strong>9</strong>, <strong>3</strong>, 5, 1, 4, 2]|
|i = 0 cont.|3|1, 4|Swap with 4|[9, <strong>4</strong>, 5, 1, <strong>3</strong>, 2]|

Final heap: [9, 4, 5, 1, 3, 2]. The root is the maximum, every parent exceeds its children, and the siblings are unordered &mdash; 4 sits before 5, which is perfectly valid.

Extracting repeatedly then gives the sorted order: swap the root with the last element, shrink, sift down. That is heap sort.

Two things this trace demonstrates. The build genuinely does little work &mdash; three sift operations for six elements, most of them trivial. And the array's final layout looks unsorted, which is the point: a heap is not a sorted structure, only a partially ordered one.
