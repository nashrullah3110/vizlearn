title: Union-Find (Disjoint Set)
intro: Two optimisations that turn linear into effectively constant.

## Start here

<strong>Union-Find</strong> maintains a collection of non-overlapping sets and supports two operations: <span class="mono-font">find(x)</span> &mdash; which set does x belong to? &mdash; and <span class="mono-font">union(a, b)</span> &mdash; merge the two sets containing a and b.

## The Structure

Each set is stored as a tree, with every element pointing to a parent. The <strong>root</strong> represents the whole set. Two elements are in the same set exactly when they have the same root.

Union is therefore trivial: point one root at the other. All the difficulty is in keeping <span class="mono-font">find</span> fast, because it must walk to the root.

## Optimisation 1: Union by Rank

<p>Naively linking roots can build a long chain &mdash; press <strong>Build a bad chain</strong> with both optimisations off to see one. Depth grows to n and every find becomes O(n).</p><strong>Union by rank</strong> always attaches the <em>shorter</em> tree under the taller one. The result never gets deeper than necessary, keeping depth at O(log n). Toggle the checkbox and rebuild the chain to compare.

## Optimisation 2: Path Compression

When <span class="mono-font">find(x)</span> walks to the root, it already knows the answer for every node along the way &mdash; so it re-points them all <em>directly</em> at the root on the way back.

Press <strong>Find</strong> on a deep node with compression on and watch the tree flatten in a single operation. Each find makes all subsequent finds cheaper, so the cost is amortised away.

## The Famous Complexity

With both optimisations, m operations on n elements cost <strong>O(m &middot; &alpha;(n))</strong>, where &alpha; is the inverse Ackermann function. It grows so slowly that for any n that fits in the observable universe, &alpha;(n) &lt; 5.

It is not technically constant, but it is constant for every practical purpose &mdash; one of the most striking results in data-structure analysis.

## Where It Is Used

- <strong>Kruskal's MST</strong> &mdash; sort edges, add one if its endpoints are in different sets. Union-Find is what makes the cycle check fast.
- <strong>Connected components</strong> &mdash; in a graph, an image (flood fill), or a network.
- <strong>Percolation and clustering</strong> &mdash; does a path exist from top to bottom?
- <strong>Account or record merging</strong> &mdash; treating "these two IDs are the same person" as a union.

## Guided tour

1. <strong>Union a few pairs</strong> and watch separate trees form. The group counter drops by one per successful merge.
2. <strong>Union two elements already in the same set.</strong> Nothing changes &mdash; and that check is exactly how Kruskal avoids creating a cycle.
3. <strong>Turn off both optimisations and press Build a bad chain.</strong> Depth grows linearly and finds get slow.
4. <strong>Turn path compression back on and run Find on the deepest node.</strong> The tree flattens in one step.
5. <strong>Compare max depth with rank on and off.</strong> Union by rank prevents the tall trees; compression fixes the ones already made.

## Worth remembering

Union-Find answers "same group?" and "merge groups" in effectively constant time, using union by rank to keep trees shallow and path compression to flatten them on the way. It is the structure that makes Kruskal's algorithm and fast connected-component queries possible.
