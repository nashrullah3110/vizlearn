title: Selection Sort
intro: Selection sort repeatedly finds the smallest remaining value and places it next in the output. It always uses quadratic comparisons but makes at most one swap per pass.

## Find the next minimum

Divide the array into a sorted prefix and an unsorted suffix. Scan the suffix for its minimum, swap that value with the first suffix position, and extend the prefix by one. After each pass, the prefix contains the smallest values in sorted order.

For `[7, 3, 5, 2]`, the first scan finds 2 and swaps it with 7: `[2, 3, 5, 7]`. The next scan begins after 2 and finds 3 already in place. Continue until one value remains. Set **Array Size**, press **Randomize Array**, and use **Next Step** to see each scan and swap.

## Cost and properties

Selection sort makes about (n(n-1)/2) comparisons regardless of input order. Even a sorted array still requires scanning each remaining suffix to confirm its minimum. Its running time is therefore quadratic in the best, average, and worst cases.

The standard version is in-place and performs at most (n-1) swaps. That low number of writes can be useful when writes are unusually expensive, but selection sort is not stable by default: swapping a distant minimum can move equal values past each other. In most ordinary uses, insertion sort is preferable for small or nearly sorted inputs, and a faster general-purpose sort is preferable for large inputs.

## Common mistakes

- **Stopping early because the prefix looks sorted:** the remaining suffix must still be checked.
- **Assuming it adapts to sorted input:** it performs the same number of comparisons either way.
- **Calling the basic algorithm stable:** an early swap can change the order of equal values.
- **Confusing few swaps with low total work:** it still scans quadratically many elements.
