title: Python Strings
intro: A Python string is an immutable sequence of Unicode code points. Indexing, slicing, and methods create or return values; they do not change the original string.

## Immutability and indexing

Strings are ordered and zero-indexed: `text[0]` is the first code point and `text[-1]` is the last. You cannot assign to one character, so `text[0] = "H"` raises `TypeError`. A transformation such as `.upper()` returns a new string.

Use **Base String** and **Method** in the visualizer, then press **Apply Transformation**. Compare the original with the result. Try **Start**, **Stop**, and **Step** with the Slicing method: the start index is included, the stop index is excluded, and the step controls how indices advance.

For `text = "Python"`, `text[2:4]` returns `"th"`; the character at index 4 is outside the slice. `text[::-1]` returns a reversed copy. A slice of length (k) takes time and space proportional to the characters returned.

## Useful string operations

```python
text = "  Hello, World  "

text.strip()                  # remove surrounding whitespace
text.lower()                  # case conversion; returns a new string
text.replace("World", "Ada")  # replace substring
text.split(",")               # split into parts
", ".join(["red", "blue"])    # join parts into a string
"World" in text               # substring test
text.find("World")            # index, or -1 if absent
```

Use `casefold()` for caseless comparisons across languages. Use `split()` without an argument to split on runs of whitespace; `split(" ")` splits only on literal spaces and can leave empty strings.

## Characters and bytes

Python strings contain Unicode code points; files and network protocols use bytes. Encode when writing bytes and decode when reading them:

```python
raw = "café".encode("utf-8")  # five bytes
text = raw.decode("utf-8")    # four Unicode code points
```

Some visible characters use multiple code points, so a displayed symbol is not always one index. Specify an encoding when opening text files for consistent behavior. Unicode normalization can make canonically equivalent text comparable; choose a normalization form that suits the application, because compatibility normalization may change distinctions.

## Common mistakes

- **Expecting a method to mutate the string:** assign its returned value if you need to keep the result.
- **Using inclusive slice endpoints:** the stop position is excluded.
- **Confusing bytes with characters:** encoded byte length can differ from `len(text)`.
- **Building output with repeated concatenation in a loop:** collect pieces and use `"".join(parts)` for large output.
