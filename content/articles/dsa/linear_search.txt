title: Linear Search
intro: Linear search checks values one by one until it finds the target or reaches the end. It works on unsorted data and needs no preprocessing.

## Check each item in order

Linear search scans values from one end until it finds the target or reaches the end. It works on unsorted data without preprocessing, making it useful for small inputs or one-off searches; a missing target requires checking every element.

For `[42, 17, 8, 91, 5]`, searching for 91 checks four values and returns index 3. Searching for 100 checks all five and reports no match.

Use **Search Target** to choose a value and **Array Size** to change the input. Press **Randomize Array**, then **Next Step** or **Auto-Run** to follow the comparisons.

## Cost

The best case is one comparison when the first item matches. The worst case is <code>n</code> comparisons when the target is last or absent, so time is <code>O(n)</code> and extra space is <code>O(1)</code>. If a successful target is equally likely to be at any of <code>n</code> positions, the average is <code>(n + 1)/2</code> comparisons.

## When to choose another search

Linear search is a good fit when data is unsorted, small, or checked only once. If the data is sorted and many searches are needed, binary search reduces each search to <code>O(log n)</code> comparisons, though the data must remain sorted. If many repeated membership checks use hashable keys, a set or dictionary can provide average constant-time lookup after construction.

## Common mistakes

- **Stopping after a mismatch:** continue until the target is found or the input ends.
- **Returning the wrong duplicate:** a left-to-right scan returns the first matching index.
- **Using `-1` without checking:** valid Python negative indices make it easy to accidentally read the last element when a search failed.
- **Ignoring sortedness trade-offs:** sorting solely to run one search may cost more than scanning.
