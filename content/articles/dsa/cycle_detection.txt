title: Cycle Detection
intro: Finding a loop without remembering where you have been.

## The problem it solves

<strong>Floyd's cycle detection</strong> &mdash; the tortoise and hare &mdash; determines whether a linked structure contains a loop, using two pointers moving at different speeds and <strong>constant</strong> extra memory.

## The Obvious Solution and Its Cost

You could store every visited node in a hash set and check each new one. That works and is O(n) time &mdash; but it needs <strong>O(n) memory</strong>.

Floyd's algorithm achieves the same result with two integers. On a huge structure, or in an embedded system, that difference decides whether the problem is solvable at all.

## Why They Must Meet

If there is no cycle, fast simply runs off the end &mdash; done, no loop.

If there <em>is</em> a cycle, both pointers eventually enter it. Once inside, consider the gap between them measured around the loop. Fast gains exactly one position per step, so the gap shrinks by one each time. A gap that decreases by one every step must reach zero &mdash; they cannot jump past each other.

This is the whole proof, and it is why the algorithm is guaranteed to terminate rather than merely likely to.

## Finding Where the Cycle Starts

Detection is only half of it. After they meet, reset one pointer to the head and move <strong>both one step at a time</strong>. They will meet again exactly at the cycle's entry point.

The reason is arithmetic: if the tail before the loop has length &mu; and the meeting point sits &lambda; steps into a loop of length L, the distances work out so that both pointers arrive at the entry simultaneously. Step through to the end of the cyclic example and watch that second phase run.

## Where It Is Used

- <strong>Linked list integrity</strong> &mdash; a corrupted list with a loop makes traversal hang forever.
- <strong>Detecting infinite loops</strong> in state machines and iterative processes.
- <strong>Finding duplicates</strong> &mdash; the classic "find the duplicate in an array of n+1 values from 1..n" problem becomes cycle detection when you treat values as next-pointers.
- <strong>Cryptography</strong> &mdash; Pollard's rho algorithm for integer factorisation uses exactly this to find collisions.

Note that cycle detection in a <em>graph</em> is a different problem, usually solved with DFS and a recursion-stack check, or by topological sort.

## Things to try

1. <strong>Run the cyclic list.</strong> Watch fast lap the loop and close in on slow one position per step.
2. <strong>Note where they meet</strong> &mdash; usually <em>not</em> at the cycle's entry. That is why a second phase is needed.
3. <strong>Keep stepping.</strong> Phase two resets one pointer to the head and both walk at speed one, meeting exactly at the entry node.
4. <strong>Switch to the acyclic list.</strong> Fast runs off the end and the algorithm correctly reports no cycle.
5. <strong>Watch the memory readout: O(1) throughout.</strong> No matter how long the list, only two pointers are ever stored.

## What to remember

Floyd's algorithm detects a loop in O(n) time and O(1) space, because inside a cycle the gap between a one-step and a two-step pointer shrinks by exactly one each iteration and must hit zero. A second phase from the head then locates where the cycle begins.
