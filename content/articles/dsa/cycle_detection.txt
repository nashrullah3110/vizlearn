title: Cycle Detection in Linked Lists
intro: The two-pointer cycle-finding method, often called Floyd’s tortoise-and-hare algorithm, detects a linked-list loop with constant extra space and can locate its entry.

## Detect a meeting

Start a slow pointer and a fast pointer at the head. Move slow by one node and fast by two. If fast reaches `None` or has no next node, the list ends and has no cycle. If the pointers meet, they are inside a cycle.

Choose **Structure** in the visualizer and compare **List with a cycle**, **List with no cycle**, and **Cycle back to the start**. Use **Auto-Run** to watch the fast pointer catch the slow pointer. Compare node identity, not just stored values: different nodes can contain equal values.

## Why they meet

Once both pointers are inside the loop, fast gains one node on slow at every step. Their distance around the cycle shrinks by one, so they must eventually land on the same node. If there is no loop, fast instead reaches the end.

## Find the cycle entry

After a meeting, reset one pointer to the head. Move both one step at a time. They meet at the first node of the cycle. If the non-cyclic prefix has length μ and the cycle length is λ, the first meeting’s position in the cycle makes both pointers reach the entry after μ more steps.

Floyd’s algorithm takes <code>O(n)</code> time and <code>O(1)</code> extra space. A visited-node set also detects a loop in linear time, but stores up to <code>n</code> node references. Choose it when simpler debugging is more useful than saving memory.

## A related use

In the classic duplicate-number problem, each array value can be treated as the next index to visit. That creates a linked structure over indices, and Floyd’s method can locate the cycle without modifying the array. The input constraints are essential for this mapping to be valid.

Graph cycle detection is a different problem: use DFS with graph-specific state, or topological sorting for directed acyclic graphs. See [depth-first search](depth_first_search.html) and [topological sort](topological_sort.html).

## Common mistakes

- **Advancing fast by one:** the pointers no longer close the gap at the required rate.
- **Checking values rather than nodes:** equal values do not mean two pointers reference the same node.
- **Forgetting the empty-list case:** check for `None` before accessing `.next`.
- **Assuming every cycle detector is interchangeable:** linked-list pointers and graph edges need different state and reasoning.
